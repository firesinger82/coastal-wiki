# COASTAL-WIKI 구조·작업 방식 개편 계획

상태: **검토 중인 제안, 미채택·미구현**. 기준 커밋 `36b7f34`. 사용자 요청은 이번 조사에 근거한 계획을 Claude와 함께 만드는 것이다. 이 문서는 모델 분석을 재개하거나 기존 전수 지시·승인 조건을 자동으로 바꾸지 않는다.

## 1. 목적과 권고 방향

연안공학의 개념·이론·분석법을 이해하고, 모델별 구현·차이·적용 한계를 원문으로 추적할 수 있는 지식 기반을 만든다. 위키에서 학습·비교·근거 탐색을 하고, 개인 계산 케이스는 별도 저장소에서 구축한다. 기존 [README](../../README.md)와 [CLAUDE](../../CLAUDE.md)의 목적을 유지한다.

권고: **기존 저장 경로를 유지하고, 독자 탐색·자료 편입·감사 과제·완료 보고를 분리한다.** 새 DB·GraphRAG·전면 폴더 이동보다 기존 노트의 접근성과 근거 추적을 먼저 개선한다. 이는 조사에 근거한 설계 판단이며 문헌이 이 구조의 우월성을 실증한 것은 아니다. [조사 결과](../../research/digests/2026-09-12-wiki-purpose-review.md)

## 3. 목표 구조와 실제 변경 위치

```text
README.md                        목적과 읽는 순서
INDEX.md                         개념 → 이론 → 분석법 → 모델 비교의 짧은 안내
WORKPLAN.md                      현재 작업 1건과 상세 계획 링크 (새 파일 1개)
plan.md                          결정·개정 이력, 현재 실행 목록을 중복 보관하지 않음
concepts/<topic>/README.md        개념·이론·분석·모델 연결의 탐색 안내
concepts/<topic>/*.md             기존 내용과 경로 유지
textbook/notes/                   이론·교과서 근거 유지
models/<model>/README.md          물리·수치·입출력·제약별 탐색 안내
models/<model>/source-analysis/   기존 구현 설명과 깊은 분석 유지
models/<model>/manual-notes/      기존 문헌 해설 유지
models/<model>/web-refs/          원출처 안내 유지
research/                        탐색적 수집과 비교 검토 유지
_staging/<task>/                  해당 과제의 범위·검토·미해결 기록
examples/ · experience/           현재 경계와 검증 조건 유지
```

**탐색 구조:** INDEX는 항목마다 “다루는 내용 / 시작 문서 / 문서 상태 확인 링크”를 짧게 둔다. 모델 행에서 전체 완료·퍼센트를 제공하지 않는다. 기존 항목과 유일한 링크는 유지하고 감사 상세는 기존 원장으로 연결한다. 감사 이력을 지우거나 그 내용을 다른 곳에 다시 쓰지 않는다.

**개념 진입:** 기존 번호 체계를 유지한다. 예를 들어 waves README에서 정의·이론·스펙트럼 분석·파랑 변형·모델 구현 비교로 안내한다. 도메인 설명을 새 overview 파일로 복제하지 않고 기존 노트의 절에 연결한다. 링크 대상이 미검증이면 그 상태를 숨기지 않는다.

**모델 진입:** XBeach README의 첫 화면은 모드, 파랑, 흐름·습윤건조, 표사·지형, 경계·입출력, 선택 물리, 구현 제약의 순서로 연결한다. 아래에 “문서 상태와 분석 이력”을 두어 현재 draft 노트 및 전체 연결 감사 미완을 표시한다. 새 기술 단언은 원출처 대조와 해당 검증 절차를 거친다. 현재 README 내용·노트를 위치 변경만으로 verified로 올리지 않는다.

**현재 작업:** 새 `WORKPLAN.md`는 작업명·상태·고정 범위 링크·다음 행동·사용자 결정 링크만 가진다. 상세 잔여와 결함을 복사하지 않는다. AGENTS 진입 순서에 현재 작업 확인을 연결하고 기존 RESUME에는 “현재 활성 여부는 WORKPLAN” 포인터를 둔다. 각 기존 원장은 근거와 상세 상태의 기준으로 남는다. 한 번에 활성 구현 묶음은 하나다.

## 4. 전수 판독을 어디에 적용할 것인가

다음은 **채택 시 바뀌는 정책 제안**이다. 기존 Total Read를 몰래 폐기하지 않도록 적용 대상을 명시한다.

| 작업 | 자료 범위 | 완료 조건 |
|---|---|---|
| 새로운 논문·매뉴얼 자료 편입 | 시작 전에 선정한 논문/장/절과 버전. 논문 전체를 골랐다면 전체, 특정 절이면 그 절을 읽었다고 표시 | 선정 범위의 충실한 판독, 원문·요약 분리, 필요한 기존 노트와의 연결·충돌 표시. 인벤토리·SHA는 의미 판독의 대체물 아님 |
| 기존 위키의 한 설명 보강 | 명시한 주장·문서 절, 해당 식·수치·실행 조건을 지지하는 원문과 관련 코드 | 주장 지지와 적용 한계 확인, 모순 해결 또는 source-needed 공개, 기존 독립 검토·필요한 실제 사람 결정 |
| 모델 핵심 체계 검토 | 물리·수치·상태 전달 등의 명명된 체계와 고정 판본 | 해당 체계의 문서–구현 대응과 알려진 공백 처분. 이름만 검색해 미호출/무관 판정 금지 |
| 모델 전체 연결 감사 | 별도로 요청·확정한 전수 집합과 기존 종료 기준 | 전체 범위와 외부·사람 게이트를 충족해야만 그 감사 완료로 표시 |

권고하는 정책 변경은 **위키의 개별 보강·활용이 모든 모델의 전수 연결 감사 완료를 기다리는 선후 관계를 없애는 것**이다. 해당 내용의 엄격한 출처 검증은 유지한다. 이미 확정한 전수 감사의 범위를 줄이는 행위는 별도의 명시된 변경 결정이며 미판독·미완을 완료로 바꾸지 않는다. 기존 도메인·모델의 중요도를 읽지 않고 낮추거나, 질문이 없다는 이유로 핵심 이론을 배제하지 않는다.

깊은 대조를 시작하는 조건은 (1) 게시 주장과 원문/코드의 충돌, (2) 식·단위·적용 모드의 설명 공백, (3) 핵심 기능 지도에서 근거가 없는 분야, (4) 인용 중인 판본의 변경이다. 관련 입력과 종료 조건을 먼저 적는다. 새 발견은 현재 주장을 안전하게 게시하는 데 필요한 부분만 해당 묶음에서 처리한다. 그 밖의 새 주제는 후보로 남기며 현재 범위를 자동 확대하지 않는다.

**검증의 중심:** 새로 쓰거나 실질적으로 고치는 단언의 원문 지지를 확인한다. 기존 전체 노트에 원자적 주장 DB를 한꺼번에 만드는 작업은 포함하지 않는다. 기존 `citation_status`와 `has_source_needed`를 유지한다. 수치·식·모드 조건처럼 오독 영향이 큰 단언은 검토 패킷에서 `주장 / 원출처 위치·판본 / 지지 또는 불일치 / 영향 / 검토`를 명시한다. “미대조”는 “문제 없음”과 다르다. 모든 객관 단언의 인용 의무는 유지한다.

## 5. XBeach 미완의 전환안

**XBeach를 완료로 표시하지 않는다.** 기존 R1–R4·57개 Fortran 판독 근거·수식 시각 판독·충돌 정정·승인 이력을 재사용한다. 456파일 집계는 전량 의미 판독 완료가 아니다. [기존 판정의 정정](../../research/inbox/2026-09-12-wiki-purpose-review/review-adjudication.md)

| 기존 항목 | 제안하는 처리 | 바뀌지 않는 사실 |
|---|---|---|
| R1 전체 실행 연결 | 전체 감사로 별도 추적하고 우선순위는 재결정. 파일럿의 링크 정리에 선행시키지 않음 | 전체 미완 유지. G1–G3를 새 이름만으로 닫지 않음 |
| R2 수식 위치별 대응 | 전체 수식 처분은 별도 감사. 개별 노트에 인용할 식은 해당 보강에서 반드시 대조 | 전체 수식 대응 미완 유지, 이미 대조한 식은 재사용 |
| R3 충돌 정정·위키 반영 | 이미 반영한 C1–C4는 재사용. 새로 확인된 오류는 해당 문서·원문과 함께 별도 유한 묶음으로 처리 | R3 전체 완료는 기존 의존관계 유지. 오류를 단지 별도 감사로 보내고 게시문에서 숨기지 않음 |
| R4 최종 검토·필요 승인 | 전체 감사의 R4는 그대로 두고 개별 보강 결과는 적용되는 기존 절차로 검토 | 기존 승인을 새 주장에 승계하거나 AI가 HG를 발급하지 않음 |
| 중단된 `interfaces-20260912/` | 미설치 작업으로 보존·연결. 사용할 때 최종 검토부터 확인 | 구현·검증·설치 완료로 세지 않음 |

권고: 첫 구현 묶음은 **waves ↔ XBeach 탐색 개선**으로 한정한다. XBeach 전체 연결 감사나 다음 모델 전수 감사가 동시에 자동 재개되지 않도록 WORKPLAN에 기록한다. 이는 사용자가 개편안을 채택하고 해당 구현을 요청한 뒤의 실행 순서다.

## 6. 단계별 실행·산출물·중단 기준

### P0 — 이번 턴: 계획과 외부 검토

- 현재 구조와 조사 근거를 결합한 이 계획을 Claude와 검토한다. Codex의 계획 반증 검토를 받아 반영한다.
- 산출물: 계획, 실제 외부 응답, 지적별 반영/유보, 아래 탐색 화면 예시. 현재 정책·canonical·검색 구현은 수정하지 않는다.
- 종료: 핵심 선택·충돌·전환 범위·검사 조건이 구체적이고 검토 지적을 처리한 계획을 사용자에게 제출. 반복 조사·감사로 넘어가지 않는다.

### P1 — 채택 후 첫 묶음: 탐색과 재개 경로

- 변경 대상은 8개로 고정: `README.md`, `INDEX.md`, `AGENTS.md`, 새 `WORKPLAN.md`, `concepts/_template/README.md`, `models/_template/README.md`, `concepts/waves/README.md`, `models/XBeach/README.md`.
- 기존 파일 내용의 도메인 단언은 복제하지 않고 탐색·상태 안내 중심으로 정리한다. 새 기술 주장이 필요하면 이 묶음에서 작성하지 않고 제안으로 남긴다.
- 기존 진입 링크와 원문·노트·감사 근거 경로가 유지되는지 확인한다. `INDEX`의 수치·승인 이력 상세는 연결된 원장의 유무를 확인하고 제거한다. 유일한 정보는 보존 또는 기존 상세 문서로 이관한다.
- 종료: 8개 변경의 링크·상태 표기·기존 정보 보존 검사, 독립 검토, 필요한 사용자 검토. 시작 후 파일 수가 늘면 사유와 새 manifest를 별도 제시한다.

### P2 — 자료 편입·완료 기준의 정책 반영

- 변경 대상: `CLAUDE.md`, `CONVENTIONS.md`, 새로 채택한 결정을 기록할 `plan.md`; XBeach RESUME·GOAL에는 현재 작업 포인터만 연결.
- §4의 범위별 판독·검증, 전체 감사와 개별 보강의 관계, 상태·재개 우선순위를 한 규약으로 정리한다. 외부 검토·사람 게이트·불변 원본 보호는 유지한다.
- 종료: 기존 Total Read·G9·G8·외부 게이트와의 충돌표에서 각 조항의 유지/수정 범위를 명시하고 독립 검토. 기존 전수 원장과 승인 영수증은 수정하지 않는다.
- 실제 작업 순서는 P1의 단순 탐색 정리를 먼저 하되 P2 채택 전에는 바뀐 감사 정책으로 새 분석을 실행하지 않는다.

### P3 — 유용성 확인 1회, 확대 판단

- waves와 XBeach 기존 노트로 질문 12개를 고정: 개념·이론 3, 모델 구현 연결 3, 비교·적용 한계 2, 답이 없거나 근거가 불충분한 질문 2, 이번 변경과 무관한 회귀 질문 2.
- 각 질문에 기대하는 근거 위치·현재 상태·금지할 과잉 단언을 변경 전에 정한다. “정답”은 위키만으로 확정하지 않고 인용된 원출처와 대조한다. 이미 문제를 아는 평가자의 결과를 블라인드나 미지 결함 발견률로 표현하지 않는다.
- 전후 동일 질문과 동일 검색 설정을 사용한다. 탐색 경로, 근거 회수, 상태 노출, 근거 없는 단정, 검토 시간을 기록한다. 12문항 점수를 전체 위키 품질/완료율로 표시하지 않는다.
- 종료: 1회 비교와 필요한 명확한 회귀 수정 1회까지. 새로운 심층 분석·검색 엔진 교체·전체 모델 확대는 별도 결정. 결과가 나쁘면 범위를 늘리지 않고 현 설계를 수정하거나 보류한다.

## 7. 진행 보고와 운영 비용

사용자에게는 “이번 고정 묶음 / 실제로 준비·반영된 산출물 / 검토 대기 / 남은 장애”를 보고한다. 같은 문서의 판독·대조·검토·승인은 별도 상태다. 파일 수·루틴 수·논문 수·질문 점수로 XBeach 전체 퍼센트를 만들지 않는다. 전체 감사와 위키 이용 상태를 같은 완료 라벨로 합치지 않는다.

새 운영 문서는 WORKPLAN 한 개로 제한한다. 새 논문마다 여러 원장·계층·승인 시스템을 추가하지 않는다. 기존 검토 도구와 원장 형식을 재사용하고, 시작 시 과제별 한 범위·한 종료 조건을 적는다. 이 계획은 일괄 재분류, 대규모 새 주장 manifest, GraphRAG 구축, 새 cron, vendor 내부 판독, 모델 소스 수정, 강제 권한 재설정을 포함하지 않는다.

## 8. 검증·롤백과 채택할 결정

- 기존 검사: research 격리, 상대 링크·wikilink, 로컬 경로 경계, 기존 layer/claims 검사. 코드 변경이 없는 묶음에 새 테스트 프레임워크를 만들지 않는다.
- 보존: XBeach 불변 292개, 원본 및 기존 canonical 노트 바이트, 현재 인용 상태·승인 기록은 탐색 개편으로 변경하지 않는다.
- 변경별 커밋을 분리한다. 문제가 있으면 탐색·정책 변경 커밋의 해당 부분을 되돌리고 원래 경로/메타데이터를 복원한다. 원본이나 과거 영수증을 지우지 않으므로 지식 손실 없는 복귀가 가능해야 한다.

채택 대상으로 제시할 결정은 세 가지다: **① 기존 폴더 유지 + 개념 중심 탐색 개선, ② 개별 지식 보강과 전체 모델 감사의 선후 관계 분리, ③ waves–XBeach 한 묶음으로 먼저 확인하고 이후 확대.** 사용자가 계획을 검토한 뒤 실행을 요청하면 그 범위 안에서 진행한다. 이번 계획 작성 요청을 구현 승인으로 해석하지 않는다.
