상태: **외부 검토 의견을 반영한 제안, 미채택·미구현**. 기준 커밋 `36b7f34`. 2026-09-12에 시작해 09-13에 검토를 정리했다. 사용자 요청은 현황 파악을 먼저 하고 이번 조사를 바탕으로 Claude와 계획을 만드는 것이다. 이 문서는 현재 정책이나 XBeach 완료 상태를 바꾸지 않는다. [실제 검토와 반영 기록](review-response.md)

## 1. 먼저 확인한 현재 구조

[실제 폴더 현황](current-structure.md)과 [기계 집계](structure-inventory.json)가 계획의 출발점이다. 개념은 10개, 모델은 13개다. 작성 지식뿐 아니라 `standards/`, `data/`, `references/`, 도구·감사 영역도 존재한다. Git 추적 6,731개 중 `_staging` 5,645개는 작업 증거를 포함한 파일 수이며 지식량이나 낭비의 측정치가 아니다.

구체적으로 확인한 불일치:

- 루트 README의 디렉터리 설명에 standards·data·references·tools가 빠져 있다.
- `models/INDEX.md`는 모델 10개만 등록하고 일부 상태가 TBD다. 실제 13개 디렉터리 및 루트 INDEX와 맞지 않으며, 문서 자체도 stale을 명시한다.
- 원본은 모델 raw·교과서 md·KDS 변환본으로 나뉜다. 검색은 concepts/models/textbook/experience만 포함하며, textbook/md는 낮은 우선순위로 검색한다. standards/examples는 현재 검색 대상이 아니다.
- 개념 템플릿의 “6개 파일 채우기”와 현재 규약의 “두 파일부터 시작”이 다르다.
- waves README에서 교과서 이론 노트로 가는 길, XBeach에서 관련 개념으로 돌아가는 길, 여러 토픽에 흩어진 모델 비교 노트의 안내가 약하다.
- XBeach R1–R4는 이미 입력·종료 조건이 고정돼 있다. 전체 감사와 개별 정정의 반영도 기존 R3 실행 규칙에서 분리하고 있다. “고정 기준이 없다”거나 “현재 어떤 보강도 전체 감사 전에는 불가능하다”는 진단을 하지 않는다.

## 2. 권고: 저장 위치 유지, 탐색·현재 작업·검증 단위 정리

목적은 연안공학 개념·이론·분석법을 이해하고 모델 구현·차이·제약을 원문으로 추적하는 지식 기반이다. 개인 계산 케이스는 이 지식을 공급받아 별도에서 만든다. [현재 목적](../../README.md), [경계 규칙](../../CLAUDE.md)

| 현재 영역 | 개편 후 독자에게 보이는 역할 | 물리 변경 |
|---|---|---|
| concepts | 개념에서 이론·분석법·모델 적용으로 진입 | 기존 경로 유지, README 탐색 안내 개선 |
| textbook/notes · textbook/md · sources.yml | 이론 설명과 원문 대조 경로 | 각자의 역할 유지, 이론 노트 진입 링크 추가 |
| models | 물리·수치·경계/입출력·구현 제약별 탐색 | 파일 재배치 없이 모델 README에서 기존 노트 연결 |
| standards | 설계기준의 원자료·변환본 안내 | 루트 안내에 등록. 검증된 AI 노트와 구별 |
| examples | 여러 개념·모델을 결합한 실습 | 기존 경로·상태 유지, 루트에서 찾을 수 있게 안내 |
| experience · data | 검증된 경험·분석 노트와 그 근거 데이터 | 원래 배치·검증 조건 유지 |
| research · references/collect.py | 자료 수집·후보 검토와 수집 코드 | 연구 후보와 canonical의 경계 유지 |
| tools · _staging · _archive | 검색·검사, 진행 중 근거, 과거 이력 | 사용자용 개념 목차와 구별해 운영 안내에 연결 |

이 표는 목표 역할의 설명이다. **P1에서 편집할 파일은 §6의 8개뿐**이며 이론 노트는 편집하지 않는다. 다른 모델·토픽의 README 개편은 첫 비교 결과 이후 별도 판단한다.

새 최상위 지식 폴더나 별도 WORKPLAN은 만들지 않는다. `plan.md` 맨 위에 **현재 작업 이름과 상세 계획/상태 원장의 링크**만 둔다. 현재 사용자 지시가 이 포인터보다 우선한다. 상세 미완 목록·결함·진행률을 복사하지 않는다. 모델 원장은 모델별 사실의 기준이며 과거 RESUME의 다음 작업을 전역 실행 명령으로 해석하지 않는다.

기술 설명은 한 canonical 위치에 둔다. 개념→교과서→모델 연결과 모델→개념 역링크는 탐색 링크라고 표시하고 주장을 복제하지 않는다. 기존 `layer`·`depends_on`를 바꾸지 않는다. **근거 인용**으로 사용하는 경우에는 기존 citation_status 전파 규칙을 적용한다. 단순 탐색 링크는 [CONVENTIONS §8.1](../../CONVENTIONS.md)의 탐색/근거 구분을 따른다.

## 4. 바꿀 작업 규칙과 유지할 검증

**변경 제안은 착수 우선순위와 작업 단위의 명시화다.** 기존 R3는 확인된 정정을 R1/R2 전체 종료 전에 반영할 수 있게 한다. 이 방식을 모델 공통 규약에 명시하고, 현재 활성 작업을 사용자가 고른 지식 보강 묶음으로 관리한다. 지금의 규약이 모든 지식 활동을 전수 감사로 일괄 차단한다고 주장하지 않는다.

| 조항 | 채택 후 처리 |
|---|---|
| 개별 지식 보강 | 그 주장에 필요한 원문·식·조건·코드를 대조하고 해당 외부 검토·필요한 사람 결정을 거쳐 반영. 전체 모델 감사는 독립 상태로 유지 |
| 선정 원문 판독 | 선정한 논문/장/절·판본을 먼저 명시하고 그 범위는 충실하게 읽음. 특정 절 판독을 전권 판독으로 표현하지 않음. 기존 승인 전수 집합의 축소 권한으로 쓰지 않음 |
| 고정 전수 집합·종료 조건 | 변경하려면 사용자 명시 결정·원래 snapshot 보존·개정 기록을 갖춘 별도 변경. 구조 개편이나 “진행”을 축소·완료 허가로 해석하지 않음 |
| 중요도·배제 판단 | 읽지 않은 driver·이론을 이름만 보고 비핵심으로 분류하지 않음. 기존 note_worthy 근거 의무 유지 |
| 주장 검증 | 인용 위치뿐 아니라 원문이 해당 수치·식·실행 조건을 지지하는지 대조. 새로 쓰거나 실질 변경하는 범위에 적용, 전체 위키의 주장 DB를 일괄 생성하지 않음 |
| 완료와 상태 | citation_status·has_source_needed·독립 검토·사람 게이트 유지. 승인되지 않은 새 주장에 기존 HG를 승계하지 않음 |
| 의존성 조사 | 모델 자체의 MPI 동작·호출 계약까지. Jumpshot·범용 라이브러리 내부는 기존 사용자 범위 통제를 따름 |

깊은 대조의 발동 조건은 게시 주장과 원문/코드의 충돌, 식·단위·모드 설명의 공백, 핵심 분야의 근거 공백, 인용 판본 변경이다. 입력과 종료 조건을 먼저 기록한다. 선택한 자료를 충분히 읽는 일과 모든 동봉 자료의 내부를 계속 확장하는 일은 구별한다.

근거는 [이번 조사](../../research/digests/2026-09-12-wiki-purpose-review.md)의 원문 충실도·인용 지지·누락/회귀 평가에 대한 단서다. 전수 감사와 선별 감사를 연안모델 위키에서 직접 비교한 실증은 확보하지 못했다. 이 제안을 입증된 최적안으로 표현하지 않는다.

| 기존 작업 | 개편안에서의 위치 | 완료 상태 |

새 파일·노트 이관·본문 단언·검색 코드 변경은 이 묶음에 포함하지 않는다. 링크 대상의 상태는 실제 frontmatter를 대조한다. 모든 13개 모델 링크와 등록 영역의 존재·역할을 확인하는 구조 검사를 수행한다. waves–XBeach 12문항만으로 전역 링크의 정합성을 대신하지 않는다.

### P2 — 공통 작업 규칙의 명시화

별도의 정책 개정 묶음으로 `CLAUDE.md`, `CONVENTIONS.md`, `plan.md`를 대조하고 §4의 정확한 delta만 반영한다. XBeach RESUME·GOAL-STATUS 두 문서에는 전역 활성 작업 포인터만 연결한다. 상세 모델 상태 원장을 복제하지 않는다. **변경 대상 5개**이며 기존 전수 snapshot·승인·완료 조건 자체는 수정하지 않는다.

기존 규약의 어떤 조항이 유지·보충·수정되는지 표로 확인하고 외부 검토를 받는다. P1은 현재 규약과 양립하는 안내 정리이므로 먼저 가능하다. P2가 채택되기 전에 P2를 근거로 새 분석의 범위를 축소하지 않는다.

P2의 plan.md 본문 변경은 §4의 실제 채택·개정 기록에 한정한다. 최상단 포인터는 실제 활성 작업의 전환만 기록하며 P1의 범위·완료 기록을 덮어쓰지 않는다.

### P3 — 탐색 유용성 확인 후 확대 판단

P1 변경 **전** 질문 12개와 기대 근거 위치·상태를 고정하고 전후 1회씩 같은 조건으로 확인한다. 개념/이론 3, 구현 연결 3, 비교/한계 2, 근거 부족 2, 변경과 무관한 회귀 2다. 단계 번호가 뒤여도 기준선은 반드시 P1 이전이다.

평가 범위는 탐색 경로·근거 위치 도달·draft/disclosed-gap 노출·부적절한 확신 여부다. 원출처로 기대 근거의 범위를 확인하되 새로운 수치 스킴 감사를 수행하지 않는다. 알려진 사실을 아는 평가자가 수행한 결과를 블라인드나 미지 결함 발견률로 표시하지 않는다. 문항 점수를 위키 전체 정확도나 XBeach 완료율로 올리지 않는다.

종료는 전후 비교 1회, 명확한 회귀 수정 1회까지다. 수정은 **P1의 8개 파일과 그 허용 변경 안**에서만 한다. 밖에서 드러난 기술 문제는 근거와 영향을 기록하고 관련 안내에서 한계를 드러낸다. 질문 추가·솔버 실행·R1 재개·새 검색 엔진 구현으로 확대하지 않는다. 미해결 중대한 안내 오류가 있으면 통과 처리하지 않고 확대를 보류한다.

**전체 실행 순서:** 개편안 채택 → 12문항 기준선 동결 → P1 → 전후 확인·범위 내 수정 → P2의 구체적인 정책 패치 검토·채택 → 이후 확대/감사 우선순위 결정. P1과 P2의 실제 구현은 각각 구체적인 diff와 기존 절차로 검토한다.

## 7. 이번 개편에서 유보할 것

- 현재 검색은 concepts·models·textbook·experience 네 root만 포함한다. standards(기준 변환본)·examples·data·references·research·_staging·_archive는 대상 밖이다. 이들의 검색 편입은 안내 개선과 분리해 결정한다. 변환본·실습을 단순히 verified 자료로 추가하지 않으며, 첫 묶음에서는 직접 탐색 링크로 접근한다.
- references 수집 코드를 tools로 옮기거나 data를 외부 저장소로 이동하지 않는다. 실행 경로·재현 근거 의존성 확인 없이 이름만으로 재배치하지 않는다.
- `_staging`의 파일이 많다는 이유로 영수증을 삭제·재생성하지 않는다. 빈 중첩 디렉터리도 이번 구조 파악을 정리 명령으로 해석해 삭제하지 않는다.
- 새 DB/GraphRAG/cron, 모든 문서의 주장 manifest, 전 모델 템플릿 일괄 채우기를 만들지 않는다.
- 루트의 swan_prd.md·swan_ecs.md는 위치를 확인했으나 내용 역할의 처분은 미정이다. 이번 묶음에서 이동·삭제·재분류하지 않는다.

## 8. 검증·보고·되돌리기

기존 링크·research 격리·로컬 경로 경계·layer/claims 검사를 사용한다. 폴더 안내와 상태 출처를 직접 대조한다. XBeach 불변 기록 292개와 P1 대상 밖의 canonical 노트 바이트·승인 상태를 보존한다. 코드가 바뀌지 않는 이번 묶음에 새 테스트 프레임워크를 만들지 않는다.

진행 보고는 “고정 묶음 / 반영 산출물 / 검토 대기 / 남은 문제”다. 폴더·파일 수나 질문 점수를 모델 전체 퍼센트로 바꾸지 않는다. 변경 묶음별 커밋으로 나누고 문제가 생기면 해당 탐색/정책 변경만 되돌릴 수 있게 한다. 원본과 기존 노트 경로를 유지하므로 이관 복구 작업이 필요 없어야 한다.

사용자에게 제안하는 선택은 **현재 폴더를 유지한 채 실제 구조 안내와 waves–XBeach 탐색부터 고치고, 개별 보강과 전체 감사를 구분하는 기존 원칙을 공통 규약에 명시하는 것**이다. 이번 요청은 계획 작성이며 구현 승인을 받은 것으로 기록하지 않는다.
