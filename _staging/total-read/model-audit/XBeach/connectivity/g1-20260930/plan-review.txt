수정 분류표는 다음처럼 **결속 범주와 적용 조건을 분리**하는 편이 안전합니다.

| `resolution` — 후보당 하나 | 필수 근거 |
|---|---|
| `direct_edge` | 조건별 실행 정의 ID, USE/동일 scope/host 가시성, 호출 호환성 |
| `generic_edge` | generic 가시성·interface, specific ID, 전체 실인자–형식인자 대응 |
| `indirect_interface` | 포인터/type-bound 선언, 인터페이스, 등록·association 또는 dispatch 조건; 모르는 실제 대상은 명시 |
| `intrinsic` | 표준/컴파일러 구분, 이름 가림 여부와 실제 호출 형태 확인 |
| `external_interface` | 외부 심볼·선언/모듈·빌드/링크 근거; 구현 내부는 조사 종료 |
| `not_a_call` | 해당 scope의 배열·변수·문자열 등 선언과 표현식 해석 |
| `unresolved` | 결속 실패 원인, 부족한 증거, 종료 판단에 미치는 영향 |

모든 행에 별도로 `bindings[]`, **프로젝트별 파일 포함 상태**, **CPP 조건**, **실행 조건**, **확인/제외/미확정 상태**를 둡니다. 생성 여부는 대상·증거의 출처 속성으로 기록합니다. 기존 `guard_excluded`·`guard_conditional`은 이 별도 축으로 옮기고, 제외되어 결속을 조사하지 않은 경우도 명시하여 해결된 호출로 집계하지 않아야 합니다.
