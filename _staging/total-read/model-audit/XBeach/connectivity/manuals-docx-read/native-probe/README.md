# 빈 수식 스트림과 글리프 대조 — 2026-09-11

AI의 한정 판독 기록이다. 원본과 과거 판독 영수증은 보존했다. [새 영수증](receipt.json)에 원본 DOCX·문단·관계 ID·OLE·Equation Native 바이트와 검사 결과를 결속했다.

**Kingsday p.27 식 (2.38)의 Equation Native에는 수식 본체가 없다.** 221바이트 중 앞 28바이트는 불투명한 접두부로 보존했다. 오프셋 28부터는 MTEF5 헤더, 인코딩·글꼴·크기·간격·스타일 설정, FULL, END가 있으며 오프셋 221에서 정확히 끝난다. LINE/CHAR/TMPL 등 수식 본체 레코드는 없다. 따라서 이 스트림에서 해당 식을 복원할 수 없다.

해석은 [Wiris 공식 MTEF5 규격](https://docs.wiris.com/en_US/mathtype-mtef-v5-mathtype-40-and-later)의 헤더·레코드·차원 배열 설명에 따른다. 공식 사이트의 검색 색인 내용을 확인했으나 직접 다운로드는 로그인 화면으로 이동했으므로 완전한 규격 사본을 확보했다고 하지 않는다. OLE 접두부 전체를 해석하는 일반 파서는 작성하지 않았다.

두 DOCX의 삽입 오브젝트에서 같은 MTEF 바이트를 가진 다음 5개를 결속했다. 전체 Native 스트림은 접두부가 달라질 수 있으므로 오브젝트 전체 동일성으로 확대하지 않는다.

[검사 코드](../inspect_empty_native.py)는 지원하는 설정 레코드와 최상위 종료만 읽는다. 수식 본체·미지원 레코드·알 수 없는 옵션·잘린 입력·종료 이후 바이트는 거부한다. 일반 수식 해독기로 사용하면 안 된다. [검증 코드](../validate_native_probe.py)는 원본 결속·재현과 함께 모든 절단 위치, 본체 삽입, 종료 뒤 데이터, 잘못된 버전·옵션에 대한 거부를 검사한다.

두 판본의 (2.5)–(2.8), B.37/C.37 원본 WMF 10개도 별도로 렌더하여 [대조 이미지](preview-contact.png)를 확인했다. 전체 PDF·PNG와 원본 WMF/OLE·문단 XML도 저장했다.

- (2.5)는 별도 렌더에서도 k의 위첨자가 네모로 남는다. 정확한 문자 식별은 미해결이다.
- (2.6)–(2.8)은 별도 렌더에서 본체가 보이며 네모 표시는 관측하지 않았다.
- B.37/C.37은 별도 렌더에서도 첫 줄이 `0a`, 둘째 줄이 `0`으로 끝난다. 원시 문자 레코드와 수학적 의도는 아직 대조하지 않았다.
