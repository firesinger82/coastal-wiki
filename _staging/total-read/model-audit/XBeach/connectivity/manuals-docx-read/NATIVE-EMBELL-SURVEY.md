# 문자 장식 목록의 한정 판독

2026-09-11 AI 구조 분석. [영수증](native-embell-survey.json), [새 판독기](inspect_embell_records.py), [조사 재현](survey_native_embell.py), [검증](validate_native_embell.py).

[Wiris MTEF5 명세](https://docs.wiris.com/en_US/mathtype-mtef-v5-mathtype-40-and-later)의 공식 검색 인덱스 발췌에서 CHAR의 장식 목록과 EMBELL 레코드 형식을 확인했다. 전체 명세를 내려받은 것은 아니다. CHAR 옵션 1일 때 별도 END로 닫히는 장식 목록을 읽고 해당 문자 아래에 저장한다. EMBELL은 옵션 0과 종류 코드 2–22만 지원한다. 이동 보정(nudge), 미지원 옵션/종류, 목록 안의 비장식 레코드는 거부한다. 기존 판독기와 과거 영수증은 보존한다.

이 확장으로 80개를 추가 수용해 전체 486개 중 441개 기계적 수용·본문 미지원 42개·접두부 미해결 3개가 됐다. 추가 수용된 스트림의 문자 장식은 문자 및 Native 바이트 좌표와 함께 영수증에 저장했다. 기존 수용 361개의 구조 출력은 이전 판독기와 완전히 같다.

검증은 전체 원본 재추출·결과 재현, 이전 수용 출력 대조, 실제 관측한 장식 종류별 전체 절단/후행 바이트 거부, 독립 바이트 fixture의 문자-장식 소속 및 좌표, 미지원 장식 옵션·종류·문자 옵션·잘못된 목록 거부를 포함한다. 종류 2–22의 모든 시각 형태를 확인했다는 뜻은 아니다.

수학적 의미와 렌더 충실도는 별도 확인 대상이다. 전체 gate NOT_PASSED·신규 사람 승인 없음. 다음은 나머지 레코드/옵션과 Master 접두부 3개를 확인하고 수용된 식도 원문/렌더와 대조하는 작업이다.
