이 부속서는 위 본문(v1~v3 규율)에 **우선한다**. 충돌하면 이 부속서를 따른다.

## 개정 사유

2026-08-11 게이트 v4 의 validator 로 기존 pending 을 검사한 결과, code 249 레코드 중 **33 파일**,
note 20 레코드 중 **17 파일**이 결함으로 나왔다(name 항목 기준 code 69개·note 118개).
2026-08-13 원인 분류 결과 **창작 라벨은 0건**이었고, 그중 177개 항목이 "수치 리터럴 name"
(`'0.53'`·`'-0.39'`)이었으며 그 수치는 **전부 앵커 줄에 문자 그대로 실재**했다.

즉 판독자는 본문 A절 후단("식별자가 없는 항목은 name 에 그 줄에 실재하는 첫 토큰을 쓴다")을
그대로 따른 것이다. 그런데 게이트 v4 의 anchor_check 는 name 에 식별자 토큰이 없으면 거부한다.
**A절 후단은 게이트와 양립 불가**이며, 이 상태로 재판독하면 판독자에게 남는 수는 이름을
창작하는 것뿐이다(= 2026-08-11 doc 폐기 2 의 실패 모드). 이를 막기 위해 개정한다.

동시에 게이트를 **v5** 로 조였다(2026-08-13, Codex 적대검증 반영). v4 는 부분문자열 일치와
다토큰 중 하나만 일치하는 것을 허용해서, `DT` 가 `DTMAX = 1.0` 을, `DATA column_1` 이
`DATA(1) = 0.53` 을 통과시켰다. 실제로 doc 축 input.txt 에서 `SLP @L32`(실제 L31)·
`PLOT_INTV @L49`(실제 L48) 계통 off-by-1 이 이 구멍으로 통과해 있었다.

## A. name 규율

### A-1. 본문 A절 후단 폐기

"식별자가 없는 항목(포맷 행 등)은 name 에 그 줄에 실재하는 첫 토큰을 쓴다" 는 **무효**다.
대신 게이트 v5 가 집행하는 두 규칙을 따른다.

- **N1. name 전체 문자열이 앵커 줄에 문자 그대로 실재해야 한다.** 식별자 경계까지 일치해야 하며,
  다른 이름의 부분문자열은 근거가 아니다. `DT` 를 `DTMAX = 1.0` 줄에 앵커할 수 없고,
  `PLOT_INTV` 를 `PLOT_INTV_STATION` 줄에 앵커할 수 없다. name 에 토큰이 여러 개면
  **그 전체가 통째로** 원문에 있어야 한다 — 하나만 맞고 나머지가 창작이면 거부된다.
- **N2. 순수 수치 리터럴 name 금지.** `0.53`·`-0.39`·`4.42674E-10`·`1.0_SP` 는 name 이 될 수 없다.
  이런 항목은 아래 A-2 로 처리한다.

1자 식별자는 정상이다 — `real, parameter :: g = 9.81` 은 name=`g` 로 기록한다.
식별자 문법이 아닌 원문 토큰도 그대로 실재하면 정상이다 — `!_TAG_FILE_FORMAT`(ctags),
`%%BoundingBox`(EPS), 매뉴얼 표의 `HOT START` 처럼 공백이 포함된 파라미터명도 원문에
그대로 있으면 통과한다. **판단 기준은 식별자 문법이 아니라 원문 실재다.**

### A-2. 이름 없는 수치 항목의 처리 (doc-v2 부속서03 B절과 동일 규율)

포맷 행·데이터 블록·표처럼 그 줄에 이름이 없는 수치 항목에서:

- **라벨을 창작하지 마라.** `column_1`·`row_count`·`LAYER_012`·`spectral_floor`·`Coherent_Percentage`
  처럼 그 파일에 없는 이름을 수치 행에 앵커하는 것은 금지다. 외부 지식이나 다른 파일의 포맷을
  이 파일에 귀속시키는 것이기 때문이다. 원문 토큰 하나를 앞에 붙여 게이트를 통과시키려는
  시도(`DATA column_1`)도 N1 이 거부한다.
- 그 수치는 `verbatim_spans` 에 **원문 그대로** 라인앵커와 함께 넣고, 열·행 구조와 값의 의미는
  `what_it_is` 에 서술한다. 구조를 안다고 해서 name 을 만들지 말고 what_it_is 에 쓴다.
- 그 결과 `constants`·`params_defined` 가 **빈 배열이 되어도 된다.** 빈 배열은 "판독 결과 이름
  있는 항목 없음"이라는 정직한 기록이며, 본문 5항·8항이 금지하는 '미판독 은폐'가 아니다.
- **단, 빈 배열은 원문에 이름 있는 상수·파라미터가 실제로 하나도 없을 때만 허용한다.**
  앵커가 틀렸다는 이유로 실재하는 항목을 지워서 빈 배열을 만드는 것은 금지다(아래 C-2).
  비어 있지 않은 수치 파일에서 `constants`·`params_defined`·`verbatim_spans` 가 **모두** 빈 배열인
  레코드는 부실 판독으로 간주한다.
- 같은 파일에 이름 있는 항목과 없는 항목이 섞여 있으면 이름 있는 것만 constants 에 넣는다.
- 변수에 대입되는 수치(`FroudeCap = 1.0`)는 **이름 있는 항목**이다 — name=`FroudeCap`, loc=대입줄.

### A-3. 수치 블록의 verbatim_spans 최소 기준

본문은 `verbatim_spans` 를 "짧게" 쓰라고 하고 A-2 는 수치를 거기 넣으라고 한다. 충돌을 피하기
위해 **모든 수치를 옮기는 것이 아니라 구조별 대표행을 보존**한다. 각 연속 데이터 블록마다:

- 블록의 라인 범위와 열 수를 `what_it_is` 에 기록한다.
- 블록의 첫 비어 있지 않은 행, 마지막 비어 있지 않은 행, 그리고 열 구조가 바뀌는 각 최초 행을
  `verbatim_spans` 에 원문 그대로 넣는다.
- 파일 자체에 명시되지 않은 열 의미·단위는 단정하지 않는다. 모르면 `unresolved` 에 적는다.

## B. 앵커 규율

### B-1. loc 은 '그 필드를 입증하는 정의 발생 행'이다

`constants`·`params_defined` 의 loc 은 식별자의 **정의 발생**이 있는 물리 행이다.

- 대입문은 좌변이 있는 행, 선언문은 선언자가 있는 행, 헤더 필드는 그 헤더 토큰의 행.
- **주석·우변 참조·단순 사용처의 동명 토큰은 loc 근거가 아니다.** 파라미터를 설명하는
  주석줄(`! Froude Number Cap ...`)과 실제 대입줄(`FroudeCap = 1.0`)은 다른 줄이며 loc 은 대입줄이다.
- 연속행(Fortran `&`, MATLAB `...`)에서 이름과 값이 서로 다른 행에 있으면 loc 은 **이름의 정의 행**에
  두고, 값이 있는 행은 별도로 `verbatim_spans` 에 근거를 남긴다.
- 같은 이름이 여러 번 정의되면 정의마다 각각 기록한다.

(2026-08-11~13 적발 사례: `MPI_IRECV @L75` 는 L74 호출의 인자 줄, `BB @L116`·`DxSxx @L187` 은
off-by-1, `SLP @L32` 는 L31 이 정답인데 L32 의 `Xslp` 에 부분문자열로 걸렸다.)

### B-2. 게이트가 기계적으로 보장하는 범위 (오해 금지)

게이트 anchor_check 는 **`constants`·`params_defined`·`equations` 만** 검사한다.
`entities`·`io`·`calls`·`verbatim_spans` 의 앵커는 **검사하지 않는다.**
따라서 `calls` 에 적은 `MPI_IRECV @L75` 가 틀려도 게이트는 통과시킨다.
게이트 PASS 는 "이 세 필드의 앵커가 실재한다"는 뜻일 뿐 레코드 전체의 정확성 보증이 아니다.
나머지 필드의 앵커 정확성은 본문 C절 자가대조와 맹검 감사가 책임진다 — 자가대조를 생략하지 마라.

## C. 제출 규율

### C-1. 실측 필드

`bytes`·`lines_or_pages`·`read_range`·`chunk_manifest_sha256` 은 CHUNK-HEADER 값을 **그대로**
옮긴다. 추정·재계산 금지. 게이트 submit 이 manifest 실측값과 대조해 불일치 시 거부한다.

### C-2. 본문 C절 "항목을 제거" 의 제한

본문 v2 C절은 확인 불가한 앵커를 "수정하거나 항목을 제거"하라고 한다. 이 중 **제거는
다음 경우에만 허용한다**: 재대조 결과 그 항목이 원문에 존재하지 않거나, 해당 스키마 범주가
아님이 확인된 경우. 실재하는 항목을 verify 통과를 목적으로 제거하는 것은 금지다 —
그것은 전수 열거 의무 위반이자 미판독 은폐다. 앵커가 틀렸으면 **원문에서 실제 정의 발생 행을
다시 찾아 정정**하는 것이 정답이다.

### D-1. reader·producer 의 model-id

`reader`·`producer` 에는 계열명이 아니라 **이 지시문에 명시된 실측 model-id** 를 그대로 쓴다.
자기 판단으로 계열명을 적지 마라(2026-08-11 적발: 판독자가 자기 ID 를 `gpt-5` 로 자기신고해
203건 전량 폐기). 지시문에 실측 model-id 가 없으면 **레코드를 생산하지 말고 run 을 시작 전
실패 처리**하고, model-id 가 포함된 새 동결 프롬프트를 요구하라. `reader`·`producer` 는 필수
provenance 필드이며 `unresolved` 로 대체할 수 없다.
