# Claude Fable 5.1 검토

요청·응답 모델: `claude-fable-5-1` (`modelUsage` 확인). 보조 사용 모델은 원본 JSON 참조.

**판정: 반영 가능. blocker 없음.** 다섯 파일의 diff는 구조 계획 §4의 7개 조항과 §6 P2의 범위(정확히 5파일, 전수 snapshot·승인·완료 조건 불변)에 일치하며, 어떤 게이트도 약화하지 않았다.

**질문별 확인**

- **분리 명시 + 게이트 유지**: CLAUDE.md 신설 절이 "전체 감사 완료를 기다리지 않고 반영할 수 있다"와 "대조·검토·게이트를 면제한다는 뜻은 아니다"를 한 문단에 같이 둔다. R3 원문("이 정정들은 R1/R2 전체가 끝날 때까지 기다릴 일이 아니다", "R3 전체의 종결만 R1/R2 최종 판정에 의존한다")과 같은 구조다.
- **개별 반영 → 전체 감사 완료?**: "개별 보강 반영을 미완인 전체 감사의 완료로 간주하지 않는다"로 명시 차단.
- **선정 범위의 전권 과장**: CONVENTIONS 보충 절 첫 항 "절 단위 판독을 문헌 전권 판독이라고 표현하지 않는다" 및 `verification_method`에 범위·한계 기록. 검증기가 이 필드 값을 고정 문자열로 강제하지 않음을 tools/ grep으로 확인했다.
- **고정 집합 변경 요건**: CLAUDE.md "사용자의 별도 명시 결정, 원래 snapshot 보존, 개정 기록" 세 요건 모두 있고 "구조 개편이나 일반적인 진행 지시를 그 결정으로 대체하지 않는다"가 붙어 있다. CONVENTIONS 쪽도 "전수 승인 집합을 축소하는 근거로 사용하지 않는다"로 대칭.
- **위치 매칭 vs 의미 지지**: "인용 위치·문구 매칭만으로 의미 검증이 끝난 것이 아니다. 해당 수치·식·적용 조건을 원문이 실제로 지지하는지 확인한다"로 구분됨. 기존 2종 검증 방법은 "그대로 유효"로 보존.
- **citation_status·has_source_needed·HG**: 3종·3상태 유지 명시, "새 주장에 과거 사람 승인(HG)을 자동 승계하지 않는다" 포함. §2.0 G9 본문은 손대지 않았다.
- **전역 포인터 단일화**: CLAUDE.md, RESUME.md, GOAL-STATUS.md 세 곳이 모두 `plan.md#현재-작업` 하나를 가리키고, RESUME·GOAL은 "아래 기록의 현재·다음·재개 표기는 당시의 이력으로서 전역 실행 지시가 아니다"를 덧붙인다. 상대경로 5단계(`../../../../../plan.md`)는 connectivity 깊이와 맞는다. `note_worthy`는 루트 plan.md에 실재하는 용어다.

**반영 조건 (blocker 아님)**

1. **P1 선반영 필수.** P2의 plan.md before 해시(`8e601e78…`)는 P1 install-manifest의 after 해시와 같고, 작업 트리 plan.md에는 아직 `## 현재 작업` 절이 없다. P1 미반영 상태에서 P2를 적용하면 CLAUDE.md의 `plan.md#현재-작업` 링크가 끊긴다. install_policy.py가 target drift를 assert하므로 순서 위반은 실패로 잡히지만, README P2 절에 "P1 반영 후"를 한 줄 명시하면 사람이 헷갈리지 않는다.
2. **plan.md 개정 기록이 얇다.** P2 채택 절은 내용을 `_staging/wiki-navigation-20260913/README.md`로만 위임한다. `_staging`은 CLAUDE.md 규칙 8상 경유지이고 이 디렉토리는 현재 미커밋이다. 패치 자신이 "개정 기록"을 요건으로 세우는 만큼, 그 절에 변경 5파일명과 "CLAUDE.md 신설 절·CONVENTIONS §2 보충 절·RESUME/GOAL 포인터" 한 문장을 직접 적는 것이 최소 해결책이다. 또는 해당 staging 디렉토리를 같은 커밋에 포함한다.
