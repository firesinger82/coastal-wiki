
## models/ADCIRC/raw/source_code/adcirc/docs/introduction/what_is_adcirc.rst:1–84
1: What is ADCIRC?
2: ===============
3: 
4: **ADCIRC** is a system of computer programs for solving time dependent, free surface circulation and transport problems in two and three dimensions. These programs utilize the finite element method in space allowing the use of highly flexible, unstructured grids. The system has been optimized for parallel computing architectures, making it highly efficient for large-scale simulations.
5: 
6: Model Features
7: --------------
8: 
9: ADCIRC can be used to simulate:
10: 
11: * Tidal and Wind-Driven Circulation
12: * Hurricane Storm Surge and Flooding
13: * Wave-Current Interaction
14: * Dredging and Material Disposal Studies
15: * Transport of Materials
16: * Baroclinic Circulation
17: * Coastal Inundation and Protection Studies
18: 
19: ADCIRC Programs
20: ---------------
21: 
22: The ADCIRC software package provides the following programs:
23: 
24: * **ADCIRC**: Serial version of the core circulation model
25: * **PADCIRC**: Parallel version of ADCIRC for high-performance computing environments
26: * **ADCPREP**: Domain decomposition utility for preparing parallel simulations
27: * **SWAN**: Serial unstructured wave model
28: * **ADCSWAN**: Serial coupled ADCIRC+SWAN model
29: * **PADCSWAN**: Parallel coupled ADCIRC+SWAN model
30: * **PUNSWAN**: Parallel unstructured SWAN model
31: * **ASWIP**: Preprocessor for converting ATCF formatted hurricane forcing data
32: * **LIBADC**: Library of ADCIRC subroutines for incorporation into other codes
33: * **Utilities**: Various utility codes for pre- and post-processing
34: 
35: System Requirements
36: -------------------
37: 
38: ADCIRC is highly scalable and can be run on a range of platforms, from a standard desktop/laptop computer to high-performance computing (HPC) clusters. The hardware requirements depend on the size and complexity of the computational grid and the length of the simulation.
39: 
40: ADCIRC can be compiled and run on:
41: 
42: * Linux/Unix systems
43: * Windows (using compatible compilers)
44: * MacOS
45: 
46: The model is written in Fortran and requires:
47: 
48: * Fortran compiler (gfortran, Intel Fortran, etc.)
49: * MPI library for parallel execution
50: * Optional: NetCDF libraries for certain output formats
51: 
52: Getting Started
53: ---------------
54: 
55: To get started with ADCIRC, you'll need to:
56: 
57: 1. Install prerequisites (compiler, MPI, etc.)
58: 2. Build ADCIRC using either traditional make or CMake method
59: 3. Prepare input files
60: 4. Run simulations
61: 5. Analyze output
62: 
63: For detailed installation and running instructions, see :doc:`Getting Started <../getting_started/index>`.
64: 
65: For questions and support, please see the :doc:`Questions and Support <../questions_and_support/index>` section.
66: 
67: ADCIRC Files
68: ------------
69: 
70: ADCIRC uses a set of input files to define the model domain, boundary conditions, and runtime parameters:
71: 
72: * Fort.14: Grid and boundary information
73: * Fort.15: Model parameters and periodic boundary conditions
74: * Fort.13: Nodal attributes
75: * Additional files for meteorological forcing, wave forcing, etc.
76: 
77: The model produces various output files containing water levels, currents, and other variables at specified locations and time intervals.
78: 
79: For detailed descriptions of all input and output files, and parameters, see the :doc:`Input Files <../technical_reference/input_files/index>`, :doc:`Output Files <../technical_reference/output_files/index>`, and :doc:`Parameters <../technical_reference/parameter_definitions/index>` sections of this documentation. 
80:

10: **IM** is an important parameter in the `fort.15 file <fort.15_file>`__ that
11: defines numerical model formulation and dimension. Among other things, ``IM``
12: specifies whether ADCIRC is solved in two-dimensional depth-integrated (2DDI) or
13: in three-dimensions (3D), solution of the governing equations is semi-implicit

15: baroclinic. Popular values for 2D barotropic ADCIRC include ``IM=0`` and
16: ``IM=111112``; users should be aware that the
17: :ref:`A00 <A00>`, :ref:`B00 <B00>`, and :ref:`C00 <C00>` coefficients must be
18: specified differently in these two cases.

10: **ICS** is a fundamental parameter in the :ref:`fort.15 file <fort15>`
11: that defines the coordinate system and the desired projection. The value of ICS
12: also has an important consequence for the choice of the Coriolis
13: :ref:`CORI <CORI>` parameter of the :ref:`fort.15 file <fort15>`.
14: 
15: .. _available_ics_values:
16: 
17: Available ICS Values
18: --------------------
19: 
20: .. list-table::
21:    :widths: 10 15 40
22:    :header-rows: 1
23:    :class: wrap-table
24: 
25:    * - ICS Value
26:      - Short-name
27:      - Description
28:    * - 1
29:      - Cartesian
30:      - Points in the fort.14 are already mapped onto an arbitrary Cartesian coordinate system, e.g., UTM. Also useful for idealized problems.
31:    * - 2
32:      - Geographic, CPP, no curvature
33:      - Points in the fort.14 are specified in geographic coordinates, which will be projected using the CPP (equidistant) cylindrical mapping by ADCIRC. The curvature of the Earth is not accounted for.
34:    * - 20
35:      - Geographic, Equal-area
36:      - Points in the fort.14 are specified in geographic coordinates, which will be projected using the Equal-area cylindrical mapping by ADCIRC. The curvature of the Earth is correctly accounted for.
37:    * - 21
38:      - Geographic, CPP
39:      - Points in the fort.14 are specified in geographic coordinates, which will be projected using the CPP (equidistant) cylindrical mapping by ADCIRC. The curvature of the Earth is correctly accounted for.
40:    * - 22
41:      - Geographic, Mercator
42:      - Points in the fort.14 are specified in geographic coordinates, which will be projected using the Mercator (conformal) cylindrical mapping by ADCIRC. The curvature of the Earth is correctly accounted for.
43:    * - 23
44:      - Geographic, Miller
45:      - Points in the fort.14 are specified in geographic coordinates, which will be projected using the Miller cylindrical mapping by ADCIRC. The curvature of the Earth is correctly accounted for.
46:    * - 24
47:      - Geographic, Gall-Stereographic
48:      - Points in the fort.14 are specified in geographic coordinates, which will be projected using the Gall-Stereographic cylindrical mapping by ADCIRC. The curvature of the Earth is correctly accounted for.
49: 
50: Implications
51: ------------
52: 
53: Beginning from Version 55, ICS values equal to 20-24 will be possible. These are
54: intended to replace the old method of specifying ICS = 2, but this option is
55: retained for regression testing. When ICS = 2, the curvature of the Earth is not
56: correctly accounted for in the Spherical coordinate form of the governing
57: equations which becomes more important as the geographic size of the
58: computational domain size increases. In recent years global modeling using
59: ADCIRC has been successful [1]_, e.g.,
60: `GLOCOFFS <https://wpringle.github.io/GLOCOFFS/>`__ where it was found that the
61: old method was deficient. The new options using values ICS = 20-24 now account
62: for the curvature correctly, and should in general be always used on

5: .. _astronomical_tides:
6: 
7: Astronomical Tides
8: ==================
9: 
10: ADCIRC supports two primary methods for implementing tidal forcings in your model: tidal potential terms and open boundary conditions. These can be used independently or in combination to achieve accurate tidal simulations.
11: 
12: Tidal Potential Terms
13: ---------------------
14: 
15: Tidal potential terms represent the direct gravitational effects of celestial bodies (primarily the moon and sun) on the water surface. In ADCIRC, these are specified in the :ref:`fort.15 <fort15>` file through:
16: 
17: * ``NTIP``: Number of tidal potential constituents to be included
18: * ``TIPOTAG``: Name/tag for each tidal potential constituent
19: * ``TPK``, ``AMIGT``, ``ETRF``, ``FFT``, ``FACET``: Parameters defining amplitude, frequency, earth tide reduction factor, and nodal factor for each constituent
20: 
21: Open Boundary Conditions
22: ------------------------
23: 
24: Open boundary conditions allow you to specify water surface elevations at the model domain boundaries. These can be implemented in two ways:
25: 
26: 1. **Periodic (Harmonic) Conditions**:
27:    Specified in the :ref:`fort.15 <fort15>` file using:
28:    
29:    * ``NBFR``: Number of forcing frequencies on open boundaries
30:    * ``BOUNTAG``: Name/tag for each boundary forcing constituent
31:    * ``AMIG``, ``FF``, ``FACE``: Parameters for amplitude, nodal factor, and equilibrium argument
32:    * ``EMO``, ``EFA``: Elevation amplitude and phase for each constituent at boundary nodes
33: 
34: 2. **Non-periodic Conditions**:
35:    Time series of water surface elevations are defined in the :ref:`fort.19 <fort19>` file.
36: 
37: The locations of open boundaries are defined in the :ref:`fort.14 <fort14>` file through the open boundary node strings.
38: 
39: Internal Tide Energy Conversion
40: -------------------------------
41: 
42: For large-scale ocean models, internal tide energy conversion should be considered. This represents the conversion of barotropic to baroclinic energy as surface tides flow over deep ocean topography. It can be implemented through:
43: 
44: * A spatially varying nodal attribute called ``internal_tide_friction`` in the fort.13 file
45: * Typically applied only in deep ocean regions (>100-500m depth)
46: * Accounts for approximately 30% of global barotropic tidal dissipation
47: 
48: See :ref:`internal_tide_energy_conversion` for more details.
49: 
50: .. toctree::
51:    :maxdepth: 1
52:    :caption: Contents:
53:    :hidden:
54:    
55:    internal_tide_energy_conversion
56: 
57: Best Practices
58: --------------
59: 
60: 1. For coastal models, focus on accurate open boundary conditions
61: 2. For large-scale ocean models, include both tidal potential terms and internal tide energy conversion
62: 3. Ensure boundary conditions are properly ramped up using the ``NRAMP`` parameter in fort.15
63: 4. Validate your tidal implementation against known tidal constituents or observations
64: 
65: For detailed implementation guidance, refer to the :ref:`fort.14 <fort14>` and :ref:`fort.15 <fort15>` documentation.

## models/ADCIRC/raw/source_code/adcirc/docs/user_guide/special_features/bridge_piers.rst:1–21
1: Bridge Piers
2: ============
3: 
4: Given the typical resolution of coastal circulation models, (e.g., in nearshore applications resolved scales are usually 10s to 100s of meters and larger), it is rarely practical to solve explicitly for the small scale flow around obstructions such as bridge pilings (diameters of meters). However, in some situations it may be desirable to include the effects of these subgrid scale obstructions on the resolved scale flow. To accomplish this, a subgrid scale obstruction parameterization has been developed and implemented in ADCIRC. Since the cross-sectional area of these obstructions is usually quite small compared to the cross-sectional area of the flow field (and thus the effect on flow continuity is quite small), their primary effect is to impart additional drag on the resolved scale flow. This section describes the theory behind the obstruction parameterization implemented in ADCIRC.
5: 
6: The bridge pier option is turned on by setting the parameter ``NWP`` to add for an additional Nodal Attribute in the Model Parameter and Periodic Boundary Condition File. Required input coefficients are read in at specified nodes from the Nodal Attributes file (fort.13). Additional information can be found in Luettich and Westerink (1999).
7: 
8: Theory
9: ------
10: 
11: The two-dimensional, vertically integrated momentum equations used in ADCIRC contain bottom friction (drag) terms. To represent the extra drag caused by subgrid scale obstructions such as bridge piers, a second contribution has been added to the bottom friction terms:
12: 
13: * Bottom friction x + obstruction drag x 
14: * Bottom friction y + obstruction drag y
15: 
16: Options in ADCIRC exist to express the bottom friction terms as linear, quadratic or hybrid quadratic/Manning's n functions of flow velocity. The obstruction drag is assumed to be due primarily to form drag and therefore is represented as quadratic in velocity:
17: 
18: * obstruction drag x = :math:`C_D \frac{U\sqrt{U^2+V^2}}{H}`
19: * obstruction drag y = :math:`C_D \frac{V\sqrt{U^2+V^2}}{H}`
20: 
21: where :math:`C_D` is an obstruction (piling) drag coefficient.

## models/ADCIRC/raw/source_code/adcirc/docs/user_guide/special_features/dynamic_water_level_correction.rst:7–32
7: Dynamic water level correction
8: ==============================
9: 
10: **Dynamic Water Level Correction** is a process by which modeled water levels
11: are dynamically adjusted by use of a forcing term. The correction can be applied
12: as constant or varying in space and/or time. The correction is applied as a
13: forcing term in the momentum equations whose mathematical form is equivalent to
14: that of an atmospheric pressure term. This means that, for gradually-varying
15: corrections, corrected water levels should closely follow the input correction,
16: though these may deviate if a correction is applied very quickly or to an area
17: that has a very weak connection to an open boundary through which water can
18: flow. Further discussion is below in the :ref:`FAQ <dwlc_frequently_asked_questions>`.
19: 
20: Overviews and examples of this capability have been provided in multiple
21: presentations (Luettich et al. 2017 [1]_, Asher et al. 2018 [2]_) and a journal
22: article (Asher et al. 2019 [3]_) with details and an application to Hurricane
23: Matthew. Users looking for ways to generate water level correction surfaces can
24: look to that same article and this digital publication/data repository [4]_,
25: which holds the code base used in the aforementioned paper.
26: 
27: Version
28: -------
29: 
30: Early versions of this feature were implemented in v53, however important bug
31: fixes and a renaming of related variables [Note1]_ were done later, so users are
32: strongly encouraged to not use these earlier versions.

## models/ADCIRC/raw/source_code/adcirc/docs/user_guide/special_features/ice_modifications.rst:1–36
1: Ice Modifications
2: =================
3: 
4: ADCIRC has been modified to incorporate the effects of ice coverage on hydrodynamic processes. These modifications allow for more accurate simulations in polar and sub-polar regions where ice coverage significantly affects water circulation patterns.
5: 
6: Overview
7: --------
8: 
9: The ADCIRC ice modifications enable the model to account for:
10: 
11: 1. Ice coverage effects on surface wind stress
12: 2. Ice friction effects on water flow
13: 3. Changes in momentum exchange due to ice-water interaction
14: 4. Modifications to mass conservation equations to account for ice presence
15: 
16: Implementation
17: --------------
18: 
19: The implementation of ice modifications in ADCIRC involves several components:
20: 
21: * Modification of the governing equations to include ice effects
22: * Addition of ice-specific parameters in input files
23: * New output options for ice-related variables
24: * Special numerical treatments for partially and fully ice-covered regions
25: 
26: Usage
27: -----
28: 
29: To enable ice modifications in ADCIRC, specific parameters must be set in the fort.15 file. Additionally, ice coverage data may be provided through dedicated input files.
30: 
31: Detailed documentation on the implementation and usage of ice modifications can be found in the ADCIRC documentation: "Modifications to ADCIRC for ICE Coverage" (available at https://adcirc.org/wp-content/uploads/sites/2255/2016/01/adcirc_modifications_for_ice.pdf).
32: 
33: References
34: ----------
35: 
36: For complete details on the theoretical foundation, implementation, and usage of ice modifications in ADCIRC, please refer to the official documentation at the ADCIRC website: https://adcirc.org/wp-content/uploads/sites/2255/2016/01/adcirc_modifications_for_ice.pdf 

## models/ADCIRC/raw/source_code/adcirc/docs/user_guide/special_features/vertical_element_walls.rst:1–18

3: Vertical Element Walls (VEWs)
4: =============================
5: 
6: What are Vertical Element Walls?
7: --------------------------------
8: 
9: Vertical Element Walls (VEWs) are a special boundary condition in ADCIRC that allow for the representation of steep-sided channels or other vertical features within the mesh. Unlike traditional mesh elements that assume a gradually sloping bathymetry, VEWs provide a way to model abrupt vertical changes in the terrain, which is particularly useful for:
10: 
11: 1. Modeling narrow channels with vertical walls where traditional mesh elements would require excessive refinement, 
12: 2. Representing steep slopes or embankments without the need for complex mesh transitions, and thus,
13: 3. Simulating compound flooding scenarios involving river channels and floodplains
14: 
15: VEWs effectively create internal boundaries that allow water to flow between adjacent elements with different bed elevations, providing a more effective representation of channelized flow while maintaining computational efficiency.
16: 
17: .. note::
18:    VEWs and the :ref:`condensed_nodes` nodal attribute are implemented only for :ref:`IM` values that run ADCIRC in the lumped explicit mode.

## models/ADCIRC/raw/source_code/adcirc/docs/user_guide/examples/global_astronomical_m2_tide.rst:1–48

3:    :keywords: adcirc, global astronomical m2 tide
4: 
5: Global Astronomical M2 Tide
6: ===========================
7: 
8: This example tests ADCIRC version 55 (and beyond). It tests the simulation of
9: the astronomical M2 tidal constituent on the spherical Earth under equilibrium
10: tidal forcing with the inclusion of the self-attraction and loading tide. The
11: results of interest are the M2 tidal constituent amplitudes and phases of
12: elevations and velocities from the least-squares harmonic analysis. The test
13: finishes in about 5 minutes in serial ADCIRC for a full month of simulation.
14: Find the test at the `GitHub test
15: suite <https://github.com/adcirc/adcirc-cg-testsuite/tree/v55/adcirc/adcirc_global-tide-2d>`__.
16: 
17: Mesh
18: ----
19: 
20: The mesh is a coarse representation of the spherical Earth with minimum
21: resolution of approximately 50 km, comprised of 27,330 vertices and 50,859
22: triangular elements.
23: 
24: Options/Features Tested
25: -----------------------
26: 
27: -  :ref:`ICS <ICS>` = -22: Uses the Mercator projection with a coordinate
28:    rotation to remove the pole singularity (need to provide a
29:    :ref:`fort.rotm <fortrotm>`).
30: -  :ref:`IM <IM>` = 513113: Uses the fully implicit scheme for the gravity wave
31:    term (computational time step is 12 minutes).
32: -  :ref:`NTIP <NTIP>` = 2: equilibrium tide + self-attraction and loading tide
33:    forcing (read from a :ref:`fort.24 file <fort24>`).
34: -  :ref:`A00 <A00>`, :ref:`B00 <B00>`, :ref:`C00 <C00>` = 0.5, 0.5, 0:
35:    Ensures that the fully implicit scheme is stable with a large time step.
36: -  :ref:`ESLM <ESLM>` = -0.2: enables the Smagorinsky turbulence closure with a
37:    coefficient of 0.2.
38: -  :ref:`NHAGE <NHAGE>` = 5: outputs the harmonic constituent elevations into a
39:    netCDF4 :ref:`fort.53 file <fort53>`.
40: -  :ref:`NHAGV <NHAGV>` = 5: outputs the harmonic constituent velocities into a
41:    netCDF4 :ref:`fort.54 file <fort54>`.
42: -  :ref:`internal_tide_friction <internal_tide_friction>`:
43:    spatially varying linear wave drag :ref:`fort.13 file <fort13>` attribute
44:    accounting for energy conversion due to internal tide generation in the deep
45:    ocean.
46: -  :ref:`quadratic_friction_coefficient <quadratic_friction_coefficient_at_sea_floor>`:
47:    spatially varying quadratic bottom friction :ref:`fort.13 file <fort13>`
48:    attribute.

1: # ADCIRC Model Test Suite
2: The included suite of tests has been developed to test changes to the ADCIRC model and ensure solutions are consistent across releases. This suite is run any time a change is made to the model code and must pass before the code is allowed to be integrated into the upstream repository.
3: 
4: These also encompass a nice set of examples for users to get acquainted with setting up and running the model.
5: 
6: ## Running the Suite
7: ### Compiling for the suite
8: The automated test scripts may require the following ADCIRC executables to be compiled:
9:   1. adcirc
10:   2. padcirc
11:   3. adcswan
12:   4. padcswan
13:   5. adcprep
14: 
15: Depending on the modules used within the test suite, you may not need to compile all of these, 
16: though some tests may require certain features are enabled, such as netCDF or GRIB2 support.
17: 
18: ### Running Tests
19: The test suite uses a python test apparatus. This runner relies on a yaml file to define the testing metadata.
20: The default test list is `test_list.yaml` and is located in the root directory fo this repository. It is possible
21: to leverage your own tests by modifying this file or creating a new one. The test suite produces a series of plots
22: as well to aid diagnosing any issues that may arise.
23: 
24: To run the full set of tests, the following command is used:
25: ```
26: python3 test_runner/test_runner.py --all --bin <path/to/adcirc/build> --test-yaml test_list.yaml --tolerance 0.00001 --test-root .
27: ```
28: 
29: You can also run a single test by specifying the test name:
30: ```
31: python3 test_runner/test_runner.py --test <name_of_test> --bin <path/to/adcirc/build> --test-yaml test_list.yaml --tolerance 0.00001 --test-root .
32: ```
33: 
34: Note that the default testing tolerance is 0.00001. This can be adjusted by changing the `--tolerance` flag. It may be
35: useful to do so depending on your build settings and compiler.

39: an example of how a case should be constructed. Cases should exercise a feature or combination of features that is
