## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 277·285–292·335–460·1157·1166–1173·1218–1358·2109·2118–2125·2174–2332·2858·2866–2873·2922–3080: Real8 루틴 네 개의 입력 배열은 real(8)이다. 해당 루틴들의 송수신 버퍼 선언은 kind 지정 없는 real 또는 Real이다. 해당 통신 호출의 자료형 인수는 mpi_real8이다. 실제 kind 크기를 결정하는 빌드 설정은 이 파일 판독 범위에 포함하지 않았다.
- 2607–2608·2857–2858: 두 4D0 루틴의 배열 선언은 두 번째 차원 하한으로 istart를 사용한다. 원문 층 루프는 `do K = 0,KC`이다(2663·2694·2711·2742·2759·2790·2807·2837·2913·2944·2961·2992·3009·3040·3057·3087). 해당 루프 하한과 길이 계산식에는 istart를 사용하지 않는다(2681·2729·2777·2825·2931·2979·3027·3075).
- 1878·2129·2380·2627·2877: 4D·4D0 루틴들의 외부 할당 조건은 `if(.not.ALLOCATED(DSENDW_4D) .or. ndim > MAXLEN )then`이다. 해당 조건에는 JC·IC·KC·istart의 변경 여부를 검사하는 항이 없다. 일반 4D 버퍼 크기는 JC*KC*2*ndim·IC*KC*2*ndim이다(1879·1888·2130·2139·2381·2390). 4D0 버퍼 크기는 JC*(KC+1)*2*ndim·IC*(KC+1)*2*ndim이다(2628·2637·2878·2887).
- 123–248·335–460·544–669·753–885·979–1121·1218–1358·1445–1591·1679–1831·1923–2081·2174–2332·2425–2580·2672–2830·2922–3080: 각 MPI 호출은 ierr를 받으며 각 MPI_RECV는 status_message를 받는다. 이 파일의 실행문에는 ierr·status_message 값을 검사하는 조건이 없다.
- 69·281·491·700·922·1160·1393·1626·1862·2113·2364·2611·2861: 각 통신 루틴은 지역 정수 J 또는 j를 선언한다. 이 파일의 해당 루틴들에는 J 또는 j를 사용하는 실행문이 없다.
- 495–502·515–522·704–711·724–731: Communicate_1D_Integer와 Communicate_1D_Logical의 송수신 버퍼는 integer이다. 최초 할당 후 초기화 대입의 리터럴(literal)은 0.0이다.
- 2522–2532·2542: Communicate_4D_Integer의 해당 수신 분기는 nbr_south를 사용한다. 2542행은 DRECVS_4D를 복원하면서 주석에 `! unpack data from north`라고 적는다.
