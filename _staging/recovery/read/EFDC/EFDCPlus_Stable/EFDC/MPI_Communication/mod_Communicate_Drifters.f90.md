## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 180·218–222: Communicate_Drifters_Integer는 선택 인수 iLLA의 존재 여부로 iMap을 정한다. iLLA 값 자체를 검사하는 실행문은 이 루틴에 없다.
- 98·103·112·117·126·131·139·144·230·236·251·256·271·276·291·296: 방향별 송수신 호출은 모두 global_max_drifters_to_comm 개 원소를 전달한다. 방향별 send·recv 개수는 호출 실행 조건에 사용된다. 복원 호출의 size_r에는 방향별 recv 개수를 전달한다(149·153·157·161·306·310·314·318).
- 338–359·382–407: 실수 포장 루틴의 drifter_mapping 길이는 NPD이고 루프 상한은 global_max_drifters_to_comm이다. 정수 포장 루틴의 ghost_drifter_ids 길이는 global_max_drifters_to_comm이다. 두 포장 루틴은 local_drifter_id>0만 검사한 뒤 NPD 길이 배열에 접근한다. 해당 루틴들에는 local_drifter_id의 상한 검사가 없다.
- 438–450·481–490: 두 복원 루틴은 mapping_id(ii)를 NP에 복사한 뒤 local_drifter_data(NP)·LLA_Process(NP)·JSPD(NP)에 접근한다. 해당 루프들에는 NP의 범위 검사가 없다. 정수 복원 루틴의 Map2Local 접근에는 drifter_val>1 조건만 있다.
- 468·491: Unpack_Recieved_Data_RK8는 iMap을 입력 인수로 선언한다. 이 루틴의 실행문은 iMap을 사용하지 않는다. 491행 주석도 이를 명시한다.
- 68·98–144·193·230–296: 두 통신 루틴은 MPI 호출에서 ierr·status_message를 받는다. 이 파일에는 해당 반환값을 검사하는 실행문이 없다.
