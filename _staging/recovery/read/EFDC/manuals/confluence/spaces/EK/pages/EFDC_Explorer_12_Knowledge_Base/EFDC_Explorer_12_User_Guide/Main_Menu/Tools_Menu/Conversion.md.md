# Conversion.md — 판독 구간 기록

구간은 1행부터 36행까지 빈틈없이 이어진다.

| 구간 | 내용 |
|---|---|
| 1–9 | 문서 메타데이터 — 페이지 ID, 제목, space, 원문 URL, 버전, 갱신 시각, 문서 계층 경로와 frontmatter 구분선을 포함한다(1–9). |
| 10–13 | Conversion — Tools의 Conversion에서 단위·좌표·날짜 변환 하위 메뉴에 접근한다(10). 색상 CSS를 포함한다(10). 그림 `10-12-2021_4-06-01_PM.png`는 Unit Conversion, Coordinate Conversion, Coordinate File Conversion, Date Conversion 하위 메뉴를 보여 준다(12). 빈 줄과 그림 마크업을 포함한다(11–13). |
| 14–19 | Unit Conversion — 길이·면적·체적 등을 다른 단위로 바꾼다(16). 설정 이름·단위·유효 숫자(significant digits) 예시와 입력 순서를 그대로 옮긴다: `Select the *unit conversion,* the *Unit Conversion* form displays as [Conversion#Figure 2](https://eemodelingsystem.atlassian.net/wiki/spaces/EK/pages/2082766849#Conversion-Figure2). It allows converting length, area, volume, etc from a unit to another unit. Firstly the user selects a unit from the drop-down list for *Convert* (e.g Length), next select from the drop-down list for the *From Unit* (meter(m)), then enter the value want to convert in the *Input* Value, next select the target unit for the *To Unit* (e.g foot (ft)), we can set the number of significant digits by entering a number (e.g 3). Finally, click the *Convert* button, the output value will be shown in the *Output Value.*` (16). 그림 `10-12-2021_4-18-50_PM.png`는 `Convert: Length`, `From Unit: meter (m)`, `Input Value: 100`, `To Unit: foot (ft)`, `Number of significant digits: 3`, `Output Value: 328.084`를 표시한다(18, 그림). 절 제목·빈 줄·마크업을 포함한다(14–19). |
| 20–25 | Coordinate Conversion — 한 점의 좌표계(coordinate system), 입력·출력 투영(projection) 및 단위를 바꾼다(22). 설정과 UTM Zone 의무 조건은 `The feature allows converting from a coordinate system to another coordinate system for a point. The user should select the input projection and unit for the *Convert from Coordinate System*frame first then enter the values in the text box. Next, select the target projection and unit for the *Convert to Coordinate System*frame then click the *Convert* button to take place as shown in [Conversion#Figure 3](https://eemodelingsystem.atlassian.net/wiki/spaces/EK/pages/2082766849#Conversion-Figure3). The *UTM Zone* in the *Convert to Coordinate System*frame must be defined when converting from Longitude, Latitude to UTM zone in meter or foot.` (22). 그림 `10-12-2021_5-05-52_PM.png`는 `NAD83: North American 1983`의 Degree 좌표를 같은 기준의 Meter 좌표로 변환한다(24). 입력은 `Longitude (°): -73.960782`, `Latitude (°): 40.737637`, `Altitude (m): 0`이다. 출력은 `X (m): 587746.19557763`, `Y (m): 4510152.28601953`, `Altitude (m): 0.000`이다. 출력 설정은 `UTM Zone: Zone 18`, `Central Meridian: -75`, `Scale Factor: 0.9996`이며 도분초 좌표는 `73°57'38.82"W`, `40°44'15.49"N`이다(24, 그림). 절 제목·빈 줄·마크업을 포함한다(20–25). |
| 26–31 | Coordinate File Conversion — 좌표 파일의 입력·출력 좌표계와 단위를 바꾸고 변환 완료 메시지를 띄운다(28). 파일 이름·UTM Zone 조건·순서를 그대로 옮긴다: `The feature allows converting a file containing coordinates from a coordinate system to another coordinate system. Firstly selecting the input coordinate system of the file by choosing from the drop-down list in the *Convert from Coordinate System*, then browsing to the file to be converted in the *File Name*. In the *Convert to Coordinate System*frame, the user should select the target coordinate system and UTM zone in case converting the file from degree to meter or foot. Next, browse to the folder where the file saved to, then put a name for the output file. Filnally click the *Convert* button to start converting as shown in [Conversion#Figure 4](https://eemodelingsystem.atlassian.net/wiki/spaces/EK/pages/2082766849#Conversion-Figure4). When it's done, a message will be popped up as shown in [Conversion#Figure 5](https://eemodelingsystem.atlassian.net/wiki/spaces/EK/pages/2082766849#Conversion-Figure5).` (28). 그림 `10-13-2021_11-44-04_AM.png`는 Degree 입력 파일 `D:\Lon_Lat.dat`, Meter 출력 파일 `D:\UTM_Z18.dat`, 출력 `UTM Zone: Zone 18`, `Central Meridian: -75`, `Scale Factor: 0.9996`을 보여 준다(30, 그림). 그림 `10-13-2021_11-52-12_AM.png`는 `D:\UTM_Z18.dat` 변환 성공 알림이다(30). 파일 내용 형식의 예시 줄은 문서에 없다(26–31). 절 제목·빈 줄·두 그림 마크업을 포함한다(26–31). |
| 32–36 | Date Conversion — 기준일(Base Date)과 Gregorian 달력 날짜 사이의 일수를 계산하고 일수로 날짜를 계산한다(34). 음수·양수 조건, 기준일 기본값과 프로젝트에 대한 영향은 `The feature as shown in [Conversion#Figure 6](https://eemodelingsystem.atlassian.net/wiki/spaces/EK/pages/2082766849#Conversion-Figure6) allows the number of days to be calculated from the time of a Base Date to the time of a specified (Gregorian) calendar date. If the calendar date entered is before the Base Date a negative number of Julian days is given. This tool can also be used to determine a Calendar Date, given any number of days before (<0) or after (>0) a given Base Date. The default Base Date is the Project's Base Date. However, the user can change the Base Date in this utility without impacting the Project's Base Date.` (34). 그림 `10-12-2021_5-24-45_PM.png`는 `Julian Date: 100`, `Gregorian Date: 2001-08-09 00:00:00`, `Base Date: 2001-05-01 00:00:00`를 보여 준다(36, 그림). 절 제목·빈 줄·마지막 그림 마크업을 포함한다(32–36). |

## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- 10·16·22·28·34: `#Conversion-Figure1`부터 `#Conversion-Figure6` 링크가 있다. 이 파일에는 대응 앵커와 그림 번호 캡션이 없다.
- 16·18(그림): 본문은 `number of significant digits` 설정을 설명한다. 그림의 해당 값은 `3`이며 출력값은 `328.084`이다.
