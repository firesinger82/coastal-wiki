| 10–26 | NetCDF 개요와 설계 목적 — Network Common Data Form은 자체 기술(self-describing)과 이식 가능한 배열 지향 데이터를 위한 입출력 라이브러리라고 설명한다(10–12). 여러 언어·GIS 프로그램의 접근, 이름·색인 기반 직접 접근, 단위 등의 부가 정보를 설명한다(12). 공동 이용·컴퓨터 간 공유·형식 해석 작업 및 오류 감소·응용 간 입출력·표준 인터페이스의 여섯 목적을 나열한다(14–26). |
| 27–32 | UGRID와 EFDC 출력 — EEMS10.4부터 UGRID를 지원하며 전체 I,J 격자 대신 활성 셀만 출력한다고 설명한다(28). 수평 위상(horizontal topology)은 I,J 대신 EFDC+ 셀 색인에 따른다고 적는다(28). WebGIS 표시 가능성을 설명한다(30). 플랫폼·바이너리 변환·매개변수 수·차원 순서 원문: `EFDC+ can currently write the native output in NetCDF-CF format for Windows and Linux. EFDC+ Explorer (the pre-and post-processor for EFDC+) can also convert the binary files output by EFDC+ (\*.OUT) to [netCDF.nc](http://netCDF.nc) files, including the derived water quality parameters. EFDC+ currently exports 44 parameters to NetCDF format. This allows EFDC+ output to be read and displayed on web servers. It should be noted that while the display order of some dimensions (i.e. TIME, KC, CELL) in *\*.nc* output files exported from EFDC+ Explorer may differ from that obtained directly from EFDC+, the values of variables are not impacted and retrieved correctly with reference to their descriptive data.` (32) |
| 33–40 | NetCDF 출력 설정 — 연계 파일과 같은 출력 간격, Output to NetCDF, 압축 수준과 속도 회전(velocity rotation)을 설명한다(34–38). 매개변수·범위·조건 원문: `EFDC+ exports the NetCDF files at the same interval that it produces the model linkages files, which is set in the tab for *Timing and Linkage \| Linkage \| NetCDF*.` (34) `The main configuration for NetCDF output is in the *EFDC+ Explorer Linkage \| NetCDF* tabs as shown in [Figure 1](#Figure1).  Here the user can turn on netCDF output by checking the *Output to NetCDF* checkbox.  The user may select the level at which the NetCDF data is compressed with the *Deflate Level* setting. This can range from 1, no compression, to 9 for maximum compression, but is recommended by Unidata to be set to 2 for the best balance between file size and speed.` (36) `The user may also select to *Rotate Velocity.* If this option is checked, the velocity field is rotated to true east and true north and if not checked then there is no rotation to true east and true north.` (38) Figure 1 로컬 그림을 직접 열었다(40). `Output to NetCDF`, `Rotate Velocity`, `Lagrangian Particle Tracks`, `Single File` 선택과 `Deflate Level: 2`, `Time / From: 0`, `To: 28`을 보여 준다(40 그림). |
| 41–52 | 출력 항목·파일 생성·Note — 출력 항목 선택과 미활성 퇴적층 옵션의 원문: `Then, the user can select which parameters they want to output from the water column or the sediment bed by checking the box in *Output Parameters* frame. Users can select more detailed components when writing to a NetCDF file. Some options for the sediment bed are not yet enabled and will be added to EE in future releases.` (42) 일별 파일, 간격 권고, LPT(Lagrangian particle tracking) 별도 출력 조건 원문: `In the *File Creation* frame, the user is given the option of EFDC+ generating a *Single File*, or *Multiple Daily Files.*The *Multiple Daily Files* option provides one netCDF file for each day (24 hours) of model output. NetCDF files (.nc files) are placed in the #output folder along with the EFDC output.  The snapshots for the NetCDF files are determined by the setting for the interval for the EE linkage file. The user can change the snapshot interval by changing the EE linkage options. It is recommended that the linkage frequency should be 10 minutes or more for correct display in ArcGIS tools.  After setting these options, the user should save their model and run EFDC+, which will then export the NetCDF .nc files to the #output folder. With release of EEMS11.3, EFDC+ writes the LPT NetCDF output to a separate .nc file. The output frequency for the drifters in NetCDF is based on the LPT output frequency.` (44) 실행창 종료 방식·날짜 기본값·층 순서·단위·셀 색인 주의 원문: `- After running the model, the user must close the EFDC+ run window using the carriage return before viewing the netCDF output. Using the X button on the run window will mean NetCDF output will not be written.` (48) `- The calendar date is the default date in the NetCDF output.` (49) `- Layer ordering in the water column and sediment bed will be reversed in NetCDF compared to that of EE.` (50) `- Units in NetCDF are often different from those in EE, for example, bed toxics in NetCDF are in mg/m2 rather than mg/kg as they are in EE.` (51) `- When extracting results from NetCDF file, users should take care regarding the L cell index. The loop of the cell list in EFDC+ starts from L = 2 (i.e. corresponding to the first active cell), while with tools used to extract data from NetCDF, such as Python or Matlab, start the loop from 0 or 1, respectively.` (52) |

| 86–89 | Using Python script — 수평 셀·층·출력 빈도·기간으로 출력 행 수를 계산하며 NaN 건조 셀 제거와 스크립트 문의를 안내한다(86–88). 수량·계산식 원문: `Python script can be used to read the netCDF output of the model. For example, a model with 1000 horizontal grids, and 5 layers, and the model simulated with 1-hour output frequency for 10 days. So each day will have 25-time steps → there are 1000\*5\*(24\*10 + 1) = 1,205,000 lines totally. In which of the total lines there are lines with NaN values (dry cells), they should be removed. The User can contact us to get the script.` (88) |

## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- 10행: 색상 CSS가 본문 시작에 남아 있다.
- 88행: 본문은 하루 `25-time steps`를 적으며 전체 행 수 식에는 `24\*10 + 1`을 쓴다. 일별 경계 시점의 중복을 처리하는 설명은 이 파일에 없다.
- 92·94행 그림: 본문은 출력이 EE에서 본 데이터와 일치함을 보이기 위한 비교라고 설명한다. EE와 ncWMS 그림의 범례는 `6.2121`–`9.8351`이고 ArcGIS 그림은 `6.22986`–`9.83983`이다.
