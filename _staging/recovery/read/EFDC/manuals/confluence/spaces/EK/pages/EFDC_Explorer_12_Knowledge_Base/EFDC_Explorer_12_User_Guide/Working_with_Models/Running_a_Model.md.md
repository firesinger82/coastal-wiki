| 1–9 | 앞부분 메타데이터. `title: "Running a Model"` (3) 및 페이지 ID, space, URL, 버전, 갱신 시각과 문서 계층을 포함한다(1–9). |
| 10–13 | 모델 실행 시작. 올바르게 설정된 모델은 EE 인터페이스에서 EFDC+ 실행 파일을 호출한다. 그림 10의 녹색 Run Model 아이콘과 그림 12의 도구막대 강조 표시를 확인했다. 실행 중 일시 정지에 관한 원문은 `The EFDC+ model run can longer be paused during a run as was possible with EEMS.` (10)이다. 바로 뒤 문장은 `This feature is no longer required as the user can re-scan the output for display without needing to pause the run.` (10)이다. 두 문장을 그대로 구분하여 기록한다. |
| 14–25 | EFDC+ Run Options와 실행 방식. 실행 전 설정을 검토·갱신하며 변경된 입력 파일은 자동 저장한다(14). OMP, 단일 PC MPI, 클러스터 MPI의 세 가지 실행 방식을 열거한다(18–22). 같은 실행 파일을 사용하며 EEMS10.2의 MPI 기능 및 공통 탭 적용 조건은 `All three options use the same executable file. MPI is a new feature with the release of EEMS10.2. A number of [principles to consider when configuring an MPI run](/wiki/spaces/EK/pages/1095270402/Guiding+Principles+for+Running+MPI) are provided. The user can select the run option from the *EFDC+ Run Options* form as described on the page for each option. The *Model Timing* tab and *Run Time Diagnostics* tab are applied for all three run options and described in detail below.` (24)이다. 그림 16은 General 탭을 보여 준다. 표시된 예시 값은 `Available CPU Cores: 6` (16), `# OMP Cores Used: 1` (16), `KMP Offset: 0` (16), `L: 2722` (16), `I: 34` (16), `J: 66` (16), `Print Interval: 500` (16), `Output Interval (min.): 60` (16)이다. `Write EE_Arrays.out Linkage file (optional)` (16), `Auto-generate Calibration Plots & Statistics` (16), `MPI Domain Decomposition` (16) 선택 상자는 선택되지 않았다. |
| 26–29 | Choosing Options. MPI는 셀(cell)·층(layer) 수가 큰 모델에서, OMP는 이송(transport)이 많은 경우에 잘 확장되는 경향을 서술한다. 작은 수온·염분 모델에서는 추가 코어(core)를 충분히 활용하지 못할 가능성을 명시한다. MPI 프로세스(process) 수와 영역별 OMP 코어 비율에는 보통 실험이 필요하다. 불확실성과 적용 조건을 포함한 원문: `Generally speaking, MPI tends to scale well with model size i.e. high cell and layer count. Conversely, OMP scales better when there is a lot of transport. If, for example, you have a smaller model that is only simulating temperature and salinity, you likely will not be able to take full advantage of extra cores. It typically takes some experimentation to find the ideal ratio of # of MPI processes and OMP cores per domain.` (28) |
| 30–35 | Model Timing tab. 실행 옵션과 Timing 탭에서 시간 설정을 제공하며 상세 Timing 문서를 연결한다(30–32). 그림 34는 시간 설정 화면이다. 화면 값은 `Time of Start (days): 212` (34), `Number of Reference Periods: 6` (34), `Duration of Reference Period (hours): 24` (34), `Time Step (seconds): 60.0000` (34), `Safety Factor: 0` (34), `# Ramp-up Loops: 1000` (34), `Maximum dH/dT: 0` (34), `Growth Step: 2` (34), `Maximum Time Step: 3600` (34)이다. |
| 36–41 | Run Time Diagnostics tab / Run Logging Options. 진단 출력은 선택된 EFDC 옵션에 의존한다. 파일 내용을 결정하려면 소스 코드를 참고해야 한다. 진단 출력은 실행 시간을 늘릴 수 있다. 매개변수·적용 조건을 포함한 원문: `[Figure 4](#Figure4) shows the *Run Logging Options* frame with various check box options to aid error diagnosis. Checking *Enable Diagnostics* causes EFDC to produce many extra output files. The diagnostic files depend on the EFDC options, and the source code needs to be consulted to determine the content of the diagnostic files. The diagnostic files can usually be turned off after initial model testing. Other options include the ability to write out *Negative Depth and Courant* diagnostics. These options may add to the run time of the model.` (38) 그림 40은 진단 설정 창이다. `Negative Depth / Courant` (40)는 선택되어 있고 `Enable Diagnostics`, `Write to the log file`, `Check All Series for Timing` 및 `Compute` (40)는 선택되어 있지 않다. 질량 수지 간격의 화면 값은 `#Steps: 960` (40)이다. |
| 42–43 | Mass Balance Reporting Options. 질량 수지(mass balance) 출력 사이에 누적되는 시간 단계 수를 설정한다. 3개 시간 수준과 2개 시간 수준의 출력 파일을 구분하며 FORTRAN 코드 참조를 의무로 적는다. 원문: `The *Mass Balance Reporting Options* frame enables mass balance checking and reporting for EFDC. The number of steps relates to the number of time steps accumulated between reporting. Consistent with the fixed naming convention, the mass balance file written by EFDC is BAL.OUT for the 3-time level solution and BAL2T.OUT for the 2-time level solution. The user must refer to the FORTRAN code to interpret these outputs.` (42) |
| 44–44 | Data Quality Checking Options. 모든 시계열의 시작·종료 시각을 검사하는 선택 사항과 실제 사용 경계조건 시계열의 항상 수행되는 검사를 구분한다. DEBUG 실행에서는 늦게 시작하거나 일찍 끝나는 시계열로 배열 범위 오류가 발생한다고 설명한다. 적용 조건과 의무를 그대로 옮긴다: `In the *Data Quality Checking Options* frame, the *Check All Series for Timing* frame will run a check on the EFDC input files to ensure that all of the boundary condition time series files start and end times fit within the model run time, even if they are not used by a boundary condition. EFDC+ Explorer ALWAYS checks for boundary condition timing for time series used by the model. However, if the user is running the model in DEBUG model (e.g. VS2010 debug mode), the model will report an out-of-array bounds error for any time series that starts late or ends too soon. This option helps the user either fix the error or delete the series since it is not being used.` (44) |

## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- 일시 정지 설명에 `can longer be paused` (10)라고 적혀 있다. 같은 행의 뒤 문장은 실행을 일시 정지하지 않고 출력을 다시 스캔할 수 있다고 적는다(10). 첫 문구에는 부정어가 표시되어 있지 않다.
