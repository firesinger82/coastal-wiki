# MPI_on_a_Single_Machine.md — 판독 구간 기록

구간은 1행부터 64행까지 빈틈없이 이어진다.

| 구간 | 내용 |
|---|---|
| 1–9 | 앞부분 메타데이터. `title: "MPI on a Single Machine"` (3) 및 페이지 ID, space, URL, 버전, 갱신 시각과 문서 계층을 포함한다(1–9). |
| 10–13 | MPI 실행 개요. 모델을 하위 영역으로 나누고 사용자 지정 코어 수로 각 영역을 계산한다. 최적 영역 배치에는 실험이 필요할 수 있다고 적는다(10). 성능 저하를 피하려는 재시작 파일(restart file) 출력 빈도의 권고를 그대로 옮긴다: `It is recommended that restart files be written as infrequently as reasonably possible to avoid reduced performance as EFDC+ writes out the output files.` (12) |
| 14–23 | MPI 실행을 위한 모델 수정 조건. 수리 구조물(hydraulic structure)의 상·하류 셀, 셀 연결자(cell connector)의 양 끝, 취수·회수(withdrawal/return) 경계의 양 끝 및 유량 재배분 그룹의 모든 셀을 같은 하위 영역에 배치해야 한다. 북·남·동·서에 최소 2개 행·열의 완충 영역(buffer zone)이 필수이며 없으면 실행되더라도 결과가 틀릴 수 있다고 적는다. 조건 원문: `- Hydraulic Structures with a downstream receiving cell.  Both the upstream and the downstream cells must be in the same subdomain` (16) `- Cell Connectors. Both ends of the connectors must be in the same subdomain` (17) `- Withdrawal/Return boundaries. Both the withdrawal and the return must be in the same subdomain` (18) `- Flow Boundary with group redistribution of flows.  All cells in the boundary group must be in the same subdomain` (19) `- Model grids that do not have two columns of extra cells on the North, South, East, and West sides. It is a requirement with the MPI model that there be a buffer zone around the model cells of at least two rows and columns. Without this, the model may run but the results will be incorrect. Check this with the [View Cell Map](/wiki/spaces/EK/pages/246580346/View+Cell+Map) option.` (20) View Cell Map으로 경계와 셀 블록(cell block)을 수동·자동 이동하여 수정할 수 있다(22). |
| 24–29 | 아직 지원하지 않는 MPI 구성. 채널 수정자(channel modifier), 계산 지하수 유량(groundwater flux), Low Chord 교량(bridge) 옵션을 열거한다. 옵션 이름과 매개변수 조건을 그대로 옮긴다: `- Channel Modifiers` (26) `- Computed Groundwater fluxes (ISGWIE > 0)` (27) `- Hydraulic Structures with Low Chord bridge option (NQCTYP = 3 or 4 option)` (28) |
| 30–37 | MPI Domain Decomposition 선택 및 코어 수. 하드웨어에 따른 Available CPU Cores를 표시한다. OMP 코어 수와 하위 영역 수를 설정하며 전체 코어 수는 두 수의 곱이다. 원문: `Once the model cell blocks have been arranged, check the *MPI Domain Decomposition* box as shown in Figure 1. For this option, the model will be run using MPI and the user should set the number of cores to be used as they would with OMP. The total number of cores available (based on the user’s computer hardware) is shown under *Available CPU Cores*.` (30) `Set the *#OMP Cores Used* based on the machine hardware. Enter *Total # Subdomains* to be used. which is the number of subdomains into which you want to divide the overall model domain. In the example shown in Figure 1 below two subdomains have been set. The *Total # Cores Used* will be updated as this is calculated based on *# OMP Cores Used* multiplied by *Total # Subdomains*.` (32) 그림 34의 예시는 `Available CPU Cores: 4` (34), `# OMP Cores Used: 2` (34), `KMP Offset: 0` (34), `Total # Cores Used: 4` (34), `Total # Subdomains: 2` (34), `# Subdomains in I Direction: 2` (34), `60, 52` (34), `# Subdomains in J Direction: 1` (34), `108` (34)이다. Figure 1 캡션을 포함한다(36). |
| 38–45 | 자동·수동 영역 분할. 자동 분할은 하위 영역마다 활성 셀 수를 대략 같게 선택한다고 적는다. 최초 I 방향 하위 영역 수, 1 × 6에서 6 × 1로 변경하는 예시 및 수동 I·J 입력 예시를 원문으로 옮긴다: `EE can automatically divide the model into the subdomains entered using the *Run Automatic Domain Decomposition* button*.*  The number of cells chosen in each subdomain is done such that each subdomain has roughly the same number of active cells.  Selecting this will use an algorithm to divide the whole domain into the number of subdomains as defined above, i.e… six subdomains from 1 x 6 cuts. Initially, EE always assigns *# Subdomains in I direction* to one. The user can modify this number from 1 x 6 to 6 x 1 or some other combination by selecting the up and down arrow next to the text box.` (38) `The user can also set the *# of Subdomains in I Direction* and *# of Subdomains in J Direction* manually by entering the number in the text boxes (eg. 2; 2) as shown in Figure 2.` (40) 그림 42는 `Total # Subdomains: 4` (42), `# Subdomains in I Direction: 2` (42), `# Subdomains in J Direction: 2` (42)와 비어 있는 영역 크기 입력 칸을 강조한다. 화면의 Available CPU Cores는 `6` (42), # OMP Cores Used는 `2` (42), Total # Cores Used는 `8` (42)이다. Figure 2 캡션을 포함한다(44). |
| 46–51 | 모델 행·열 합계와 네 하위 영역의 분할 예시. 원문은 `The number of cells contained in each subdomain is based on the number of rows and grid columns in the model domain. Figure 3 shows an example of a model domain divided into four subdomains, this model domain has 46 rows and 89 columns. For this example, EE requires the total grid rows to add to 46 and total grid columns to add to 89 in this case.  So, the user can divide the 46 rows into 24 + 22, and the 89 columns into 55 + 34.` (46)이다. 산술 표현 `24 + 22` (46)와 `55 + 34` (46)를 그대로 옮긴다. 그림 48은 Grid Rows `46` (48)에서 J 방향 입력 `24, 22` (48)로 향하는 빨간 화살표와 Grid Columns `89` (48)에서 I 방향 입력 `55, 34` (48)로 향하는 파란 화살표를 보여 준다. 그림의 Total # Subdomains는 `4` (48), I·J 방향 하위 영역 수는 각각 `2` (48)이다. Figure 3 캡션을 포함한다(50). |
| 52–64 | 분할 결과 시각화와 실행. Show Cell Map으로 영역 분할을 보고 Run EFDC+로 실행한다(52–54). 그림 56의 격자 지도에는 `Colored By: MPI Sub-domains` (56)와 `Label Step: 2` (56)가 표시된다. 지도는 가로 셀 인덱스 눈금 `2–88` (56), 세로 눈금 `2–46` (56)을 표시한다. 파란 Sub-domain 1은 왼쪽 아래, 청록 Sub-domain 2는 오른쪽 아래, 연두 Sub-domain 3은 왼쪽 위, 빨간 Sub-domain 4는 오른쪽 위의 활성 셀을 표시한다. 분할선은 I 인덱스 55·56 사이 및 J 인덱스 24·25 사이에 있다(56). 그림 60은 실행 버튼을 강조한 General 화면이다. `Total # Subdomains: 4` (60), `# Subdomains in I Direction: 4` (60), `32, 23, 19, 15` (60), `# Subdomains in J Direction: 1` (60), `46` (60)을 표시한다.
