## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- 101–102행: propeller JSON 예시의 마지막 선박 객체 닫기 뒤에 쉼표가 있고 바로 다음 줄에 배열 닫기 `]`가 있다. 67–103행을 표준 JSON으로 해석하면 이 쉼표 때문에 파싱에 실패한다.
- 74·90·118·295행: JSON 필드 이름은 `revolutions_per_min`이다. Fortran `rpm_prop`의 설명 단위는 `Revolutions per second of the Propeller`이다. 이 파일에는 두 단위 사이 변환 설명이 없다.
- 128·245행: gross_tonnage 단위는 `[units, which tons?]`이고 draught 단위는 `[units = feet? meters?]`이다. 문서가 단위를 미정 질문으로 남긴다.
- 159–174·239–245행: 항적 JSON 예시는 `speed`라는 필드를 쓰지만 단위 설명은 `velocity`라는 필드 이름을 쓴다.
- 137·148–233·239–245행: 위치 설명은 x,y,z 좌표를 가진다고 적는다. 항적 JSON 예시와 위치 단위 목록은 x_position·y_position만 제시하고 z 좌표 필드는 제시하지 않는다.
- 243–244·261행: 입력 course·heading 단위는 degrees이다. ship 자료형의 heading_angle 단위는 radians이다. 이 파일에는 그 변환 절차가 없다.
- 309–317행: vel_field 코드 블록은 `type :: vel_field`로 시작하지만 코드 블록 종료 전에 대응하는 end type 문장이 없다.
- 363행: get_current_position 설명은 `Should check that the`에서 문장이 끝난다.
- 375행: 합성 유속 설명의 `(from the normal EFDC+ hydrodynamics.`에는 대응하는 닫는 괄호가 없다.
- 390행: URL의 파일 이름은 `Untitled(1).png`이다. 지정한 이름 변환 규칙의 경로에는 파일이 없다. 첨부 폴더 목록에서 `Untitled1.png`를 찾아 열었으며 이 파일은 선수 방향 도식이다.
