For instance, changing an input file or changing the output.` (36); `**Z** minor changes and features that will not require any changes to EE. This could be speed ups in run time, addition of a subroutine to clean up some code, fixing a specific bug.` (38); `We will begin each **Y**,**Z** starting at 0. For example, if we just made a big change from **10.1.5** and need to sync up with EE we should not be at **10.2.0**` (40); `The big take away here is that every time we make a big change and we need to sync up with EE we should increment the **Y** value and correspond with the EE developers. At that point EE should make the necessary changes and increment their **Y** value. Note, the **X** values do not have and should not correspond exactly between EE and EFDC+. I think this will allow for flexibility in development style while still managing to keep the synchronization better.` (42). |

## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- 138행: 명령 문자열은 `git commit —amend`이다. 옵션 앞 문자는 두 개의 하이픈이 아닌 긴 대시 `—`이다.
