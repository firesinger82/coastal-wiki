(The ''analytical.F'' subroutine in previous versions has been re-structured to do this).  ` (20). |

| 42–53 | Directory hierarchy — 상대경로(relative paths)의 기준 디렉터리 구조를 옮긴다(42–50). 기본 varinfo.dat 사용과 수반(adjoint)·4DVAR 연구의 별도 하위 디렉터리, 구조 변경 시 경로 수정 조건이다(47·52). 원문: ` * cblast/ ` (44); ` ** Data/ ` (45); ` *** all initial, surface forcing, tides, and other open boundary data ` (46); ` *** the [[varinfo.dat]] file that matches model input/output variable names to corresponding netcdf data variables. You can change this organizational structure for files to suit your own requirements - just make the necessary changes in ''roms_cblast.in'' so that ROMS finds the files.   ` (52). |
| 54–71 | build_cblast.sh — 작업 중인 csh 빌드 스크립트가 환경변수(environment variables)로 makefile 기본값을 덮어쓰는 구문을 설명한다(56–58). 사용·미사용 변수 이름, 값·조건·컴파일 예시를 모두 보존한다(62–69). 원문: ` ''This script is a work in progress. We have already resolved some issues to do with the control of make depend. For now, the script provided here works but will be updated to use new features in the makefile as they evolve and are tested.'' ` (56); ` This ''csh'' shell script serves to illustrate how a specific application can be configured without editing the [[makefile]] by using UNIX shell environment variables to over-ride the [[makefile]] defaults. If in the [[makefile]] a flag is set with the syntax '''VARIABLE ?= value''' this indicates its default value, but if '''VARIABLE''' is set in the shell that calls the script then the job inherits that value and over-rides the default. Of course, you can also choose to edit that line in the [[makefile]] itself and operate in that way. Just remember you did this.  ` (58); ` * '''ROMS_APPLICATION''' is '''CBLAST''' which tells ''make'' to look for CPP definitions in a file called ''cblast.h''. See [[makefile]] for more information. The value of '''ROMS_APPLICATION''' must match the parameter '''MyAppCPP''' in [[roms.in]] ` (62); ` * '''MY_HEADER_DIR ''' tells ''make'' where to look for the ''cblast.h'' CPP defs file. ` (63); ` * '''MY_ANALYTICAL_DIR''' sets where '''ana_*.F''' files would be located. The CBLAST example here does not require any such files, but this line is left for information.  ` (64); ` * '''BINDIR''': Sets where te executable should be placed following sucessful compilation. ` (65); ` ** Not used in this example: ` (66); ` *** '''BUILD_DIR''' would set the path to a temporary ''Build'' subdirectory is created to hold '''*.f90''' and '''*.o''' files.  ` (67); ` *** '''setenv MPI on''' would activiate compilation for parallel execution.  ` (68); ` *** If your FORTRAN compiler is not the default in makefile, you could set it here with '''setenv FORT myF90compilername'''. ` (69). |
