| 65–93 | Conflicts — 서버·로컬 변경의 중첩으로 생기는 충돌, 갱신 선택지·표식·임시 파일 세 종류와 생성 조건을 설명한다(65–75). 개정 280에서 291로의 충돌과 새 선택 메뉴 예제를 제시한다(77–85). 수동 병합·임시 파일 복사·되돌리기의 세 해결 방법과 resolved 처리 동작을 설명한다(87–92). 원문: `:*Subversion halts during the update, offering you several choices, and remembers that the file is in a state of conflict if you don't clear it right then.` (70); `:*If Subversion considers the file to be mergeable, it places conflict markers (special strings of text which delimit the “sides” of the conflict, usually "<" and ">" characters) into the file to visibly demonstrate the overlapping areas.` (71); `:*For every conflicted file, Subversion places three extra unversioned (not under Subversion control) files in your working copy:` (72); `::*'''filename.mine:''' This is your file as it existed in your working copy (local copy) before you updated your working copy. (If Subversion considers the file to be unmergeable, then the .mine file isn't created, since it would be identical to the working file.)` (73); `::*'''filename.rOLDREV:''' This is the file that was the '''BASE''' revision before you updated your working copy. That is, the file that you checked out before you made your latest edits.` (74); `::*'''filename.rNEWREV:''' This is the file that your Subversion client just received from the server when you updated your working copy.
