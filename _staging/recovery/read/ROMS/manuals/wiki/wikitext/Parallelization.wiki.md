| 1–22 | ROMS tiling — 병렬 타일(tile) 그림 참조와 수평 영역 분할(domain decomposition)을 소개한다(1–6). 컴파일 시 직렬(serial)·OpenMP·MPI를 선택한다(6). 설계 목표와 MPI/OpenMP 식별 플래그를 제시한다(7–16). 전체 격자와 내부 셀의 두 방향 번호를 설명하며, 임의 크기로 병렬 실행할 수 있어도 부하가 균등하지 않을 수 있다고 적는다(18–21). 원문: `ROMS supports serial, OpenMP, and MPI computations, with the user choosing between them at compile time. The serial code can also take  advantage of multiple small tiles which can be sized to fit in cache. All are accomplished through domain decomposition in the horizontal. All of the horizontal operations are explicit with a relatively small footprint, so the tiling is a logical choice. Some goals in the parallel design of ROMS were:` (6); `* Minimize code changes.` (7); `* Don't hard-code the number of processes.` (8); `* MPI and OpenMP share the same basic structure.` (9); `* Don't break the serial optimizations.` (10); `* Same result as serial code for any number of processes.` (11); `* Portability - able to run on any (Unix) system.` (12); `First, some [[C Preprocessor]] options. If we're compiling for MPI, the option '''-DMPI''' gets added to the argument list for '''cpp'''. Then, in [[globaldefs.h]], we have:` (14); `<div class="box">     #if defined MPI<br />     # define DISTRIBUTE<br />     #endif</div>` (15); `The rest of the code uses '''DISTRIBUTE''' to identify distributed memory jobs. The OpenMP case is more straightforward, with '''-D_OPENMP''' getting passed to '''cpp''' and '''_OPENMP''' being the tag to check within ROMS.` (16); `The computations are done over the cells inside the darker line; the cells are numbered 1 to '''Lm''' in the <math>\xi</math>-direction and 1 to '''Mm''' in the <math>\eta</math>-direction. Those looking ahead to running in parallel would be wise to include factors of two in their choice of '''Lm''' and '''Mm'''. ROMS will run in parallel with any values of '''Lm''' and '''Mm''', but the computations might not be load-balanced.` (21). 수식·기호 원문: `\xi` (21). 수식·기호 원문: `\eta` (21). 그림 참조: `[[Image:parallel_tile_map.png\|center\|frame\|<center>Parallel Tile Partitions</center>]]` (2). 그림 파일 없음. 그림 참조: `[[Image:Whole_grid.png\|center\|frame\|<center>Whole grid</center>]]` (19). 그림 파일 없음. |
| 23–43 | ROMS internal numbers — 유령점(ghost point)/halo와 알고리즘에 따른 폭을 설명한다(23–27). 타일 수와 MPI 프로세스·OpenMP 스레드 조건을 제시한다(29). 타일 크기·여백식을 제시하고, 디버깅을 위해 전역 격자 번호를 유지하며 주기성(periodicity)에 따라 시작·종료 인덱스가 달라진다고 설명한다(31–40). 원문: `A domain with tiles is shown above, one color per tile. The overlap areas are known as ghost points or halo points. Each tile is an MPI process, an OpenMP thread, or a discrete unit of computation in a serial run. The tile contains enough information to time-step all the interior points, so the number of ghost points is dictated by the footprint of the algorithm using the largest number of neighbor points. In ROMS, the halo area would be two grids points wide unless the MPDATA advection scheme is used, in which case it needs three. The variable '''GHOST_POINTS''' is set accordingly:` (26); `<div class="box">    #if defined TS_MPDATA \|\| defined UV_VIS4<br>    # define GHOST_POINTS 3<br>    # if defined DISTRIBUTE \|\| defined EW_PERIODIC \|\| defined NS_PERIODIC<br>    #   define THREE_GHOST<br>    # endif<br>    #else<br>    # define GHOST_POINTS 2<br>    #endif</div>` (27); `The number of tiles is set in the input file as '''NtileI''' and '''NtileJ'''. For an MPI job, the product of the two must equal the number of MPI processes. For an OpenMP job, the number of threads must be a multiple of the number of tiles. For instance, for '''NtileI'''=4 and '''NtileJ'''=6, you must have 24 MPI processes while 2, 3, 4, 6, 8, 12 and 24 are all valid numbers of OpenMP threads. Also, a serial run could have 24 tiles and would just compute them sequentially.` (29); `<div class="box">     ChunkSizeI = (Lm+NtileI-1)/NtileI<br>     ChunkSizeJ = (Mm+NtileJ-1)/NtileJ<br>     MarginI = (NtileI*ChunkSizeI-Lm)/2<br>     MarginJ = (NtileJ*ChunkSizeJ-Mm)/2</div>` (32); `The internal ROMS numbers shown above are in the '''BOUNDS'''  structure in [[mod_param.F]]. '''MarginI''' and '''MarginJ''' are zero if the numbers work out perfectly, i.e. '''Lm/NtileI''' and '''Mm/NtileJ''' are integers. The tile numbers match the MPI process numbers.` (33); `Each tile can be numbered from 1 to '''ChunksizeI''' or it can retain the numbering it would have in the whole grid. We have chosen this second option for ease when debugging features such as river inputs which apply to specific locations on the grid. It is simple to do using Fortran 90 dynamic memory allocation.` (38); `With the tile sizes known, we can assign beginning and ending indices for each tile. Some of the details depend on whether or not the domain is periodic in that direction, as shown here:` (40). 그림 참조: `[[Image:Tile3.png\|center\|frame\|<center>Tiled grid with some internal ROMS parameters.</center>]]` (24). 그림 파일 없음. 그림 참조: `[[Image:Index_numbering.png\|center\|frame\|<center>Index numbering choices.</center>]]` (36). 그림 파일 없음. 그림 참조: `[[Image:Istr.png\|center\|frame\|<center>Index numbers for periodic and non-periodic domains.</center>]]` (41). 그림 파일 없음. |
| 44–50 | MPI exchange — 최대 네 배열의 halo 갱신과 이웃 타일 검색을 설명한다(44–46). 동서 교환 후 남북 교환을 하여 대각 교환을 피한다고 적는다(47). 갱신 전후 그림을 참조한다(48–49). 원문: `For MPI jobs, the ghost points need to be updated between interior point computations. The routines [[mp_exchange2d]], [[mp_exchange3d]] and [[mp_exchange4d]] can be used to update the halo points of up to four arrays at a time. The '''mp_exchangexd''' routines then call:` (45); `<div class="box">    mpi_irecv<br>    mpi_send<br>    mpi_wait</div>` (46); `The exchanges happen first in the east-west direction, then in the north-south direction, saving the need for diagonal exchanges.
