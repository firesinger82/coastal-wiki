| 1–13 | ROMS I/O — NetCDF·PIO·NetCDF4/HDF5를 통한 입출력(input/output)을 소개한다(1–3). 단일 파일 단일 writer·다중 writer·집합 writer(collective writer)·다중 파일 다중 writer의 네 전략과 기본값·활성 옵션·미구현 상태를 옮긴다(5–10). 원문: `#<span class="blue">Single file, single writer:</span> '''Serial I/O''' in non-parallel or parallel applications. It is the default strategy in ROMS using the '''NetCDF3''' or '''NetCDF4''' libraries. ` (7); `#<span class="blue">Single file, multiple writers:</span> '''Parallel I/O''' with each partition tile writing its data to a single file. In ROMS, this capability is achieved by activating [[Options#PARALLEL_IO\|PARALLEL_IO]] and [[Options#HDF5\|HDF5]]. It is only possible with the '''NetCDF4/HDF5''' libraries. ` (8); `#<span class="blue">Single file, collective writers:</span> '''Parallel I/O''' with either one or a subset of processes performing I/O operations. The I/O operations can be '''synchronous''' or '''asynchronous'''. In ROMS, this capability uses the '''PIO''' library and is available when [[Options#PIO_LIB\|PIO_LIB]] is activated. ` (9); `#<span class="blue">Multiple files, multiple writers:</span> '''Parallel I/O''' in which each distributed-memory or shared-memory tile decomposition writes its data into the partition file. Still, post-processing is required to pack the data into a single file. Currently, this capability is not available in ROMS but can be easily implemented within its current I/O infrastructure. However, this strategy is cumbersome and undesired in variational data assimilation (4D-Var) algorithms that require reading forwards and backward, in time, the state trajectories. As a consequence, reading becomes the bottleneck.` (10). |
| 14–19 | Serial I/O / Parallel I/O with NetCDF-4 — 직렬에서는 master 프로세스가 자료를 모아 기록하고 읽어 배분한다고 설명한다(14–15). 파일 형식·압축·병렬 HDF5/NetCDF 활성 조건 및 모든 타일의 읽기/쓰기로 인한 확장성 한계를 설명한다(17–18). 원문: `Serial I/O is the standard option that has been in ROMS since the beginning. In this setup, all input and output data flows through the master parallel process. All data for output is collected from all processes by the master process and written to disk. Likewise, all data for input is read by the master process and distributed to the rest of the processes. When using serial I/O, files can be written in NetCDF classic/64-bit offset (NetCDF-3) or NetCDF-4/HDF5 ([[Options#HDF5\|HDF5]] CPP option) formats. File compression is available in the NetCDF-4/HDF5 library.` (15); `Parallel I/O using parallel HDF5 and NetCDF-4 has been available in ROMS for many years. This I/O option requires parallel enabled HDF5 and NetCDF-4 and is activated by defining [[Options#PARALLEL_IO\|PARALLEL_IO]] and [[Options#HDF5\|HDF5]] CPP options. Each parallel tile reads and writes the decomposed data. This approach does not scale well because it requires every process to participate in reading and writing, which quickly overloads the file system with requests as the number of tiles (NtileI x NtileJ) increases.` (18). |
| 20–33 | Parallel I/O with PIO — 분산 메모리 MPI와 병렬 파일 시스템에서 PIO_LIB을 링크해야 하며 MPI-IO 때문에 분산 메모리에만 제공된다고 적는다(20–22). 동기/비동기 프로세스·통신 구성과 비동기 모드의 개발 중·사용 비권고 상태를 옮긴다(24–29). roms.in의 PIO 설정 포함 지시문이 있다(31–32). 원문: `The '''PIO''' library is primarily intended for ROMS '''distributed-memory (MPI) applications''' running on a large number of processes in an HPC system with a Parallel File System (like Lustre, GPFS, and so on) for high-performance I/O. The '''PIO''' library uses the '''MPI-IO''' interface to facilitate the partitioning of the data across computational or dedicated I/O processes. For example, in an HPC cluster environment with a '''Parallel File System''', the user can instruct '''PIO''' to designate which processes per node to perform I/O. This is a much more reasonable approach for larger applications running on hundreds of processors. To use this Parallel I/O strategy, the '''PIO''' library must be linked to ROMS at compile time by defining the [[Options#PIO_LIB\|PIO_LIB]] CPP option. <span class="blue">It is only available in distributed-memory applications since it uses '''MPI-IO'''</span>.` (22); `<li>'''Synchronous:''' MPI intra-communications mode. A subset or all processes does I/O and also computations. The user specifies the total number of I/O tasks and how they are distributed across the HPC nodes as a function of the ROMS MPI-communicator object, '''OCN_COMM_WORLD'''. It is often desirable to shift the first I/O task away from the first computation task since it has higher memory requirements than other processes. If the MPI processes are spread over several computer nodes, it is highly recommended to spread all I/O tasks over all nodes. Avoid all I/O processes occupying the same node.</li>` (27); `<li>'''Asynchronous:''' MPI inter-communications mode. The I/O tasks are a disjointed set of dedicated I/O processes and do not perform computations. It is possible to have groups of computational units running separate models (coupling) where all the I/O data are sent to dedicated processes. In ROMS, the asynchronous mode is possible by activating [[Options#ASYNCHRONOUS_PIO\|ASYNCHRONOUS_PIO]]. '''<span class="red">However</span>, this capability is still under development and not recommended for use at this time.'''</li>` (28); `{{#lst:roms.in\|PIO}}` (32). |

| 48–55 | Output Multi-Files / 배수·재시작 조건 — MOD 나머지가 항상 0이어야 하는 식을 제시한다(48–51). 첫 이력 파일 5개 이후 4개, 첫 quicksave 파일 9개 이후 8개, 평균·진단 일별 한 기록의 본문 수량을 보존한다(51). 재시작 때 NTIMES/DSTART 변경 금지, iic 재설정 설명·추가 MOD 식·평균/진단/재시작 일치 조건을 옮긴다(53–55). 원문: `Notice that all the parameters are an exact integer multiple from each other:` (48); `<div class="box">     MOD([[Variables#ntimes\|NTIMES]], [[Variables#ndefHIS\|NDEFHIS]]) = 0 <br />     MOD([[Variables#ntimes\|NTIMES]], [[Variables#ndefHIS\|NDEFQCK]]) = 0 <br />     MOD([[Variables#ntimes\|NTIMES]], [[Variables#ndefAVG\|NDEFAVG]]) = 0 <br />     MOD([[Variables#ntimes\|NTIMES]], [[Variables#ndefDIA\|NDEFDIA]]) = 0 <br /><br />     MOD([[Variables#ntimes\|NTIMES]], [[Variables#nRST\|NRST]]) = 0 <br /><br />     MOD([[Variables#ndefHIS\|NDEFHIS]], [[Variables#nHIS\|NHIS]]) = 0 <br />     MOD([[Variables#ndefQCK\|NDEFQCK]], [[Variables#nQCK\|NQCK]]) = 0 <br />     MOD([[Variables#ndefAVH\|NDEFAVG]], [[Variables#nAVG\|NAVG]]) = 0 <br />     MOD([[Variables#ndefDIA\|NDEFDIA]], [[Variables#nHIS\|NDIA]]) = 0 <br /></div>` (49); `where the Fortran intrinsic function '''MOD(<span class="red">X</span>,<span class="red">Y</span>)''' computes the remainder of the division of <span class="red">X</span> by <span class="red">Y</span>, and has to be always '''zero''' for ROMS multi-file option to work. Notice that the first files in the <span class="twilightBlue">history</span> data series (<span class="violet">roms_his_0001.nc</span>) will contain '''5'''-time records because of the initial conditions, and the rest of the files will have '''4'''-time records. Similarly, the first file in the <span class="twilightBlue">quicksave</span> series (<span class="violet">roms_qck_0001.nc</span>) will contain '''9'''-time records, and the rest will have '''8'''-time records. The time-averaged data in the <span class="twilightBlue">averages</span> and <span class="twilightBlue">diagnostic</span> files are single records files representing daily averaged fields. The above analysis also holds when converted to time in seconds since every parameter is multiplied by the [[Variables#dt\|DT]] timestep.` (51); `<span class="red">WARNING:</span> If running your application in a supercomputer with limited-time job queues, long simulations will require a restart. You '''cannot''' change the values of [[Variables#ntimes\|NTIMES]] or [[Variables#dstart\|DSTART]] because the multi-file will fail. If [[Variables#dstart\|DSTART]] is changed, it will reset the timestep internal counter <span class="red">iic(ng)</span>, and we are in deep trouble! Notice that the value [[Variables#nRST\|NRST]] is crucial for the restart of ROMS with multi-file. In addition, we need the following mathematical equalities:` (53); `<div class="box">     MOD([[Variables#nRST\|NRST]], [[Variables#nHIS\|NHIS]]) = 0<br />     MOD([[Variables#nRST\|NRST]], [[Variables#nQCK\|NQCK]]) = 0<br />     MOD([[Variables#nRST\|NRST]], [[Variables#nAVG\|NAVG]]) = 0<br />     MOD([[Variables#nRST\|NRST]], [[Variables#nDIA\|NDIA]]) = 0<br /></div>` (54); `Also, it will be trivial to restart if [[Variables#nAVG\|NAVG]] = [[Variables#nDIA\|NDIA]] = [[Variables#nRST\|NRST]] because of the accumulation sums when computing time-averaging fields. If balancing terms and budgets from output data, you will need [[Variables#nAVG\|NAVG]] = [[Variables#nDIA\|NDIA]] too.` (55). |

## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- 32행: roms.in의 PIO 포함 대상 본문은 이 파일에 없다.
- 44·51행: NDEFQCK 주석은 `daily, single record files`를 포함하지만 51행은 첫 quicksave 파일 9기록·나머지 8기록이라고 적는다.
- 49행: 표시 NDEFQCK의 참조는 `Variables#ndefHIS`, 표시 NDEFAVG의 참조는 `Variables#ndefAVH`, 표시 NDIA의 참조는 `Variables#nHIS`이다.
