## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 64 및 236: which_MPI를 openmpi로 두 번 export한다. 다른 MPI 구현 선택은 231–235행의 주석이다.
- 77·209–217: MY_CPP_FLAGS를 먼저 빈 값으로 export한다. PIO 옵션이 있을 때 뒤에서 -DPIO_LIB를 추가한다. AVERAGES·DEBUGGING 추가 예는 주석이다.
- 95–101: -j 인수 검사의 정규식은 숫자 1개 이상만 확인한다. 이 블록에는 CPU 수가 1 이상인지 검사하는 추가 조건이 없다.
- 104–110: -p 분기는 debug="print-$1"을 만든 뒤 shift한다. 매크로 인수가 비어 있는지 검사하는 조건은 이 분기에 없다.
- 229·238 및 324–328: USE_MPI는 on으로 export한다. USE_OpenMP 대입은 주석이고 기존 값을 지우는 명령은 없다. 이후 두 변수가 모두 비어 있지 않으면 exit 1한다.
- 245–247 및 333–347: -g 설정이 있을 때만 USE_DEBUG=on을 export한다. 이 파일에는 -g가 없을 때 USE_DEBUG를 비우는 명령이 없다. 빌드 디렉터리 선택은 g_flags 대신 USE_DEBUG의 비어 있지 않은 값을 검사한다.
- 287 및 298–300: source 호출은 esm_libs.sh와 my_build_paths.sh 경로를 각각 읽을 파일과 첫 인수로 두 번 적는다. 포함 스크립트 내부는 확인하지 않았다.
- 71·366–395: branch 기본값은 0이다. branch=1일 때만 git checkout $branch_name을 실행한다. 기본 else 분기는 MY_ROMS_SRC로 이동하며 develop 브랜치 checkout 명령은 없다.
- 379–380·394·407·413·419·421 및 424–446: cd·git checkout·make 명령의 종료 상태를 바로 검사하는 조건은 이 파일에 없다. 이 파일에는 set -e 또는 pipefail 설정도 없다. 일반 컴파일 make 뒤에는 헤더명 계산과 보고 출력이 이어진다. 스크립트 실행 결과는 확인하지 않았다.
