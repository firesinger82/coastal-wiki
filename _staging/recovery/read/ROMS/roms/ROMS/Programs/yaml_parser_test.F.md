## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 1·67·71·366: 실제 모듈 이름은 yaml_parser이다. 사용 예시 주석은 yaml_parser_mod를 USE한다. 사용 예시 주석은 yaml_initialize를 CALL하지만 실제 선언은 FUNCTION이다.
- 150·220·633–636: yaml_tree%list와 yaml_Svec%vector 포인터 선언에는 NULL 초기화가 없다. yaml_tree_destroy는 list를 DEALLOCATE하지만 NULLIFY하는 문장은 없다.
- 144·534–537·1135: self%indent 선언에는 기본값이 없다. yaml_tree_create는 첫 Nblanks>0 행에서만 self%indent를 설정한다. yaml_tree_fill은 모든 유효 행에서 Nblanks/self%indent를 계산한다. 들여쓴 행이 없는 파일에 대한 별도 indent 대입은 이 파일에 없다.
- 773·778–780·1848–1851·1930–1933·2007–2010·2099–2102: 추출 및 구조 getter는 status=NoErr 이후 yaml_Error가 참이면 바로 RETURN하는 문장을 갖는다. 해당 조건의 RETURN 앞에는 반환 status를 오류 값으로 바꾸는 대입이 없다. yaml_Error 자체도 yaml_ErrFlag에 대입하지 않는다(1756–1803).
- 820–849·868–886·1371–1382: yaml_tree_extract와 yaml_tree_has의 복합 키 검사는 목록을 순서대로 훑으며 키 일치를 찾는다. yaml_tree_extract는 parent_id를 블록 여부 조회에 사용한다(830–831). 이 복합 키 검사에는 이전 키의 id와 다음 키의 parent_id를 비교하는 조건이 없다.
- 981–1009: 비블록 시퀀스 분기는 S(nvalues)를 할당한다. has_vector 대입은 S(i)에 한 번만 한다(986). 뒤 j 루프는 각 S(j)%value를 채우지만 각 S(j)%has_vector를 설정하는 문장은 없다.
- 1135–1147: yaml_tree_fill은 들여쓰기 수준이 직전 pair보다 커질 때만 new_parent와 old_parent를 바꾼다. 수준이 줄어들 때 이전 부모를 찾는 별도 분기는 이 블록에 없다.
- 1212·1221–1222·1231–1275: Nalias는 입력으로 선언되지만 이후 실행문에서 참조되지 않는다. AnchorKey와 AnchorVal은 둘 다 길이 Lkey=254이다. AliasVal은 길이 Lmax=2048이다(348–349).
- 1497–1503·1613–1619: 첫 '#' 뒤의 문자열은 주석으로 제거한다. 이 처리 조건에는 따옴표 안인지 검사하는 조건이 없다.
- 1566–1569: Ispace는 value(Ianchor+1:) 부분 문자열에서 INDEX로 얻는다. 다음 anchor 추출과 value 치환은 Ispace를 value 전체의 상한 인덱스로 사용한다. 이 블록에는 Ispace에 Ianchor를 더하거나 Ispace=0을 따로 처리하는 문장이 없다.
- 1480·1598·1649–1650: 두 READ의 ERR=10은 status=-1 대입으로 이동한다. 바로 다음 실행문은 표지 20의 status=0 대입이다. 그 사이에 RETURN이나 GOTO가 없다.
- 1862–1876·1944–1954·2021–2045: 정수·논리 구조 getter는 has_vector 참 분기에서만 출력 벡터를 할당한다. 실수 구조 getter의 has_vector 불성립 분기는 V(n)%vector(i)에 READ한다(2035–2037). 이 불성립 분기에는 vector 할당이나 i 대입이 없다.
- 1948–1952·2353–2357·2430–2434·2951–2955: 논리 getter는 값의 첫 문자를 대문자로 바꾼 뒤 T인지 검사한다. T가 아닌 경우에는 .FALSE.를 대입한다. 값 종류 판별은 true/false/TRUE/FALSE 네 문자열을 따로 비교한다.
- 2525–2526·2647–2648·2718–2719·3715–3716: 실수 스칼라 getter의 변환 오류 FORMAT은 integer라고 적는다. 문자열 스칼라·벡터 getter의 MyFile은 각각 yaml_Get_lvar_0d와 yaml_Get_lvar_1d를 적는다. 테스트 프로그램의 MyFile은 read_yaml을 적지만 이후 프로그램 실행문에서 사용하지 않는다.
- 2916–2923: precision 설명 주석은 D=68과 d=100을 적는다. 실제 precision 조건은 69와 101을 검사한다. exponent 조건도 69와 101을 검사한다.
- 2936–2939: 영문 소문자에 관한 설명 주석 아래의 letter 조건은 97 또는 122와의 동등 비교이다. 대문자는 65..90 범위를 검사한다. 소문자 98..121에 대한 범위 비교는 이 조건에 없다.
- 2894·2928·2944–2955: multiple은 0으로 초기화하고 Lswitch(4)가 참일 때 문자 루프마다 증가한다. multiple은 이후 종류 선택 조건에서 사용되지 않는다. 숫자 종류 선택 조건에는 letter 카운터를 배제하는 조건이 없다.
- 3114–3119·3124–3129: add_offset을 읽기 전에 Yreal1 미할당 조건을 검사한다. scale을 Yreal2에 읽은 뒤 다시 Yreal1 미할당 조건을 검사한다.
- 3147–3200·3388–3441: 두 결합 메타데이터 루틴은 Nentries를 standard_name 결과 크기로 정한 뒤 다른 Ystring 배열을 같은 i로 접근한다(3072·3317). data_variables는 vector(1)과 vector(2)를 직접 접근한다(3159–3167·3400–3408). 이 복사 블록에는 각 문자열 배열 크기나 vector 길이를 검사하는 조건이 없다.
- 3270–3302·3388–3441: coupling_metadata의 지역 정수 선언은 i만 적는다(3299). 문자열 할당 호출은 LenStr를 사용한다. 이 루틴에는 LenStr의 명시적 선언과 implicit none 선언이 없다.
- 3405–3408: yaml_AssignString의 계속 줄 중 3407행은 끝에 &가 없다. 다음 3408행의 여섯 번째 열에는 계속 줄 표시 &가 있다. 전처리·컴파일 결과는 이 판독에서 확인하지 않았다.
- 96–104·345–351·3713·3720–3730: 실수 종류 요청은 (12,300), 최대 키·행 길이는 254·2048, 읽기 단위는 222로 고정한다. 테스트 입력 파일 이름의 길이는 120이다. 테스트 프로그램은 무한 입력 루프를 사용하며 READ에는 ERR=20만 있고 END 지정은 없다.
