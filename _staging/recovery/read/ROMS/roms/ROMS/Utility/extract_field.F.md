## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 161–169·238–246: extract_boundary2d와 extract_boundary3d의 Extract_Flag.eq.1 분기는 실행문 없이 닫힌다.
- 229–249·152–155: extract_boundary3d는 MyFile을 선언하지만 SourceFile 대입이 없다. extract_boundary2d는 SourceFile=MyFile을 실행한다.
- 710–723·743–745: average_boundary3d는 IJKlen=IorJ*Klen을 계산한다. 기록 오프셋 rc는 두 case 모두 (ir-1)*IorJ*4이고 경계 오프셋 bc는 (ib-1)*IJKlen+rc이다.
- 588–631·709–760·818–853·913–958: 네 평균 루틴은 Extract_Flag>=2의 U·V case 안에서만 출력 Bavg/Favg를 채운다. 다른 gtype용 CASE DEFAULT는 이 네 선택문에 없다.
- 1044–1050·1068–1074·1092–1098: decimate_boundary2d의 RHO·U·V case는 기록·경계마다 rc와 bc를 계산하지만 Bwrk 접근은 Bwrk(ij)이다. 이 세 접근식에는 rc·bc가 포함되지 않는다.
- 1216–1232·1238–1259·1265–1286: decimate_boundary3d의 RHO·U·V case는 Bdat=0.0_r8 이후 Bwrk(ic)=Bdat(ij)를 실행한다(1226·1253·1280). 이 루틴에는 처리 결과 Bwrk를 Bdat로 되돌리는 대입이 없다. 기록·경계·수직 루프의 Bdat 접근식은 ij만 사용한다.
- 1959–1961: decimate_field4d의 CASE DEFAULT WRITE 인수 순서는 TRIM(Vname(1,ifield)), gtype이다. FORMAT의 변환 지정 순서는 i0와 a이다.
- 1387–1483·1579–1721·1825–1965: decimate_field2d/3d/4d는 SELECT CASE (gtype)을 사용한다. 출력 start/total 설정에는 gtype.gt.0 분기와 MASKING에서의 ELSE가 별도로 있다(1487–1501·1725–1741·1969–1987).
- 2308–2322·2325–2339: interp_coords의 DISTRIBUTE 분기는 Xi를 Xinp로 수집하는 mp_gather2d 호출을 두 번 적고 Yi를 Yinp로 수집하는 호출도 두 번 적는다.
- 2110–2241: interp_coords의 gtype 선택은 PSI·RHO/W·U·V case로 구성된다. 이 선택문에 CASE DEFAULT는 없다.
