## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 3–9·31: 머리말 입력 설명은 fname을 나열한다. get_ngfldr의 실제 인수 목록에는 fname이 없다.
- 64·100–104·177·220·477·520: update는 intent(out)이다. wrapper 기본 분기에는 update 대입이 없다. 두 구현의 최초 FoundError 반환은 update=.FALSE.보다 앞에 있다.
- 257–262·266·302·347·557–562·566–567·603·648: 저장 인덱스와 출력 로그의 단일 칸 선택은 UBk.eq.1을 사용한다. 시간 판독과 2차원 데이터 판독 선택은 recordless를 사용한다.
- 266–277·347–353·566–578·648–654: Tval 대입은 recordless와 시간 ID 조건 안에 있다. UBk가 1이 아닌 로그 분기는 해당 조건 밖에서 Tval을 사용한다.
- 294–324·331–344·595–625·632–645: 차원 분기는 nvdim=1/2/3만 포함하며 최종 ELSE가 없다. Awrk 적재와 CHECKSUM 호출은 차원 분기 뒤에 있다.
- 329–344·630–645: Fmin/Fmax·Fout은 Fscale을 곱한 값을 사용한다. get_hash는 배율 적용 전 Awrk를 입력으로 받는다.
- 152–162·230·450–460·530: Vtype은 Iinfo 값 대입 이후 참조되지 않는다. status·Tend·Tstr는 두 구현의 선언 이후 사용되지 않는다.
