## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 1336–1345·4746–4755: SOLVE3D가 없는 두 루틴의 SOsdev_ubar와 SOsdev_vbar 출력은 모두 `SO_sdev(isUbar,ng)` (1338·1343·4748·4753)를 값으로 넘긴다.
- 944–947·953–956·1134–1137·4344–4347·4353–4356·4540–4543: NpostI·Nimpact·Nbico 출력 호출 바로 뒤에는 FoundError 검사 문장이 없다. 같은 절의 다른 출력 호출 뒤에는 FoundError RETURN 문장이 있다(939·961·1142·4339·4361·4548).
- 4439–4443·1039–1044: PIO의 HdecayY 출력 호출 바로 뒤에는 FoundError 검사 문장이 없다. 표준 NetCDF의 HdecayY 호출 뒤에는 `IF (FoundError(exit_flag, NoError, __LINE__, MyFile)) RETURN` (1043)이 있다.
- 3094–3149·3151–3206·3208–3263: 표준 NetCDF의 Rscope·Uscope·Vscope 블록은 각각 3120·3177·3234행 END IF 뒤에 GRID_EXTRACT의 `ELSE IF (ncid.eq.XTR(ng)%ncid) THEN` (3122·3179·3236)를 둔다. 해당 추출 분기 끝에는 각각 END IF가 3147·3149행, 3204·3206행, 3261·3263행에 있다. 이 문장 배치는 원문에서 확인했으며 전처리·컴파일 검증은 수행하지 않았다.
- 2352·2379·2470·2497·5547·5625: idLonV와 idXgrV 변수 검색 실패 분기는 ioerror=nf90_enotvar를 설정하면서 FORMAT 10으로 로그를 쓴다. FORMAT 10은 변수 쓰기 오류 문자열이다(3456–3457·6264–6265). FORMAT 20은 변수 ID 조회 오류 문자열이다(3458–3459·6266–6267).
- 5478–5508: PIO의 u점 y 좌표 검색·출력은 idYgrU와 GRID(ng)%yu를 사용한다(5479·5489·5495). 같은 블록의 쓰기 오류·검색 실패 로그는 `TRIM(Vname(1,idXgrU))` (5499·5505)를 사용한다.
- 5756–5785: PIO의 psi점 x 좌표 검색은 Vname(1,idXgrP)를 사용한다(5757). 검색 실패 로그의 변수 이름은 문자열 상수 `'x_psi'` (5783)이다.
- 5836–5876·2866–2868: PIO의 각도 변수 검색은 Vname(1,idangR)를 사용한다(5837). 정점 자료 출력 호출의 변수 이름은 문자열 상수 `'angle'` (5874)이다. 표준 NetCDF의 정점 각도 출력은 Vname(1,idangR)를 넘긴다(2866).
- 1481–1487·4891–4898: 두 루틴의 SGRID grid 출력값은 1로 고정되어 있다. 표준 NetCDF는 `(/1/)` (1486)을 직접 넘긴다. PIO는 `ival=1` (4895) 뒤에 ival을 넘긴다(4897). 주석은 값이 임의이며 후처리의 논리값으로 쓰기 위해 1을 설정한다고 설명한다(1481–1483·4891–4893).
- 99·115·3506·3508·3521: i·j·k·ilev·Zpos·MY_FOUT는 이 파일의 명시된 본문에서 선언 외의 참조가 없다. i·j·k·ilev는 두 루틴의 정수 선언에 있다(99·3506). Zpos는 두 루틴의 STATIONS 선언에 있다(115·3521). MY_FOUT는 PIO 루틴의 정수 선언에 있다(3508). 포함 헤더 내부의 참조 여부는 확인하지 않았다.
