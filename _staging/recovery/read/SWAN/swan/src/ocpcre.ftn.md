## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 3–21·2207·2612: 목차는 RDHMS를 포함하지만 이 파일에는 RDHMS 정의가 없다. EQCSTR 정의는 2207행에 있지만 목차에는 EQCSTR 이름이 없다.
- 560–562·642–643·656–660·755–756·827·910–911·1012·1115–1116·1213: NSKP 설명은 다른 타입이면 값을 그대로 둔다고 적는다. 실수·정수·문자열·시간 판독의 해당 분기는 각각 RSTA·ISTA·CSTA·RSTA를 대입하는 기본값 위치로 이동한다.
- 553·620·626·667: INDBLE의 R/RSTA는 배정밀도이다. CHGVAL 및 RQI 비교는 REAL(R)·REAL(RSTA)를 EQREAL에 전달한다.
- 489·651·663: INDBLE 내부의 미분류 오류 메시지는 루틴 이름을 INREAL로 적는다.
- 623–628·805–808·965–977·1170–1177·667·824·1009·1208: 제공된 유효값을 대입하는 경로는 직접 반환 위치로 이동한다. RQI의 기본값 비교는 값이 제공되지 않은 처리 경로에 있다.
- 1313·1350·1455·1492·474·603–604: ININTV/INITVD의 지역 RI에는 입력 판독 호출 전 초기값 대입이 없다. ININTV는 RI를 INREAL에 전달하며 INREAL은 호출 입구에서 전달받은 값을 DBLE로 변환한다. INITVD는 RI를 INDBLE에 전달한다.
- 620·626·1351–1365·1493–1507: 시간 단위 키워드 판독은 CHGVAL 조건 안에 있다. CHGVAL은 입력값이 기본값과 다르다는 비교 조건에서 TRUE가 된다. 단위 판독의 바깥 else는 FAC=1이다.
- 1473·1492: INITVD의 구조 주석은 INREAL을 호출한다고 적는다. 실행문은 INDBLE을 호출한다.
- 1631–1648·1677·1685·1776·1810·1845·1875: LEESEL 새 항목 초기화는 ELTEXT·ELINT·ELREAL을 초기화한다. 같은 초기화 블록에는 LENCST 대입이 없다. EMPT·EOR 처리 경로에도 LENCST 대입이 없다. 숫자·문자·키워드·기타 항목 경로는 각자 LENCST를 설정한다.
- 100–106·1631–1637: LEESEL은 NREP를 SAVE하며 DATA 초기값은 1이다. RDINIT에는 이 저장 반복 횟수를 다시 설정하는 실행문이 없다.
- 1727·1741·1762·1773–1775: 숫자 조립은 정수 NUM1/NUM2와 10의 거듭제곱을 사용한다. 이 계산 블록에는 자리 수 또는 지수 범위·정수 범위를 검사하는 별도 조건이 없다.
- 1814–1825·1844–1851·1874–1878: 문자열·키워드·기타 항목은 ELTEXT의 JJ 또는 JKAR 위치에 직접 저장한다. 이 직접 저장 경로에는 저장 위치를 LEN(ELTEXT)와 비교하는 조건이 없다.
- 2092–2095: PUTKAR는 JKAR>LEN(LTEXT)이면 msgerr(2)를 호출한다. 바로 뒤 소스 문장은 LTEXT(JKAR:JKAR) 대입이다. 이 루틴에는 경고 뒤 저장을 건너뛰는 분기 또는 반환문이 없다.
- 1009·1022–1030: INCSTR의 RQI 비교는 CSTA(1:LENW)를 사용한다. CSTA 길이가 LENW보다 짧은지 처리하는 조건은 뒤의 기본값 대입 블록에 있다.
- 2295·2298–2312: EQCSTR는 STRACE에 'UPCASE'를 전달한다. 비교 길이는 STR2의 길이이며 STR1의 뒤쪽 추가 문자는 비교하지 않는다.
- 1853·2415–2424: LEESEL은 KEYWRD에 ELTEXT의 앞 8자를 저장한다. KEYWIS는 LEN(STRING)만큼 KEYWRD를 참조하며 STRING 길이를 8로 제한하는 조건이 없다. STRING의 공백 문자는 불일치 검사에서 제외한다.
