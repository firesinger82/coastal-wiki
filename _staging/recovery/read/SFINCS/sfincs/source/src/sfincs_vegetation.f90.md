## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 46–55·266–274·353–357: 직접 NetCDF 경로의 수직 구간 수 검사는 >64만 다룬다. TOML 경로도 개별 배열 층수는 >64만 검사한다. TOML 전체 최대 층수가 0이면 종료를 요청한다. 개별 유형의 층수가 0인지 검사하는 조건은 없다.
- 118–121: type_to_lookup의 범위는 0..maxval(flag_values)이다. 매핑 생성 루프는 flag_values(flag_idx)를 바로 배열 인덱스로 사용한다. 이 루프에는 음수 flag와 중복 flag를 검사하는 조건이 없다.
- 130·239–243: 셀의 유형 정수 0은 이름 조회 전에 건너뛴다. TOML 판독의 건너뛰기는 이름이 none 또는 빈 문자열인지 검사한다. 두 검사 기준은 각각 정수값과 문자열이다.
- 119–121·138–149·248–252: flag_idx는 CF flag_values에서 만든 매핑으로 얻는다. flag_idx<1 오류 문자열은 TOML 항목 부재를 언급한다. TOML 이름 테이블이 없을 때의 실제 처리 루틴은 경고 후 cycle하며 임시 속성 행을 0으로 남긴다.
- 192–193·229·246·258·277–278·299–300·321–322·343–344: get_value 호출은 stat를 받는다. 이후 stat 값을 검사하는 조건문은 이 파일에 없다. 숫자 속성 원소 판독 뒤 rval을 real(kind=4)로 변환한다. get_value 내부의 오류·기본값 처리는 이 판독 범위에서 확인하지 않았다.
- 278·300·322·344: 네 속성 원소에는 형 변환 대입이 있다. Cd·높이·직경·밀도의 수치 하한·상한이나 양수 여부를 검사하는 조건은 이 파일에 없다.
