## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 80·235: 출력 인수 선언은 `durationlength`인데 실제 대입 좌변은 `durantionlength`이다. 232의 repeatwbc 종료 뒤 240에 추가 `endif`가 있다. 이 파일의 열린 if와 대조할 때 240에 대응하는 추가 시작 if는 보이지 않는다.
- 86·100–108·174·235: 지역 wp의 rtbc는 새 생성 경로에서 설정되며, repeatwbc 참 경로에서는 wp%rtbc에 대한 대입 없이 235에서 참조한다.
- 181·197·1864·2376: 호출은 `generate_wave_train_properties_per_offshore_point(wp,s)` 및 `generate_swts(wp,s)`이다. 앞 루틴 정의는 두 인수, 뒤 `generate_swts` 정의는 wp 한 인수이다. 생성 진입 루틴의 지역 선언(84–89)에는 s가 없으며 외부 use의 제공 여부는 이 파일만으로 판단하지 않는다.
- 58–59·505·507·540: 방향 수는 naint=401을 사용하지만 방향 격자 설명 주석은 200 directions라고 쓴다.
- 416·586–589: 키 입력 s의 readkey 상한 인수는 1000이고, 다중 분할의 고정 방향 판정은 모든 scoeff>=1024를 비교한다.
- 657–666: 분산 조건을 충족하지 않으면 scalefac1을 0으로 대입한 뒤 newconv 식의 분모에 scalefac1을 사용한다. 이 두 대입 사이에 0 분모 제외 조건은 보이지 않는다.
- 646–647·675: 반복 중 최대 아닌 분할의 S를 0으로 만들고, 반복 종료 뒤에는 원 multinomalspec에 scalefac1을 곱해 scaledspec 전체를 다시 대입한다.
- 9–21·209·212–213·729·1488: spectrum/shortspectrum의 S/f/ang/Sf는 pointer 성분이다. specin/specinterp, wp%vargen/vargenq 및 scaledspec의 상위 배열 해제 구간에는 각 포인터 대상 해제 문장이 없고, combspec 포인터 대상의 해제도 생성 루틴 끝까지 보이지 않는다. multinomalspec의 S는 757에서 명시적으로 해제한다.
- 875–881: 상대주파수→절대주파수 변환은 STILL TO BE DONE 주석이며 두 분기가 모두 `specin%f = specin%f`이다.
- 1324–1339: 표준격자 i=1..nfint 루프의 마지막 else에서 입력배열 `specin%S(i,:)`를 같은 i로 참조한다. 이 분기에 입력 주파수 인덱스로 바꾸는 별도 대입은 보이지 않는다.
- 1518–1519: 비정수압 fmax의 원문은 `par_g*kmax*tanh(kmax*hb0)/2/par_pi`이며 그 식에는 sqrt 호출이 없다. 물리적 적합성은 판정하지 않는다.
- 1581–1588·1605–1619·1625–1641: BUILDXBEACH가 아닌 전처리 경로의 보간·분산관계 자리에는 주석만 있다. pdflocal 정규화, thetagen의 mod, wgen 계산은 전처리 경로 밖이다.
