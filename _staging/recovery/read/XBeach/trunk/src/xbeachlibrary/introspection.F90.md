## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 464–484: getarraydimsize_c의 결과는 -1로 초기화된 뒤 성공 경로에서도 0으로 바뀌지 않는다.
- 468–482: dim 상한은 rank와 비교하지만 dim의 하한 검사는 없다. rank 1 경로는 size에 dim을 전달하지 않는다.
- 542–550·777–785: C 스칼라 getter는 공간 스칼라 포인터 자체 대신 지역 target 복사본 r0/i0의 c_loc를 돌려준다. 모듈 SAVE(10)가 있으므로 반환 뒤 수명은 이 기록에서 판정하지 않는다.
- 587–600·635–647·682–694·730–742·820–832·868–880: C 배열 getter는 저장 복사 버퍼를 만들며, 다음 같은 getter 호출 시 기존 할당을 해제하고 재할당한다.
- 510–1261: 형별 get/set 루틴은 이름 lookup의 -1을 검사하나 array%type·array%rank와 선택한 형/차원의 일치 검사는 하지 않는다.
- 193–199·236–242: 실수 파라미터 Fortran wrapper는 NULL을 len_trim(name)+1에 쓰지만 C length로 len(name)을 전달한다.
- 177·371: 파라미터 이름 및 배열 이름 함수에 index 유효 범위 검사는 이 본문에 없다.
- 258–270: 실수 파라미터 set은 t·tstop·tnext만 처리하며 그 외 이름은 -1을 반환한다.
- 84–110·978–1023: set2dintarray의 Fortran/C 함수는 있지만 모듈 generic 인터페이스 목록에는 대응 항목이 없다.
- 295: getintparameter_c에는 291행의 한정된 getkey_module 사용 외에 같은 모듈의 전체 USE가 한 번 더 있다.
