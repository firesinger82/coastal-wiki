| p.4 | 인쇄 쪽 번호 4. 2.3.1절 계속: m과 n은 행렬마다 다를 수 있으나 같은 열의 n 값은 같고 같은 행의 m 값은 같음. 행렬 중첩(a4 예)의 첫 행은 위쪽 행렬의 끝에서 둘째 행과 같은 정보를 갖는다: $\mathrm{a4}(1,:)==\mathrm{a3}(\mathrm{m}-1,:)$. 마지막 행은 아래쪽 행렬의 둘째 행과 같은 정보를 갖는다: $\mathrm{a4}(\mathrm{m},:)==\mathrm{a5}(2,:)$. 첫 열은 왼쪽 행렬의 끝에서 둘째 열과 같은 정보를 갖는다: $\mathrm{a4}(:,1)==\mathrm{a1}(:,\mathrm{n}-1)$. 본문은 마지막 열이 오른쪽 행렬의 끝에서 둘째 열과 같은 정보를 갖는다고 설명한다. 인쇄된 배열 관계는 $\mathrm{a4}(:,\mathrm{n})==\mathrm{a7}(:,2)$이다. 가장자리 행렬(a0,a1,a3 등)은 전역 행렬 A의 가장자리에 해당하는 변을 다른 부분행렬과 공유하지 않는다. 중간 행렬(a4)의 A와 공유되는 계산영역은 a4(2:m-1,2:n-1)이다. 가장자리 행렬의 공유 원소 예는 a1(2:m-1,1:n-1)이다. 매 시간 스텝에 A와 공유되는 원소를 계산한다. 본문은 작은 행렬의 둘째 열과 끝에서 둘째 열을 이웃과 통신한다고 설명한다. 본문의 행 통신 예에서는 a3(m-1,:)를 a4(1,:)로 전송한다. 약 100개 행렬이 쓰인다. 일부 행렬은 1~2개 추가 차원을 갖는다. 상대적으로 적은 수의 배열만 프로세스 간 통신이 필요하다. 2.4절 Parallelization method used, 2.4.1절 Input and output: 입출력은 MPI rank 0 master 프로세스 한 개가 수행한다. Broadcast는 전역 변수와 시스템 매개변수 등의 데이터를 그대로 모든 프로세스에 복사한다. Divide and distribute는 격자 상 시스템 상태를 기술하는 모든 행렬의 해당 부분을 각 프로세스에 전송한다. 출력 전에 master는 모든 프로세스에서 데이터를 수집한다. master만 파일시스템을 읽고 쓸 수 있는 시스템에서도 프로그램을 실행할 수 있다. 인용: `The input and output of data is performed by one process: the master process with MPI rank zero.` (p.4) [10-03 codex 재판독] |

| p.8 | 인쇄 쪽 번호 8. 5.1절 계속. `#endif` 후, 'stop' 대신 halt_program 호출: `use xmpi_module` / `if (error = 1) then` / `stop ! wrong` / `call halt_program ! good` / `endif`. xmpi_module에서 쓸 수 있는 변수 표(이름, 의미, 직렬에서의 값): xmpi_rank — MPI rank of this process — 0; xmpi_size — number of processes — 1; xmaster — is this the master process? — .true.; xmpi_isleft — is a(:,1) part of a global border? — .true.; xmpi_isright — is a(:,n) part of a global border? — .true.; xmpi_istop — is a(1,:) part of a global border? — .true.; xmpi_isbot — is a(m,:) part of a global border? — .true.; xmpi_pcol — my column number in processor grid — 1; xmpi_prow — my row number in processor grid — 1. 모든 입출력은 master에서만 수행(필요하면 broadcast): `if (xmaster) then` write/read ... `endif` / `call xmpi_bcast(x)`. readkey_int, readkey_dbl은 MPI-aware이나 readkey는 아님: `timings = readkey_int ('params.txt','timings',1,0,1)`; readkey는 `if(xmaster) then ! for readkey, test is needed` 내부에서 `call readkey('params.txt','tsglobal',fname)`, `open(10,file=fname)`, `read(10,*) x` 후 `call xmpi_bcast(x)`. 5.2절 Parallelization by code spotting 시작: 모든 관련 행렬은 a(1:nx+1,1:ny+1)로 선언되고 'spacepars' 파생형에 있음. 인용: `Take care that every input/output statement is done on master only,` (p.8) [10-03 codex 재판독: 일치] |
| p.9 | 인쇄 쪽 번호 9. 5.2절 계속: 직렬 버전은 파생형 하나, 병렬 버전은 둘: 'sglobal'(sg; master에서 채워지고 모든 데이터 공간 보유), 'slocal'(sl; 분배된 데이터만 보유). sglobal%nx, sglobal%ny는 전역 격자 차원, slocal%nx, slocal%ny는 국지 분배 행렬 차원. 코드 자체를 바꿀 필요 없이 적절할 때 데이터 통신만 챙기면 됨. 패턴-동작 표(a, b는 분배·분할된 (1:nx+1,1:ny+1) 행렬): `a = .. b ...` — No action needed; `a(:,2:ny)= ....` — `call xmpi_shift(a,':1')` 및 `call xmpi_shift(1,':n')` (원문 그대로 두 번째 호출 인수 "1"); `a(:,1) = ....` — `call xmpi_shift(a,':1')`; `a(nx+1,:) = ...` — `call xmpi_shift(a,'m:')`; `a(2,:) = ...` / `a(3:nx+1,:) = ...` — "This one needs some special attention. ## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- p.2: 필요한 배열 값의 예는 `A(i,j)`, `A(i-1,j)`, `A(1,j+1)`로 인쇄되어 있다. 마지막 예의 첫 인덱스는 문자 `i`가 아니라 숫자 `1`이다.
- p.4: 마지막 열의 설명은 `the one before the last column of the matrix right`라고 인쇄되어 있다. 바로 아래의 배열 관계는 $\mathrm{a4}(:,\mathrm{n})==\mathrm{a7}(:,2)$로 인쇄되어 있다. 설명의 열 위치와 배열 관계의 열 인덱스가 다르다. 배열 이름 `a0`, `a1`, `a3`, `a4`, `a5`, `a7`의 숫자는 아래 첨자가 아니라 기준선에 인쇄되어 있다.
- p.5: 실험 설정은 시간 스텝 수를 줄였다고 설명한다. 본문은 줄인 시간 스텝 수를 제시하지 않는다. `gfortran` 오른쪽 위의 `3`은 각주 번호다. 컴파일러 이름은 `gfortran3`이 아니다.
- p.6: 본문은 `The program scales up to 40 processes: he performance using 40 processes is ca. 20 times the performance of the serial version.`이라고 인쇄했다. 문장에는 `the`가 아니라 `he`가 인쇄되어 있다. 위쪽 그래프의 40프로세스 speedup은 눈금 기준 약 27~28로 읽힌다. 아래쪽 그래프의 40프로세스 speedup은 눈금 기준 약 30.5~31로 읽힌다. 그래프에서 읽은 값은 본문의 `ca. 20 times`와 다르다. 두 그래프에는 그림 번호와 캡션이 없다.
- p.7: 결론은 `The speedup is about 20 for a quite modest model.`이라고 인쇄했다. 8코어 그래프의 40프로세스 speedup은 눈금 기준 약 18.5로 읽힌다. 본문은 `2 quad-core nodes`를 장착한 노드라고 인쇄했다. 같은 문장은 노드당 8코어라고 설명한다. 8코어 그래프에는 그림 번호와 캡션이 없다.
