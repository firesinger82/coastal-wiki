| 25–64 | URL `agent_case=<manifest-url>&autostart=1`은 manifest의 `config.json`, `bathy.txt`, `waves.txt`, 선택 `files.overlay`의 `overlay.jpg`, `files.initial_eta`의 `etaInitCond.txt`를 읽어 `initializeWebGPUApp(configContent, bathymetryContent, waveContent, overlayBlob, ..., initialEtaBlob)`에 전달한다(25–32). `js/agent_controls.js`는 `window.CelerisAgentControls`·`celeris-agent-command` `postMessage`로 기존 `calc_constants` 갱신·줌 listener·비활성 시 fullscreen을 사용한다. 재할당 때문에 `getCalcConstants()`가 필요하다(34–43). 설계 callback은 `{ok, message}`를 반환하며 수동 alert를 보존한다. 적용 뒤 끝점만 초기화하고 crest elevation·width·side slope는 유지하며 표면/선형 모드에서 우/좌클릭 교차를 막는다(43–50). mods는 확인된 활성 명령을 받아 `whichPanelisOpen=3`, `surfaceToChange`, `changeType`, 선택 `changeAmplitude`/`changeRadius`를 설정한다(52–56). 상태 표시값 `calc_constants.agent_total_time`, `calc_constants.agent_total_time_since_http_update`, `calc_constants.agent_faster_than_realtime_ratio`는 solver를 구동하지 않는다(58–62). 경계형 `5`는 첫 공통 시간을 `calc_constants.start_time_shift`로 `total_time`에 더해 강제·진단·trigger·중첩 출력이 전역 시계를 공유한다. 일반 관측은 변경/기간 만료마다 영점, 중첩 차트는 절대 시각을 유지한다(63). manifest의 세 기본 파일은 text로 읽으며 overlay는 blob으로 읽는다(27–28). 이 경로는 수동 파일 업로드와 같은 초기화 경로다(31). 부모 iframe에 가벼운 상태 메시지를 보내지만 solver·shader·example-loading 경로를 바꾸지 않는다(31–32). bridge 설치는 일반 HTML update helper 정의 뒤다(34–35). 명령은 별도 render 논리를 도입하지 않는다(38–39). design 명령은 표면 피복 선택·선택 radius/friction·선형 단면 준비·끝점 전환·기존 추가 경로 대기를 제공한다(43–46). 자연어 해석과 확인은 CelerisAgent에 남으며 root는 활성화 명령만 받는다(52–54). click-update shader가 지형·마찰·passive tracer source·수면 편집을 처리한다(55–56). 상태 표시값은 render loop가 복제한다(58–62). 중첩 차트는 reset 때마다 x축 창을 이동한다(63). | 65–81 | `frame()`은 `render_step`을 동적 조절하며 `docs/architecture/SIMULATION_PIPELINE.md` 순서를 따른다(67). `txState`는 현재, `txNewState`는 `Pass3`·경계·삼중대각 결과, `current_stateUVstar`는 중간 상태다. 완료 후 경사 이력·진단을 갱신하고 중첩 출력은 `txState` 복사 전 승인된 `txNewState`의 `eta/hu/hv`를 읽는다(71–76). NLSW는 PCR을 우회하고 Boussinesq/COULWAVE는 수행한다(78). 방향마다 `three` 계수 그룹을 만들어 기본→`newcoef_*`, `newcoef_*`→`txtemp_PCR*`, 역방향을 교대하며 `Run_Tridiag_Solver.js`의 반복 전체 복사를 피한다(80). 각 렌더 프레임은 하나 이상의 timestep을 수행한다(67). `render_step`은 속도와 browser 응답성을 맞춘다(67). Boussinesq/COULWAVE의 PCR은 명시/source-term pass 뒤에 실행된다(78). [11-04 전수 검증 보완] |
| 82–108 | DOM listener는 예제·설정·입사파·마우스 편집·설계·`3D` 카메라·시계열·입출력이다(84–105). sine은 `one` `[amplitude, period, directionRadians, phaseRadians]`, TMA는 `Wave_Generator.js`를 쓴다(88). 키 `W/A/S/D`·화살표는 `viewType == 2`에서만 쓰며 form focus는 제외하고 모드 선택 뒤 blur한다. 좌드래그 이동·우드래그 회전·`Ctrl + left-drag` 대체, 한 손가락 회전·두 손가락 횡이동·pinch의 `shift_y`를 지원한다(92–95). Explorer의 `grid_type == 2`는 경위도 간격을 근사 미터 좌표로 바꾸며 solver/render uniform은 유지한다(96). `requestFullscreen` 실패 시 inline pseudo-fullscreen과 종료 버튼·debounce resize를 쓴다(97). 포인터는 `object-fit: contain`의 내용 영역·CSS `object-position`으로 변환한다(99). `grid_type == 2`의 tooltip·관측 입력·우클릭은 `lon_LL`·`lat_LL` 기반 절대 경위도이나 `locationOfTimeSeries`는 상대 offset이다(100–101). 선형 구조는 패널이 열린 Design에서 끝점·preview를 쓰고 `MouseClickChange.wgsl` 적용·복사·near-dry/계수 갱신 후 끝점·preview를 초기화한다(102). 서/동/남/북 경계형 `5` 업로드는 `ts_*_file`보다 우선한다(104). 활성 출력 사각형은 `txDraw` 검은 윤곽이며 캡처의 좌하단 `j`와 뒤집힌 canvas y를 맞춘다. UI는 첫/기존 사각형, 추가는 `nestedGridOutput_rectangles`, `nestedEtaWriteThreshold`는 GPU 표본이 아닌 회수 때 앞 행을 자른다(105). UI는 `calc_constants`, `html_update`, `click_update`, `add_Disturbance`를 바꾸고 루프가 계산 셰이더(compute shader)·복사를 수행한다(107). 키보드는 물리 `W/A/S/D` key code를 쓰며 blur는 비전체화면 Explorer에서 WASD focus가 갇히지 않게 한다(92). `Ctrl + left-drag`는 Mac용 회전 대안이다(93). 한 손가락 회전은 우드래그와 같은 yaw/pitch 경로다(94). pinch는 `W/S`·위/아래 키와 같은 전후 이동이다(95). 구면 camera 변환은 초기 위치·clipping·이동·terrain lookup·view-projection model transform에 적용하며 도 단위 수평/미터 단위 수직 불일치를 막는다(96). fullscreen fallback은 API 부재 때도 적용한다(97). 내용 영역 변환은 raw canvas 사각형 대신 보이는 영역을 쓰며 Agent split의 좌상단 정렬과 tooltip·시계열·design click 대응을 유지한다(99). 상대 관측 offset 보존은 기존 upload·shader에 grid-relative 좌표를 계속 전달하기 위해서다(101). 선형 구조 추가 버튼은 끝점을 검증하여 편집을 대기시킨다(102). 출력 버튼은 image·GIF·JSON config·simulation surface·중첩 경계 사각형을 포함한다(105). UI는 GPU 텍스처를 직접 변경하지 않는다(107). [11-04 전수 검증 보완] |
| 109–117 | 선택 키는 `Accuracy_mode`, `NLSW_or_Bous`, `grid_type`; `grid_type == 2`는 `Pass3_NLSW_Spherical.wgsl`이다(111). handler 인수는 위치 기반이며 구면 Pass3 바인딩 `19`는 `txDissipationFlux` 대신 `txSphericalMetrics`다(112–113). `txWaves`는 `waves.txt` 또는 sine/TMA 공통 계약으로 sine `numberOfWaves`=`1`, 진폭 `H / 2`, 방향 도→라디안이다. 횡경계가 주기일 때만 활성 구간 위상을 맞추고 TMA는 파고 진단 초기화 없이 캐시·개수·텍스처를 갱신한다(114). 경계형 `5`는 `txBoundaryTimeSeriesSouth/North/West/East`, 단계별 shifted/global `total_time`의 공통 시간 bracket과 `BoundaryPass` uniform·공간 보간을 쓴다(115). 중첩 출력은 활성 사각형당 `four` 텍스처·독립 uniform/group을 쓰며 배열이 없거나 활성 항목이 없으면 스칼라 `nestedGridOutput_*`다. 접두사는 `nestedGridOutput_file_prefix`, `nestedGridOutput_file_prefix2`, `nestedGridOutput_file_prefix3`, 예 `gridD`, `gridD2`, `gridD3`이다. 상한 초과 표본은 `dt` 증가·경고, 모두 종료 후 회수·해제·선택 임계값 절단이며 전역 시간은 보존한다(116). PCR은 x/y `BaseToA`, `AToB`, `BToA`를 쓴다(117). binding `19`의 공통 layout을 유지하는 이유는 WebGPU binding 한도 안에 머물기 위해서다(113). 중첩 출력 texture는 사용자가 capture를 시작할 때 동적으로 할당한다(116). [11-04 전수 검증 보완] |
| 118–128 | `2D`·`3D`는 렌더 그룹을 공유한다(118). 선형 preview는 `calc_constants`에서 render uniform 끝에 기록해 패널 활성 시 `fragment.wgsl`에 끝점·선을 그리며 바닥 변경은 `MouseClickChange.wgsl`·`txBottom` 복사·near-dry/계수 갱신을 따른다(119). JSON 상자는 Explorer 원근/Design top-down으로 같은 pipeline을 쓰고 색상 막대 위·`ShowLogos == 0`의 위쪽 `two` 로고 영역을 scissor한다. 자유수면 Ocean/photo-realistic 표시는 색상 막대 scissor를 생략한다(120). Google Maps 실패 시 `GoogleMapOverlay`, `IsGMMapLoaded`, `IsOverlayMapLoaded`를 지우며 overlay 재선택 호출은 초기 생성과 같은 전체 인수 순서여야 한다(121–122). COULWAVE는 `2D` 임시 출력을 `txCW_groupings` 층으로 복사하고 퇴적물 바닥 변경 뒤 near-dry·분산성(dispersive) 계수를 갱신한다(123–124). 거대 결합 파일이므로 국소 변경·모든 소비 바인딩 검색·오래된 overlay 인수 호출 점검을 권한다(128). preview 값은 매 render write 전에 채운다(119). Design의 JSON box는 2D quad 뒤에 top-down clip-space projection으로 그려 footprint로 표시한다(120). scissor는 Design mode에 적용하며 colorbar가 보일 때 하단 colorbar 위로 제한한다(120). Google Maps 실패 시 flag를 비우는 목적은 모델 진행과 local overlay 검토를 계속하기 위해서다(121). 국소 변경은 기존 pass 순서를 보존해야 한다(128). [11-04 전수 검증 보완] |
