# ARCHITECTURE.md — 판독 구간 기록

| 1–22 | 정적 브라우저 앱의 구성은 `js/`와 `shaders/`이며 서버·패키지 관리자·빌드·트랜스파일 계층이 없다고 설명한다(1–3). `transect` 구현은 제외한다(5). JavaScript는 텍스처(texture)·바인드 그룹(bind group)·계산 셰이더(compute shader)를 관리하고 WGSL은 수치 계산을 맡는다(9). `txState`의 채널은 자유수면·x 운동량·y 운동량·스칼라/거품/추적자이며 `txNewState`는 다음 상태다(13–14). `txBottom`은 북면·동면·중심 바닥고와 near-dry 플래그다(15). `txH`, `txU`, `txV`, `txC`는 면 재구성 값, `txXFlux`, `txYFlux`는 동·북면 유량이다(16–17). `current_stateUVstar`, `txstateUVstar`, `coefMatx`, `coefMaty`, `newcoef_x`, `newcoef_y`, `txtemp_PCRx/y`, `txtemp2_PCRx/y`는 중간 상태·삼중대각 풀이 자료다(18–19). 이름과 채널 변경은 보통 `main.js`·handler·WGSL의 동시 수정을 요구한다(21). 브라우저는 vanilla JavaScript 모듈을 로드하고 WebGPU 텍스처·파이프라인을 만든 뒤 천수 또는 Boussinesq 상태를 WGSL compute pass로 전진시킨다(3). 계산은 거의 전부 GPU에서 수행된다(3). transect는 자체 계약을 가진 별도 특수 모델이며 별도 문서화 대상이다(5). 상태는 JavaScript 배열 대신 WebGPU 텍스처에 저장된다(9). JavaScript는 입력 로드·GPU 자원 할당·pass 출력 복사·렌더링도 담당한다(9). 면 재구성 텍스처의 각 채널은 셀 면에 대응한다(16). `txXFlux`·`txYFlux`는 유한체적 flux다(17). `current_stateUVstar`·`txstateUVstar`는 암시 Boussinesq/COULWAVE 풀이 전후의 명시적·중간 상태다(18). 나머지 19행 텍스처는 삼중대각 계수와 임시 작업 공간이다. 이름과 채널 해석은 세 계층 사이의 API이며 변경 시 보통 함께 수정해야 한다(21). | 23–38 | 시작점은 `index.html` 또는 `river.html`과 `js/main.js`다(25). `js/constants_load_calc.js` 기본값, `config.json` 병합, 지형·선택 입력·파랑·영상 로드, WebGPU 장치·캔버스, 텍스처 할당, CPU 자료 복사, WGSL·파이프라인, 바인드 그룹, 프레임 루프의 `1.`–`9.` 순서를 적는다(27–35). 저장소 경로로 소스·셰이더를 가져오지 못하면 사용할 수 없다고 설명한다(37). `config.json`은 예제 또는 사용자 제공 설정이다(28). 선택 격자는 초기 조건·마찰·hard-bottom이며 입력에는 overlay 영상과 design 텍스처도 포함된다(29). WebGPU adapter/device를 요청하고 canvas를 설정한다(30). 할당 대상은 simulation·diagnostic·render·readback 텍스처 전부다(31). WGSL 텍스트를 fetch하고 compute/render pipeline을 생성한다(33). bind group은 handler와 shader의 binding layout에 맞춘다(34). 점검할 build artifact는 없다(37). [11-04 전수 검증 보완] |
| 39–60 | 프레임당 시간 단계 수를 `main.js`가 동적으로 조절한다(41). 순서는 `Pass0`, `Pass1` 또는 `Pass1_HighOrder`, 퇴적물 활성 시 `SedTrans_Pass1`, `Pass2` 또는 고차 Riemann 변형, 활성 시 `Pass_Breaking`이다(45–49). COULWAVE 모드만 `Pass3A_COULWAVE`·`Pass3B_COULWAVE`에서 고차 분산성(dispersive) 보조항을 `3D` 그룹 텍스처로 묶는다(50). 이후 `Pass3_NLSW`/`Pass3_Bous`/`Pass3_COULWAVE`, `BoundaryPass`, 계수 갱신이 필요한 Boussinesq/COULWAVE의 `Update_TriDiag_coef*`, `TriDiag_PCRx*`·`TriDiag_PCRy*`, 두 번째 `BoundaryPass`, 선택 바닥 갱신, 진단 순서다(51–57). NLSW는 직접 복사로 암시 풀이를 건너뛴다(54). 조건 `timeScheme == 2`에서 예측·수정 단계를 수행하며 `oldGradients`, `oldOldGradients`, `predictedGradients`를 끝에 이동한다(59). 프레임마다 하나 이상의 timestep을 실행하며 GPU 처리량과 브라우저 응답성을 맞추도록 수를 조정한다(41). `Pass0`은 wet/dry 경계 flux용 인접 수심 보조값을 계산한다(45). `Pass1` 계열은 셀 중심 상태와 지형에서 면 상태를 재구성한다(46). `SedTrans_Pass1`은 면 퇴적물 농도를 재구성한다(47). `Pass2` 계열은 x/y 유한체적 flux를 계산한다(48). `Pass_Breaking`은 쇄파 강도와 와점성 flux 보조값을 계산한다(49). `Pass3` 계열은 flux 발산·압력 경사·마찰·쇄파·source term·시간 적분을 결합한다(51). 첫 `BoundaryPass`는 경계 조건과 해안선 정리를 적용한다(52). 두 번째 pass는 암시 풀이 뒤 경계 정리를 재적용한다(55). 선택 바닥 갱신은 침식·퇴적에 따른 지형 변화 뒤 near-dry·삼중대각 자료도 갱신한다(56). 진단에는 평균·최댓값·파고 통계·시계열 추출·렌더 캐시 묶음이 포함된다(57). | 61–88 | `NLSW_or_Bous` 값 `0`은 비선형 천수 방정식과 삼중대각 우회, `1`은 `Pass3_Bous`와 암시 풀이, `2`는 `Pass3A`/`Pass3B`·COULWAVE 계수·PCR 셰이더다(63–67). `Accuracy_mode` 표준은 `Pass1.wgsl`·`Pass2.wgsl`, 고차는 `Pass1_HighOrder.wgsl`·`Pass2_HighOrder_HLLC.wgsl`이다. `Pass2_HighOrder_HLLEM.wgsl`은 현재 `main.js`의 활성 선택이 아니라고 적는다(69–72). 경계 기능은 벽·스펀지·`two-cell` 주기 교환·`waves.txt` 파랑·하천 수위/유량·퇴적물 초기화·쇄파 자료 전파·습윤/건조 정리다(74–85). `BoundaryPass.wgsl`의 임시 출력을 원래 상태 텍스처로 복사한다고 설명한다(87). 모드 `1`은 `Pass3_Bous`에서 분산 source term을 추가한다(66). 경계 pass는 단순 최종 clamp 이상의 동작이다(76). 벽은 운동량을 반사한다(78). sponge는 설정된 가장자리 근처 상태를 0 쪽으로 감쇠한다(79). 입사파는 sine/transient/solitary 파다(81). 퇴적물 초기화는 강제·감쇠 경계에서 수행한다(83). wet/dry 정리는 음수 수심 방지와 한 셀 섬·수로 끝 억제도 포함한다(85). `BoundaryPass.wgsl`은 물·퇴적물 상태를 모두 읽으며 JavaScript는 보통 임시 출력을 canonical 상태 텍스처로 복사한다(87). | 89–109 | 렌더링은 수치 모델을 전진시키지 않는다(91). `Copytxf32_txf16.wgsl`은 표시 자료를 `rgba16float`의 `2D-array` 텍스처로 묶는다. `fragment.wgsl`은 `2D` 표시·색상표·음영·설계·화살표·시계열·색상 막대를, `vertex3D.wgsl`은 높이장을 담당한다(93). `2D`·`3D`는 같은 렌더 바인드 그룹을 공유한다(95). `docs/architecture/SIMULATION_PIPELINE.md`, `DATA_AND_TEXTURES.md`, `CONFIGURATION.md`, `WEBGPU_BINDING_PATTERN.md`와 `docs/source/js/`, `docs/source/shaders/`, `docs/source/externals/`를 안내한다(97–107). 변경 대상 문서와 대응 handler·shader 문서를 먼저 확인하라고 적는다(109). 렌더 변수 묶음은 fragment·3D vertex shader가 읽는 full-precision 텍스처 수를 줄인다(93). `fragment.wgsl`의 음영은 photorealistic water shading이며 overlay는 design-component 텍스처다(93). `vertex3D.wgsl`은 render camera matrix로 수면 높이장을 만든다(93). 2D에서 fragment 전용처럼 보이는 binding도 3D vertex shader에 필요할 수 있다(95). 문서 지도는 timestep/frame loop·texture/channel 계약·config 로드/파생 상수·handler/bind group/shader 결합·개별 JavaScript/WGSL 파일·third-party/local external script를 각각 안내한다(101–107). bind-group 계약을 일급 인터페이스로 취급하면 변경하기 쉽다고 설명한다(109).
