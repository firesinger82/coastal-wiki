## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 3·72: `readTextureData` 정의는 인수 세 개이다. GeoTIFF 루틴의 호출은 dx·dy를 더 전달한다.
- 11–67·177–249·259–310: 읽기 버퍼는 mapAsync 이후 반환 경로에서 unmap 또는 destroy를 호출하지 않는다.
- 75–81: GeoTIFF 지리 키는 4326이고 기준점 여섯 값은 모두 0으로 고정되어 있다.
- 172–173·254–255·425·434·494·501: JPEG·ImageData·층별 JPEG·GIF 복사는 행 바이트를 폭×4로 지정한다. `getFrameData`는 별도로 256바이트 정렬을 계산한다(335).
- 354–363: `getFrameData`는 매핑 버퍼의 Uint8Array 뷰를 만든 뒤 unmap한다. 이후 해당 뷰를 읽어 색상 변환한다.
- 335–345·359–363: `getFrameData`는 복사 행 크기를 정렬한다. 색상 변환 루프는 정렬 행 간격 없이 `4*i`로 접근한다.
- 330·387: `getFrameData` 정의 인수는 `(device, src_texture, width, height)`이다. 호출 인수는 `(device, texture, i, textureSize.width, textureSize.height)`이다.
- 332: `bytesPerChannel`은 1로 선언되지만 이 루틴의 이후 식에서 참조하지 않는다.
- 389: 프레임 파일명은 `.png`이지만 해당 호출 앞에는 `getFrameData` 반환 배열을 PNG로 인코딩하는 호출이 없다.
- 372–412: 동영상 함수 앞 주석은 현재 사용하지 않는다고 적는다. 함수 정의와 FFmpeg 호출은 주석 처리되지 않았다.
