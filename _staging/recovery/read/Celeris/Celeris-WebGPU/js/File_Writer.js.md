## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 4·41: readTextureData의 네 번째 인수는 buffer이다. downloadGeoTiffData는 그 위치에 dx를 전달하고 다섯 번째 인수로 dy를 전달한다. 38행 주석은 해당 GeoTIFF 루틴이 미사용이며 수정 필요하다고 적는다.
- 141–142·226–227·397–409·468–478: JPEG·ImageData·슬라이스 출력의 행 크기는 width×4이다. getFrameData는 256바이트 정렬식을 별도로 사용한다(306–307).
- 261–282: TexturetoImageData는 READ 매핑 후 ImageData를 반환할 때까지 unmap·destroy를 호출하지 않는다. 초기 생성 시 매핑을 해제하는 `buffer.unmap();`은 238행에 있다. [11-04 전수 검증 정정]
- 326–337: getFrameData는 매핑 범위의 Uint8Array 뷰를 만든 뒤 unmap·destroy하고 그 뷰를 읽는다. 변환 인덱스 4*i에는 정렬 행 패딩을 제외하는 행별 오프셋이 없다.
- 302·361: getFrameData의 인수는 device·src_texture·width·height이다. 영상 작성 호출은 device·texture·i·textureSize.width·textureSize.height를 전달한다.
- 128–132: 설정 반영은 기존 속성 여부만 검사한다. 속성값 자료형과 범위 검사는 이 루틴에 없다.
- 556–592·632·837: 표면 출력과 중첩 경계 출력은 다운로드 뒤 sleep을 호출한다. blobCreationAndDownload 자체도 fileWritePause 지연 후 완료한다.
- 678–682: 중첩 경계 수치 포맷은 비유한 값을 문자열 0으로 변환한다.
- 817–829: 임계값 미초과 시 startSampleIndex는 -1이고 actualStartTime은 NaN이다. 설정 actual_start_time은 0으로 저장한 뒤 경고·반환한다.
