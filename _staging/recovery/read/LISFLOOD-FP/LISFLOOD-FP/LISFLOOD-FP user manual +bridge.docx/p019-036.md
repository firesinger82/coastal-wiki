OpenMP 컴파일 플래그는 `-parallel -openmp`다.<br>**1.2.2 Installation on a Windows Vista, XP, NT, 98 or 2000 system.** 적절한 C++ 컴파일러로 `LISFLOOD-FP.cpp`에서 실행 파일을 만든다. 세부 절차는 컴파일러에 따라 다르다. Bristol에서 Borland Visual c++ Builder, Visual c++, Intel c++로 컴파일했다고 적는다. 문서는 속도를 이유로 Intel을 선호한다고 적는다. | p.20 | 인쇄 쪽 번호: 20. **1.3 Data requirements, input files and file formats / 1.3.1 Data requirements.** 표의 열은 `Data requirement`, `Source`, `Comments`다. 캡션은 `Table 4: Input data required by the LISFLOOD-FP model.`이다.<br>래스터 수치표고모형(Raster Digital Elevation Model, DEM)은 항공사진측량 또는 항공 레이저 고도측량(LiDAR)에서 주로 얻는다. 대부분의 범람원(floodplain) 적용에는 약 `25-100m` 격자가 적절해 보이지만 더 작은 격자가 나을 수 있다고 적는다. DEM의 수직 정확도는 일반적으로 `±0.25 m`보다 작아야 한다. `250-500m`의 거친 격자도 예측 수위를 고해상도 DEM에 다시 투영하면 좋은 침수 범위 예측을 낼 수 있다고 적는다.<br>경계조건(boundary conditions)의 유입 유량 수문곡선(inflow discharge hydrograph)은 관측소 기록을 사용한다. 유량은 `.river`의 각 하도 벡터 첫 위치인 상류 하도 셀로 들어간다. 정상상태(steady state)와 동적(dynamic) 모드를 사용할 수 있다. 유량 정확도는 `±10 %`여야 한다. 동적 모의의 시간 해상도는 수문곡선 상승 속도에 의존하지만 통상 적어도 시간별 자료가 필요하다. 영역 가장자리 유동은 관측소, 지점 수위·플럭스 측정, 조석곡선 또는 조석·홍수 빈도 자료로 설정할 수 있다. 범람원 하류 경계 또는 연안 침수의 조석 강제력을 제공할 수 있다. 영역 내부 점원(point sources)도 같은 종류의 자료로 정한다. 점원 유량 또는 방어시설을 넘는 흐름을 지정할 수 있다. 연안 적용에서 외해 영역 유동의 모의를 피하는 데 사용할 수 있다.<br>하도 경사(channel slope), 하도 폭(channel width), 만제 수심(bankfull depth)은 DEM 또는 측량 횡단면에서 얻는다. 필요하면 하도 벡터의 각 점에 개별 설정한다. 하도 폭은 모델 격자 해상도와 같을 필요가 없다. 하도·범람원 마찰(channel and floodplain friction)은 Chow (1959) 또는 Acrement and Schneider (1984) 등의 표를 참고하여 사용자가 정한다. 표의 값은 \(N_c\) `typically between 0.01 and 0.05`, \(N_{fp}\) `typically between 0.03 and 0.15`다. 필요하면 각 격자 셀마다 설정할 수 있다.<br>고정 시간간격(fixed time step)은 사용자가 정한다. 명시적 수치기법(explicit numerical scheme)의 안정성은 셀 크기와 유량에 의존한다. 단일 상류 유입 셀의 유량이 보통 제한 요인이다. 전형적인 값은 `2-20 s`다. 적응 시간간격(adaptive time step)은 안정성을 유지할 최적값을 코드가 계산한다. 최적 시간간격은 격자 크기에 따라 이차적으로 감소한다. 세밀한 격자에서는 계산 비용이 크게 늘 수 있다.<br>원문: `Model data requirements are outlined in Table 4.`(p.20) |
| p.21 | 인쇄 쪽 번호: 21. **1.3.2 Input file formats / 1.3.2.1 Parameter file (.par).** 본문은 입력 파일이 여덟 종류라고 적는다. 확장자는 고정되지 않는다. 주석은 매개변수 파일(parameter file) `.par`에서만 사용할 수 있다고 적는다. 모든 항목은 대소문자를 구분한다. 인식하지 못한 항목은 오류 메시지 없이 무시한다. 한 줄에 한 항목만 쓴다. 키워드가 없으면 코드의 기본값을 사용하며 보통 오류를 내지 않는다. 항목 순서는 고정되지 않는다. 주석 처리할 줄의 첫 문자 자리에 `#`를 쓴다.<br>뒤에 Table 5로 캡션이 붙는 표가 시작된다. 열은 `Item name`, `Description`, `Value in the Buscot weir test case`다. 아래 값은 Buscot 예제 열의 값이다. `DEMfile`: DEM 파일 이름, `Buscot.dem.ascii`. `resroot`: 결과 파일 이름의 루트, `Res`와 `(giving res.op, res.mass etc)`가 인쇄되어 있다. 예시 확장자는 `.op`, `.mass`, `.wd`다. `dirroot`: `.chkpnt`를 제외한 결과 디렉터리의 상대·절대 경로, `results`. 디렉터리가 없으면 생성한다. 키워드를 생략하면 실행한 디렉터리에 결과를 둔다. `simtime`: 총 모의 시간의 실수값, 초 단위, `100000.0`. `initial_tstep`: 고정 시간간격 모델에서는 초 단위 모델 시간간격이다. 가속도(acceleration)·적응 시간간격 모델에서는 최적 시간간격의 초기 추정값이자 가능한 최대 시간간격이다. 예제값은 `10.0`이다. `saveint`: 초 단위 결과 저장 간격, `1000.0`. 파일에는 `results-0001.wd` 같은 순번이 붙는다. `massint`: `.mass` 기록 간격, 초 단위, `100.0`.<br>`checkpoint`: 체크포인트 저장(checkpointing)을 켜는 논리 키워드다. 뒤에 실제 계산 시간 기준의 시간 단위 간격을 쓴다. 값을 정하지 않으면 기본값은 `1 hour`다. 예제값은 `0.0001`이다. 시작할 때 실행 디렉터리의 기본 파일 `“resroot”.chkpnt`를 자동으로 찾아 읽는다. `loadcheck`로 다른 파일 이름을 지정할 수 있다. 처음부터 다시 시작하려면 `.chkpnt`를 삭제하거나 이 옵션을 꺼야 한다. `loadcheck`: 체크포인트 재시작에 사용할 다른 파일 이름이다. 기본적으로 단일 파일을 간격마다 덮어쓴다. 다른 시작 파일은 체크포인트 기능이 덮어쓰지 않는 시작점을 제공한다. 예제값 칸은 비어 있다. `overpass`: 검증용 관측 홍수 영상의 시각, 초 단위, `100000`. 지정한 시각에 수심 파일 `*.op` 등을 쓰는 설명이 다음 쪽으로 이어진다.<br>원문: `The code expects one item per line only.`(p.21) |
| p.22 | 인쇄 쪽 번호: 22. **1.3.2.1의 매개변수 표 계속.** 맨 위는 `overpass` 설명의 연속이다. 지정 시각에 하도 수면 종단(channel water surface profile) `*.profile`도 출력하여 모델 검증을 돕는다.<br>`overpassfile`: 여러 위성 통과(satellite overpasses) 시각을 담은 파일, §1.3.2.8 참조, 예제값 `Buscot.opts`. 주석 처리되어 사용하지 않는다. `fpfric`: 공간적으로 균일한 범람원 Manning 마찰계수(Mannings n), 예제값 `0.06`. `infiltration`: 공간적으로 균일한 범람원 침투율(infiltration rate), 단위 \(\mathrm{ms}^{-1}\), 예제값 `0.0000001`. 주석 처리되어 사용하지 않는다. `porfile`: 공극률(porosity) 상세 파일이다. 구현된 방법은 `4`개라고 적는다.
