## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 79–94·110–138: 대체 ASCII 헤더 ON 분기는 먼저 6개 헤더 문자열을 쓴다. 이후 outflag 1/2의 switch case도 자체 유량 헤더를 쓴다.
- 192–263: write_ascfileDScaled는 차원을 2배, 셀 크기를 절반으로 고정한다. switch에는 case 0만 있다. dem·depth_thresh 인수는 이 함수의 실행식에서 사용하지 않는다.
- 113–124·133–144 및 571–596: ASCII x면 출력은 (xsz+1)*ysz 값, y면 출력은 xsz*(ysz+1) 값을 반복 출력한다. 이진 x/y면 출력은 두 경우 모두 fwrite 개수가 (xsz+1)*(ysz+1)이다. 이진 헤더 차원은 각각 (xsz+1, ysz)·(xsz, ysz+1)이다.
- 521·558·599–615 및 717·739: 이진 헤더의 no_data는 -9999로 초기화한다. 수위 출력의 얕은 셀 값은 NULLVAL을 사용한다. 이 파일 안에는 둘의 동일성 검사문이 없다.
- 683–686·745–748: ASCII 범람원 수심은 0.001 이하를 0으로 처리한다. 이진 범람원 수심은 0 이하만 0으로 처리한다. ASCII 해당 출력 정밀도는 %.3으로 고정된다.
- 56–57·181–182·209–210·271–272·297–298·381–382·644–645·696–697: 파일명 배열은 800바이트, 압축 명령 배열은 255바이트다. gzip 명령은 sprintf로 구성하여 system에 전달한다.
- 303–344: 여러 하천의 세그먼트를 순회하지만 접합부 마지막 절점 특례의 조건은 전역 세그먼트 번호 chseg!=0이다.
- 875–902·926–954: 수로 면 속도는 이전 수로 유량을 단면적으로 바로 나눈 값이 아니다. 기존 유량·경사·마찰로 Qc를 재계산한 뒤 단면적으로 나눈다.
- 855–857·979–999: SGC 속도 출력 분기에서 작업 배열 세 개를 할당한다. 이 함수 끝까지 해당 배열을 해제하는 문장은 없다.
- 1–999: 이 파일에는 전처리 조건 분기나 CUDA·OpenMP 지시가 없다. C·NUMERIC_TYPE·NUM_FMT는 포함 헤더에서 전달되는 이름으로 사용되며 이 파일에서 값을 정의하지 않는다.
