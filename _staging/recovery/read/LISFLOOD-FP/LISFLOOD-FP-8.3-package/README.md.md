| 7–18 | `## Contents` (7) 뒤에 코드 울타리로 배포 구성 목록을 적는다(9–17). `README.md`는 현재 문서이다(10). `LICENSE`의 표기는 `GNU General Public License v3.0`이다(11). `source/`는 컴파일할 전체 소스이다(12). `lisflood-8.2-to-8.3.patch`는 공식 `8.2`에 같은 변경을 적용하는 패치(patch)이다(13). `config.float.cmake`는 GPU 해법과 같은 단정밀도(single precision) 빌드 설정이다(14). `tests/`의 항목은 `quick check, full suite, 8.2-vs-8.3 comparison`이다(15). `paper/`는 논문의 사례·수치·그림을 담는다고 적는다(16). 제목과 목록 사이 및 목록 뒤의 빈 줄도 포함한다(8·18). |
| 19–27 | 문서는 `source/`가 공식 `LISFLOOD-FP 8.2`를 바탕으로 한다고 적는다(19). 원문 식별자는 `Zenodo 10.5281/zenodo.13121102`이다(20). 문서는 CMake가 쓰지 않는 Windows·Intel 라이브러리 묶음, 예전 makefile, 사전 빌드 바이너리, 매뉴얼, 시험 자료와 git 이력을 제외하고 `8.3` 변경을 더했다고 설명한다(21–23). 전체 `8.2`의 최상위 폴더에서 변경을 적용하는 명령은 `patch -p1 -E --binary < lisflood-8.2-to-8.3.patch` (24)이다. 문서는 이 폴더 자체도 `8.2` 소스와 `8.3` 변경을 각각 담은 두 커밋(commit)의 git 저장소라고 적는다(25–26). 변경 확인 명령은 `git show` (26)이다. 마지막 빈 줄도 포함한다(27). |
| 28–35 | `## What changes` (28) 뒤에 `in 8.2`, `in 8.3`, `solvers` 열의 비교표를 둔다(30–31). 문서는 `8.2`의 최대 수심 격자(maximum-depth grid)가 중앙 처리 장치(central processing unit, CPU) 메모리에 있고 매 시간 단계(time step)에 PCIe로 전송되며 GPU가 쓰는 고스트 셀(ghost cells)을 포함하지 않아 큰 격자에서 `cudaErrorIllegalAddress`로 중단한다고 적는다(32). 같은 행은 `8.3`이 전체 크기의 격자를 GPU에 두고 `.max` 파일을 쓸 때만 CPU로 복사한다고 적으며, 적용 해법은 `FV1, FV2, DG2`이다(32). 다음 행은 마른 `NoData` 셀의 공유 계수기 덧셈을 건너뛰는 변경을 `FV1, FV2, DG2, ACC`에 대해 적는다(33). 유량 커널(kernel)의 매 처리 끝 스레드(thread) 동기화 추가는 너비 또는 높이가 `1920 cells`보다 큰 격자의 반복 실행 차이에 대한 변경으로 적으며, 적용 해법은 `FV1, FV2, DG2`이다(34). Apple 컴퓨터의 `Metal back end` 추가는 `FV1`에 대한 변경이다(35). 빈 줄도 포함한다(29). |
| 36–40 | 앞 구간에서 시작한 변경 비교표의 나머지 행이다. 문서는 Linux의 `CUDA 12` 빌드에서 시스템 이름과 충돌하던 미사용 전역 `sync()`의 이름을 바꿨다고 적는다(36). 문서는 macOS에서 C++ 헤더(header) `<format>`을 가리던 최상위 폴더의 한 줄짜리 `format` 파일을 제거했다고 적는다(37). 문서는 `generateDG2DEM`과 `generateDG2start`의 초기화되지 않은 `NoData` 값을 `lisflood`처럼 초기화했다고 적는다(38). 시작 시 출력은 내부 버전 `8.1.0`에서 `LISFLOOD-FP 8.3`으로 바뀌었다고 적는다(39). 표 다음 빈 줄도 포함한다(40). |
| 41–51 | `What we checked (details in the paper):` (41) 뒤의 문서상 검증 주장이다. 문서는 제공된 시험 사례에서 `8.2`가 실행되는 경우 `8.3`의 `FV1, FV2, DG2 and ACC` 출력 파일이 바이트(byte) 단위로 같다고 적는다(43–45). 예외는 실행 사이에 달라지는 질량 수지(mass balance) 기록의 마지막 자리이다(45). 문서는 `8.2`의 `FV1, FV2 and DG2`가 `Carlisle and EA test 5` 사례와 `5.2 million-cell grid`에서 `cudaErrorIllegalAddress`로 중단하지만 `8.3`은 실행된다고 적는다(46–48). 앞의 두 사례 크기는 `0.58 and 1.7 million cells`이다(47). 문서가 적은 최대 시험 크기는 `FV1, FV2, DG2`의 `5.2 million cells`와 `FV1`의 `10.6 million`이다(48–49). 문서는 `NVIDIA Compute Sanitizer`가 `8.2`에서 잘못된 메모리 접근과 공유 메모리(shared memory) 위험을 찾고 `8.3`에서는 찾지 않았다고 적는다(50–51). 목록 앞 빈 줄도 포함한다(42). |
| 52–60 | 문서는 `NVIDIA A100`에서 `24 h, 10.6 million-cell` 홍수 모의의 실행 시간이 `8.3`은 `9.4 min`, `8.2`는 `105 min`이었다고 적는다(52–54). 비교 대상 `8.2`는 실행에 필요한 최소 변경으로 최대 수심 격자를 전체 크기로 할당한 상태라고 명시한다(53–54). 문서는 절감량이 격자에 따라 달라진다고 적는다(54). `NoData` 셀이 없는 격자에서는 `0.5 million cells`에서 `72 %`, `2 to 8 million`에서 `85-89 %`를 절감하고 작은 격자에서는 수 초를 절감한다고 적는다(55–56). 문서는 논문의 세 사례에서 `Metal FV1`의 시간 단계가 CPU 해법과 같고 결과가 단정밀도 반올림 범위에서 일치한다고 적는다(57–58). 문서는 `8.2`의 다른 GPU 해법인 `acc_nugrid`와 적응형 `MWDG2/HWFV1`은 빌드 수정 외에 바꾸지 않았으며 시험하지 않았다고 적는다(59–60). |
| 61–64 | 빈 줄 사이에 시험 환경을 적는다(61–64). Linux 환경 표기는 `Red Hat Enterprise Linux 8.10, GCC 8.5, CUDA 12.6, NVIDIA A100 (40 GB)` (62)이다. Mac 환경 표기는 `macOS 27, Xcode 27, Apple M1 Max (32 GPU cores, 64 GB)` (63)이다. |
| 65–74 | 절 제목은 `## Build on Linux with an NVIDIA GPU` (65)이다. 요구 컴파일러는 `C++14`이고 시험한 컴파일러는 `GCC 8.5`이다(67). 요구 CUDA는 `CUDA 11.4 or later`이고 시험한 버전은 `12.6`이다(67). 요구 빌드 도구는 `CMake 3.13 or later`이다(68). 그 밖의 의존성은 `NetCDF-C, OpenMP and libnuma`이다(68). 클러스터(cluster)에서 모듈(module)을 불러오는 `ECMWF` 예시 명령은 `module load cuda/12.6 netcdf4/4.9.3 cmake/3.28.3` (72)이다. 빈 줄과 코드 울타리도 포함한다(66·70–71·73–74). |
| 75–88 | 문서는 현재 폴더에서 GPU에 맞춰 `CMAKE_CUDA_ARCHITECTURES`를 설정하라고 안내한다(75–76). 대응 표기는 `70 V100, 80 A100, 89 L40S, 90 H100` (75–76)이다. 구성 명령은 `cmake -S source -B build -DCMAKE_BUILD_TYPE=Release -D_CONFIG=$PWD/config.float.cmake -DCMAKE_CUDA_ARCHITECTURES=80` (79)이다. 빌드 명령은 `cmake --build build -j 16` (83)이다. CMake가 `NetCDF`를 찾지 못하는 경우 추가할 옵션은 `-DNetCDF_INCLUDE_DIR=<netcdf>/include -DNetCDF_LIBRARY=<netcdf>/lib/libnetcdf.so` (86–87)이다. 빈 줄과 코드 울타리도 포함한다(77–78·80–82·84–85·88). |
| 89–100 | 클러스터 실행 안내는 `On a cluster:` (89)로 시작한다. 문서는 로그인 노드(login node)에서 컴파일하고 GPU 노드에서 검사하라고 안내한다(91). 실행 예시는 `srun --gres=gpu:1 --time=00:20:00 tests/quick_test.sh build/lisflood` (92)이다. 클러스터가 요구하면 파티션(partition) 또는 계정 인수를 추가하라고 적는다(92–93). GPU 모델 확인 명령은 `nvidia-smi` (94)이다. 문서는 `CMAKE_CUDA_ARCHITECTURES`가 GPU 모델과 맞아야 하며 값이 틀리면 빌드는 성공해도 실행은 실패한다고 적는다(94–96). `lisflood`가 라이브러리 오류로 시작하지 못하면 `~/.bashrc`의 `LD_LIBRARY_PATH`가 불러온 모듈보다 우선할 수 있다고 적는다(97–98). 그 경우의 명령은 `unset LD_LIBRARY_PATH` (99)이며, 이어서 모듈을 다시 불러오라고 안내한다(99). 빈 줄도 포함한다(90·100). |
| 101–116 | 절 제목은 `## Build on a Mac with Apple Silicon` (101)이다. 요구 도구는 명령줄 도구를 포함하는 `Xcode`이며, Homebrew 설치 명령은 `brew install cmake libomp netcdf` (103–104)이다. 구성 명령은 `cmake -S source -B build -DCMAKE_BUILD_TYPE=Release -D_CONFIG=$PWD/config.float.cmake -DOpenMP_CXX_FLAGS="-Xclang -fopenmp -I/opt/homebrew/opt/libomp/include" -DOpenMP_C_FLAGS="-Xclang -fopenmp -I/opt/homebrew/opt/libomp/include" -DOpenMP_CXX_LIB_NAMES=omp -DOpenMP_C_LIB_NAMES=omp -DOpenMP_omp_LIBRARY=/opt/homebrew/opt/libomp/lib/libomp.dylib` (107)이다. 빌드 명령은 `cmake --build build -j 8 --target lisflood generateDG2DEM generateDG2start` (111)이다. 문서는 빌드가 `metal_fv1_kernels.metallib`를 `build/lisflood` 옆에 쓰므로 두 파일을 함께 두라고 안내한다(114–115). 빈 줄과 코드 울타리도 포함한다(102·105–106·108–110·112–113·116). |
| 117–132 | 절 제목은 `## Check` (117)이다. 버전 확인 명령은 `build/lisflood -version` (120)이다. 문서는 시작 출력에 `LISFLOOD-FP 8.3`이 나타난다고 적는다(123). NVIDIA GPU의 검사 명령은 `tests/quick_test.sh build/lisflood` (126)이다. Mac의 검사 명령은 `GPU=metal tests/quick_test.sh build/lisflood` (129)이다. 문서는 검사가 `QUICK TEST PASSED`로 끝난다고 적는다(130). 전체 시험 안내는 `tests/README.md`를 참조하라고 적는다(130). 논문 재현 안내는 `paper/README.md`를 참조하라고 적는다(131). 빈 줄과 코드 울타리도 포함한다(118–119·121–122·124–125·127–128·132). |
| 133–138 | 절 제목은 `## Use` (133)이다. 문서는 사용 방식이 `8.2`와 같다고 적는다(135). GPU 실행은 `.par` 파일에 `cuda`를 넣거나 `-cuda`를 전달하라고 안내한다(135). Mac에서는 `metal`과 `-metal`도 같은 의미라고 적는다(136). 문서는 Mac에서 `FV1`은 Apple GPU에서 실행되고 나머지 해법은 CPU에서 실행된다고 적는다(136–137). 빈 줄도 포함한다(134·138). |

## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 52–54: 문서의 `9.4 min`과 `105 min` 비교에서 기준이 되는 `8.2`는 최대 수심 격자를 전체 크기로 할당한 상태이다. 문서는 그 변경을 실행에 필요한 최소 변경이라고 명시한다.
- 59–60: 문서는 `acc_nugrid`와 적응형 `MWDG2/HWFV1`을 시험하지 않았다고 명시한다. 이 두 해법은 빌드 수정 외에는 바꾸지 않았다고 적는다.
