| 구간 | 내용 |
|---|---|
| 1–10 | Command Line Options / ADCIRC — 명령행 옵션(command line option)으로 파일 위치·입출력(I/O) 등의 동작을 제어하며 조합할 수 있다는 안내를 포함한다(1–9). |
| 11–34 | ADCIRC 옵션 / 입력·출력·writer — -I·-O 디렉터리, 병렬 실행(parallel run)의 -L·-S·-R 바이너리 핫 시작(binary hotstart) 처리와 NetCDF 예외를 원문대로 옮긴다(11–24). -W의 양의 정수 의무·ASCII 대상 파일, -Ws의 파일명 시간 정수부, -H의 바이너리·2DDI·조화 해석(harmonic analysis) 없음 조건을 옮긴다(26–33). 원문: ``` ``-I INPUTDIR`` ``` (11); `    Look for input files in the directory 'INPUTDIR' instead of looking in the directory where the ADCIRC command was issued. ` (12); ``` ``-O GLOBALDIR`` ``` (14); `    Write fulldomain output files to the directory 'GLOBALDIR' instead of writing them to the directory where the ADCIRC command was issued. ` (15); ``` ``-L`` ``` (17); `    When running in parallel, write subdomain output and binaryhotstart files to the PE* subdirectories instead of writing fulldomain output and binary hotstart files. This option does not affect the writing of NetCDF hotstart files, which are always written for the full domain. ` (18); ``` ``-S`` ``` (20); `    When running in parallel, write subdomain binary hotstart files to the PE* subdirectories instead of writing fulldomain binary hotstart files. This option does not affect the writing of NetCDF hotstart file, which are always written for the full domain. ` (21); ``` ``-R`` ``` (23); `    When running in parallel, read subdomain binary hotstart files instead of a fulldomain binary hotstart file. This option does not affect the reading of NetCDF hotstart files, which always reflect the fulldomain solution. ` (24); ``` ``-W NUM_WRITERS`` ``` (26); `    When running in parallel, dedicate NUM_WRITERS MPI processes solely to the task of writing ascii output files (either sparse or dense ascii formats). Must be a positive integer. This option only affects the writing of the ascii formatted fort.63, fort.64, fort.73, and fort.74 files. ` (27); ``` ``-Ws NUM_SPLIT_WRITERS`` ``` (29); `    Same as -W option above, but a new file is created each time the data are written; the integer part of the simulation time is appended to the file name. ` (30); ``` ``-H NUM_HOTSTART_WRITERS`` ``` (32); `    Same as -W option above, except that NUM_HOTSTART_WRITERS MPI processes will be dedicated to writing binary hotstart files. This option does not affect the writing of NetCDF hotstart files. The binary hotstart files that are written using this option are only suitable for 2DDI runs without harmonic analysis. ` (33). |
| 35–52 | Version 51 Additions — -M의 하위 영역(subdomain) 조화 해석 출력과 분조(tidal constituent) 약 30개 초과의 메모리 문제 설명을 옮긴다(38–39). -Mft·-Nft의 ascii 기본값·xdmf v51 추가, -Mfn·-Nfn의 fort.14·fort.13 기본 파일명과 대체 이름을 옮긴다(41–51). 원문: ``` ``-M`` ``` (38); `    When running in parallel, write subdomain harmonic analysis files. This option is useful for tidal analyses with many constituents (e.g., more than approximately 30) because writing fulldomain harmonic analysis output files with this many constituents can exhaust the physical memory of the host computer. ` (39); ``` ``-Mft MESH_FILE_TYPE`` ``` (41); `    The MESH_FILE_TYPE can be specified as ascii (the default) or xdmf (introduced in ADCIRC v51). ` (42); ``` ``-Mfn MESH_FILE_NAME`` ``` (44); `    Search for a full domain mesh file named MESH_FILE_NAME rather than the default mesh file name fort.14. ` (45); ``` ``-Nft NODAL_ATTRIBUTES_FILE_TYPE`` ``` (47); `    The NODAL_ATTRIBUTES_FILE_TYPE can be specified as ascii (the default) or xdmf (introduced in ADCIRC v51). ` (48); ``` ``-Nfn NODAL_ATTRIBUTES_FILE_NAME`` ``` (50); `    Search for a full domain nodal attributes file named NODAL_ATTRIBUTES_FILE_NAME rather than the default nodal attributes file name fort.13. ` (51). |
| 53–75 | ADCIRC Examples — 단독 실행·병렬 실행 입력/출력 분리, 하위 영역 출력, writer 2개, 사용자 격자 파일의 다섯 명령 예시를 원문 그대로 옮긴다(56–74). 이 명령은 기록용 인용이며 실행하지 않았다. 원문: ` Run ADCIRC with input files in a different directory:: ` (56); `    ./adcirc -I /path/to/input/files ` (58); ` Run parallel ADCIRC with input in one directory and output in another:: ` (60); `    mpirun -np 16 ./padcirc -I /path/to/input/files -O /path/to/output/files ` (62); ` Run parallel ADCIRC with subdomain output:: ` (64); `    mpirun -np 16 ./padcirc -L ` (66); ` Run parallel ADCIRC with dedicated writers:: ` (68); `    mpirun -np 16 ./padcirc -W 2 ` (70); ` Run parallel ADCIRC with a custom mesh file name:: ` (72); `    mpirun -np 16 ./padcirc -Mfn my_custom_mesh.grd ` (74). |
| 76–101 | ADCPREP Command Line Options — 영역 분할(domain decomposition) 도구의 명령행 없는 대화형 메뉴(interactive menu) 설명을 포함한다(79). --np의 프로세서 수 관계·다른 작업의 필수 조건, --partmesh의 절점별 정수 파일, --prepall의 0부터 시작하는 PExxxx 번호·기본 파일명·선행 작업 의무, --prep13·15·20·88의 prepall 선행 조건을 원문대로 옮긴다(81–100). 원문: ` ADCPREP is used to partition the ADCIRC domain for parallel execution. If ADCPREP is run without command line options, it presents an interactive menu. Using command line options allows for automation. ` (79); ``` ``--np NUM_SUBDOMAINS`` ``` (81); `    Decompose the domain into NUM_SUBDOMAINS subdomains. The number of subdomains should be equal to the number of compute processors that will be used in the parallel computation. This command line option is required for all other ADCPREP operations. ` (82); ``` ``--partmesh`` ``` (84); `    Partition the mesh only; that is, decide which subdomain each of the nodes should fall into. This should be done first. The result is a file called partmesh.txt, which consists of a list of integers, one line per node in the fulldomain mesh. Each integer in the list represents the subdomain number that each node will fall into. As a result, the range of values in the file represents the range of subdomain numbers. ` (85); ``` ``--prepall`` ``` (87); `    Use the partmesh.txt file to decompose all the ADCIRC input files into subdirectories numbered 'PExxxx' where 'xxxx' is the zero indexed, zero padded subdomain number. Expects all input files to have the default names, e.g., the mesh file must be named fort.14 instead of something like myMeshFile.grd in order for this option to work. This option requires that adcprep has already been executed with the partmesh option, and that the partmesh.txt file was written successfully. ` (88); ``` ``--prep13`` ``` (90); `    Only redecompose the nodal attributes (fort.13) input file. Requires that prepall step has already been performed. ` (91); ``` ``--prep15`` ``` (93); `    Only redecompose the control model parameter and periodic boundary conditions file (fort.15) input file. Requires that prepall step has already been performed. ` (94); ``` ``--prep20`` ``` (96); `    Only redecompose the non-periodic, normal flux boundary condition file (fort.20). Requires that prepall step has already been performed. ` (97); ``` ``--prep88`` ``` (99); `    Only redecompose the upland river initialization file (fort.88). Requires that prepall step has already been performed. ` (100). |
| 102–130 | ADCPREP Examples / Notes on Parallel Execution — 16 프로세서용 분할·전체 입력 준비와 속성 재분할 명령을 그대로 옮긴다(105–115). ADCPREP·padcirc·후처리(post-processing) 순서와 -W·-Ws·-H·-L·-M의 문서상 성능 고려를 옮기고 마지막 행을 포함한다(120–130). 원문: ` Complete parallel preparation for 16 processors:: ` (105); `    # Step 1: Partition the mesh ` (107); `    adcprep --np 16 --partmesh ` (108); `    # Step 2: Prepare all input files ` (110); `    adcprep --np 16 --prepall ` (111); ` Re-decompose just the nodal attributes file after making changes:: ` (113); `    adcprep --np 16 --prep13 ` (115); ` When running ADCIRC in parallel, it's important to understand the workflow: ` (120); ` 1. First run ADCPREP to partition the domain ` (122); ` 2. Then run padcirc with the appropriate options ` (123); ` 3. Post-processing may be needed to combine subdomain outputs ` (124); ` Performance considerations: ` (126); ``` - The ``-W``, ``-Ws``, and ``-H`` options can improve performance by dedicating specific processes to I/O operations ``` (128); ``` - Using the ``-L`` option reduces memory requirements but requires post-processing to combine outputs ``` (129); ``` - For large domains with many tidal constituents, the ``-M`` option can prevent memory exhaustion  ``` (130). |
