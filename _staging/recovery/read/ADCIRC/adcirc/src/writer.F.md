## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 46·48·55·298·412–413: 정수 메타데이터 수는 7, 실수 메타데이터 수는 2, 전담 프로세서당 버퍼 상한은 25로 고정되어 있다. 출력 데이터 파일명 송수신 길이는 1024문자이다.
- 370–396: 기존 lun 검색과 빈 lun 검색이 모두 실패한 경우를 처리하는 조건은 없다. 검색 뒤 기술자 접근은 bufID를 그대로 사용한다.
- 307–331·444–478·1555–1587·1617–1645: 네 집계 루프는 num·istart·iend를 갱신하지만 bufsize를 루프 안에서 다시 계산하지 않는다. mpi_reduce의 count 인수는 최초 bufsize이다.
- 265·517–529: sendDataToWriter는 myproc 조건 밖에서 nwloaded(wcommID)를 true로 설정한다. flush_writers에서 nwloaded(i)를 false로 설정하는 문장은 myproc=0 분기 안에 있다.
- 674–675·683–684: 희소 벡터 헤더의 nNonDefVal은 두 성분 모두 비기본값인 위치를 센다. 실제 레코드 출력 조건은 두 성분 중 하나라도 비기본값인 위치이다.
- 660·690·698 및 634–697: 희소 스칼라와 벡터 분기는 각자 close(fid)를 실행한다. 성분 select 뒤에도 close(fid)가 있다. 성분 case default에는 areDefault1 해제문이 없다.
- 568·708–710: initNetCDFOutputFile은 nerr를 반환 인수로 받는다. 해당 호출 뒤 nerr 조건 검사 없이 initialized를 true로 설정한다.
- 824–828: openFileForRead는 required=.FALSE.와 ierr를 사용한다. 뒤의 두 read 앞에는 ierr 검사 조건이 없다.
- 893–894·922: writerReadMesh의 제어 파일명 수신 대상은 controlFileName이다. readControlFile에 넘기는 이름은 controlFileName_g이다. 이 루틴에는 controlFileName을 controlFileName_g로 복사하는 문장이 없다.
- 1248–1250·1260: HTOT2_g의 미할당 여부를 검사한 분기에서 ETA2_g를 할당한다. H2_HS_Descript의 전역 배열 포인터는 HTOT2_g를 가리킨다.
- 1343–1344·1386–1419: H1_HS_Descript와 H2_HS_Descript를 집계한다. CASE(-1,1)의 배열 WRITE 목록에는 두 기술자가 등장하지 않는다.
- 1372–1373·1544·1575·1606·1633: 재시작 바이너리 파일의 직접 접근 레코드 길이는 8로 고정되어 있다. 두 collect 루틴은 tagbase를 5000/6000으로 교대하고 tag를 계산하지만 해당 tag를 mpi_reduce 호출에 넘기지 않는다.
