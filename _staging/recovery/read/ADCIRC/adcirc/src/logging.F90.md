## 판독 중 확인된 코드 사실 (판단 아님, 후속 검토 대상)

- 157–159: t_log_level_constructor의 level_code 인수는 optional이다. select case 앞에 present(level_code) 검사가 없다.
- 99–101·369–375·400: nabout과 screenUnit의 선언에는 초기값이 없다. 이 파일에는 두 변수에 값을 설정하는 실행문이 없다. 출력 루틴은 두 변수를 참조한다. 외부 설정 코드는 이 판독에서 확인하지 않았다.
- 95–97·201–202: sourceNumber의 초기값은 0이다. FULL_STACK이 없는 formatLogMessage 경로는 messageSources(sourceNumber)를 사용한다. 그 참조 앞에 sourceNumber>=1 검사가 없다.
- 71·95–96·193·197–198: 출처 이름 길이는 48이고 스택 용량은 50이다. FULL_STACK 출력 버퍼 temp의 길이는 1024이다. 내부 write는 1..sourceNumber의 모든 이름을 사용한다. 이 함수에는 길이 검사나 write의 iostat 처리가 없다.
- 434–435·448: setMessageSource는 깊이 상한 검사 없이 sourceNumber를 늘려 배열에 저장한다. unsetMessageSource는 하한 검사 없이 sourceNumber를 줄인다.
- 485–488·514–522·95: 추적 생성자의 깊이 조건은 `if (sourceNumber <= max_message_source_depth) then` (485)이다. init_log_scope의 깊이 조건은 `if (sourceNumber < max_message_source_depth) then` (514)이다. 전자는 깊이가 50인 경우에도 434행의 증가와 435행의 저장을 호출한다.
- 460–467: create_log_scope는 깊이 검사 없이 setMessageSource를 호출한다. 두 다른 초기화 경로에는 깊이 조건이 있다(485·514).
- 508–527: init_log_scope는 intent(inout) scope를 받는다. 활성 scope인지 검사하거나 이전 출처를 제거하는 실행문 없이 새 출처를 추가한다. 깊이 조건이 거짓인 경로에는 scope 상태를 다시 설정하는 else가 없다.
- 362·369–375: screenMessage는 error_unit을 별도로 use한다. 해당 지역 이름은 이 루틴의 실행문에서 직접 참조하지 않는다. 출력 장치는 log_level%unit() 또는 screenUnit에서 가져온다.
