| p.5 | 인쇄된 쪽 번호는 `2 / 6`이다.<br>§2 `Build It`의 계속이다.<br>앞선 `adcirc` 빌드가 성공했다고 가정한 다음 명령은 `make padcirc compiler=intel`이다.<br>`padcirc` 빌드가 성공하면 병렬 SWAN이 쓰는 병렬화 모듈(parallelization modules)을 사용할 수 있다.<br>`padcirc`와 병렬 SWAN은 같은 라이브러리(libraries)를 공유한다.<br>`padcswan`은 `padcirc`보다 뒤에 빌드해야 한다.<br>본문 인용: `In other words, the padcswan build depends on the padcirc build, so padcirc must be built before padcswan.` (p.5)<br>ADCIRC+SWAN 빌드를 원할 때의 디렉터리 이동 명령은 `cd ../swan`이다.<br>SWAN은 별도의 빌드 체계(build system)를 사용한다.<br>SWAN의 Perl 스크립트 `platform.pl`은 ADCIRC의 `config.guess`와 비슷한 기능을 수행한다.<br>이어지는 설명에서는 스크립트 이름을 `plaform.pl`로 인쇄한다.<br>이 설명은 스크립트가 컴파일러 플래그를 선택하여 `macros.inc`에 쓴다고 명시한다.<br>원문은 일부 플랫폼용 `macros.inc` 파일 묶음이 ADCIRC 소스 코드에 이미 있다고 설명한다.<br>기존 선택지를 보는 명령은 `ls macros*`다.<br>해당 플랫폼의 플래그를 작성하는 명령은 `perl ./platform.pl`이다.<br>원문은 생성된 `macros.inc`가 사용 중인 컴파일러를 나타내는지 확인해 볼 수 있다고 쓴다.<br>파일이 적절해 보이면 `make punswan`으로 시험 빌드(test build)를 수행한다.<br>`punswan` 빌드의 목적은 컴파일러 플래그의 유효성을 시험하는 것이다.<br>`punswan`은 실제로 사용하지 않는다.<br>`punswan`은 빌드에 성공하더라도 삭제한다.<br>성공한 시험 빌드의 실행 파일과 그 과정에서 만든 목적 파일(object files)을 제거하는 명령은 `make clobber`다.<br>이후 `padcswan` 빌드를 원할 때의 명령은 두 줄로 인쇄되어 있다.<br>`cd ../work`<br>`make padcswan compiler=intel`<br>`padcswan` 빌드에 성공하면 병렬 실행의 입력 파일을 준비하는 `adcprep`을 빌드할 수 있다.<br>ADCIRC+SWAN도 병렬 실행할 계획이면 `make` 명령행에 `SWAN=enable`을 추가한다.<br>해당 예시는 `make adcprep compiler=intel SWAN=enable`이다.<br>`adcprep`은 영역 분할(domain decomposition)에 C로 작성된 `metis` 라이브러리를 사용한다.<br>이 때문에 `adcprep` 빌드 과정에서 C 컴파일러가 호출된다.<br>`adcprep`까지 성공적으로 빌드하면 주요 실행 파일 묶음이 완성된다.<br>추가로 빌드할 수 있는 `hstime`은 ADCIRC 핫스타트 파일(hotstart file)의 시간을 읽어 콘솔 창(console window)에 쓴다.<br>시간의 단위는 원문에서 `seconds`로 명시한다.<br>`hstime` 빌드 예시는 `make hstime compiler=intel`이다.<br>`aswip`은 비대칭 바람 입력 전처리기(Asymmetric Wind Input | p.6 | 인쇄된 쪽 번호는 `3 / 6`이다.<br>§2 `Build It`의 계속과 `3 Development Strategy`가 있다.<br>§2의 첫 문장은 `aswip`을 성공적으로 빌드하려면 `adcirc` 실행 파일을 먼저 빌드해야 한다고 명시한다.<br>`aswip` 빌드 예시는 `make aswip compiler=intel`이다.<br>`aswip`은 `adcirc`와 같은 디렉터리에서 빌드한다.<br>두 프로그램에는 각각 `"main"` 프로그램 부분이 있어 충돌을 만든다.<br>`aswip` 빌드 이후 `adcirc`를 재빌드하기 전에 삭제해야 하는 대상을 원문은 `aswip its object file`로 인쇄한다.<br>해당 본문 인용: `Therefore, in order to rebuild adcirc after aswip has been built, aswip its object ﬁle must be deleted ﬁrst, to avoid a build error when adcirc is rebuilt.` (p.6)<br>앞서 제시한 빌드 지시는 NetCDF 입력 또는 출력 지원을 포함하지 않는다.<br>원문은 빌드 과정을 단순하게 하려고 이렇게 했다고 설명한다.<br>원문은 NetCDF 파일의 여러 장점을 이유로 NetCDF 사용을 권장한다.<br>지원 능력은 `NetCDF3`, `NetCDF4 (classic model)`, `NetCDF4 with internal compression`의 세 가지다.<br>NetCDF 없이 모든 실행 파일을 이미 빌드했으면 NetCDF를 포함하여 빌드하기 전에 기존 실행 파일을 제거해야 한다.<br>제거 명령은 `make clobber`다.<br>NetCDF3 컴파일을 활성화하는 명령 예시는 `make adcirc compiler=intel NETCDF=enable NETCDFHOME=/usr`다.<br>`NETCDFHOME`은 NetCDF 설치 디렉터리를 나타내는 변수다.<br>`/usr`는 이 명령 예시의 값이다.<br>빌드 체계는 해당 디렉터리에 `include/netcdf.inc`가 있을 것으로 기대한다.<br>플랫폼에 내부 압축(internal compression)이 없는 NetCDF4를 설치했을 때의 예시는 `make adcirc compiler=intel NETCDF=enable NETCDFHOME=/usr NETCDF4=enable`이다.<br>이 경우 `NETCDFHOME`이 가리키는 디렉터리에는 Fortran 모듈 파일(module file) `include/netcdf.mod`도 있을 것으로 기대한다.<br>NetCDF4 설치가 내부 압축을 지원하고 ADCIRC의 자동 내부 압축 사용을 원할 때의 명령은 두 줄로 인쇄되어 있다.<br>`make adcirc compiler=intel NETCDF=enable NETCDFHOME=/usr NETCDF4=enable`<br>`NETCDF4_COMPRESSION=enable`<br>원문은 내부 압축이 `NetCDF4 version 4.1`에서 처음 도입되었다고 명시한다.<br>모든 ADCIRC 실행 파일의 설정을 일관되게 하려면 각 실행 파일의 빌드에 이러한 명령행 변경을 적용해야 한다.<br>본문 인용: `These changes in the make command line must be made for the build of each of the ADCIRC executables so that they are all consistent.` (p.6)<br>원문은 NetCDF 지원 빌드에 맞는 컴파일러 플래그와 옵션(options)이 플랫폼마다 크게 달라 보통 로컬 시스템 관리자와 여러 차례 이메일을 주고받아야 한다고 설명한다.<br>원문은 시작할 때 참고할 대상으로 `cmplrflags.mk`의 NetCDF 관련 컴파일러 플래그를 제시한다.<br>이 쪽은 옵션의 기본값이나 수치 범위를 제시하지 않는다.<br>§3은 언제든 안정 버전(stable version)과 개발 버전(development version)을 별도로 유지한다고 설명한다.<br>안정 버전은 버그 수정(bug fixes)만 받는다.<br>개발 버전은 버그 수정과 새 기능을 받는다.<br>원문은 개발 버전이 안정화되면 그 버전에서 안정 분기(stable branch)를 만든다고 설명한다.<br>원문은 이어서 이전에
