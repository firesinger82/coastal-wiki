| 425–426 | PC — 음수 시간 간격으로 예측·수정 시간 적분 알고리즘(predictor-corrector time stepping algorithm)을 활성화한 시험을 설명한다(425). 작성자는 다른 버그를 고치던 중 이 알고리즘에 버그를 넣은 뒤 시험을 추가했다고 보고한다(425). 원문은 기본 시간 적분보다 적용 사례가 적다고 적는다(425). 원문은 예제 네 개에서는 Serial과 매우 비슷한 결과를 냈지만 Shinnecock Inlet에서는 실패했다고 적는다(425). 조건·적용 범위·결과 원문: `**PC.** The predictor-corrector time stepping algorithm was activated by selecting a negative time step. This test was added to the suite after I inadvertently introduced a bug into the predictor-corrector algorithm while fixing a different bug. Please note that the predictor-corrector algorithm has not been applied as broadly as ADCIRC’s default time stepping procedure. Note also that the predictor-corrector algorithm passed on four example problems (i.e., produced results very similar to “serial” test), but failed (blew up) on the Shinnecock Inlet problem.` (425). 빈 줄을 포함한다(426). |
| 427–430 | Hot / 작성자 — 콜드 시작(cold start)으로 대략 실행 중간까지 계산하여 핫 시작 파일(hot start file)을 만든 뒤 핫 시작으로 완료하는 시험을 설명한다(427). 처음부터 끝까지 콜드 시작으로 계산한 Serial 결과와 비교했다고 적는다(427). 목적은 핫 시작이 해를 바꾸거나 교란하지 않는지 확인하는 것이었다고 적는다(427). 작성자는 이 시험으로 핫 시작 버그 두 개를 발견하여 고쳤다고 보고한다(427). 조건·절차·결과 원문: `**Hot.** This test was carried out by cold starting the example problem and running it until a hot start file was generated, approximately halfway through. Then it was hot started and run to completion. The results were compared to the “serial” case, where the simulations start from cold and run all the way to completion. The purpose was to ensure that a hotstart does not change or perturb the solution. I discovered and fixed two hotstart bugs with this test case, one in 2D for input files where NOLIFA != 0, and another one in 3D. ` (427). 작성자·작성 시점은 `Jason G. Fleming, December 2005` (429)이다. 빈 줄을 포함한다. |
