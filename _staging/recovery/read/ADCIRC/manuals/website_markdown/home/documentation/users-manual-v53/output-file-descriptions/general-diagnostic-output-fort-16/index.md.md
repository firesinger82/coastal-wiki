| 408–415 | **Notes for fort.16 file / GFDL 자료 특성**. 지구물리유체역학연구소(Geophysical Fluid Dynamics Laboratory, GFDL) 파일 형식은 대기 모델(atmospheric models) 출력을 지원하기 위해 개발되었다고 설명한다(410–411). The files  ` (410); `have the following characteristics:` (411); `\* Each ASCII GFDL met file contains one or more nested grid data where the nested grids are allowed to change in time.  ` (413); `\* Coarse grid data is not stored where finer nest data is given.` (414). |
| 416–422 | **GFDL용 fort.22 / 입력 줄 형식**. 이 소절은 ADCIRC의 GFDL용 `fort.22` 형식을 제시한다(416). 첫 줄은 ASCII 문자 머리부(header)이다(418). 둘째 줄은 실수형 풍속 배율 값이다(419). 셋째 줄은 최대 외삽 거리(maximum extrapolation distance)를 미터 단위로 제시한다(420). 넷째 줄부터 마지막 줄까지의 세 필드 순서는 원문대로 아래에 옮긴다(421). 이 구간은 앞뒤 빈 줄도 포함한다(417·422). 원문: `The file format of the ADCIRC fort.22 for GFDL is as follows:` (416); `Line 1 — ASCII Text Header  ` (418); `Line 2 — Windmultiplier Value (real number)  ` (419); `Line 3 — Maximum Extrapolation distance (m)  ` (420); `Lines 4-end — cycleTime rampValue filename` (421). |
| 423–437 | **실제 GFDL 파일 / 격자 수와 자료 열**. 첫 줄은 `NCELLS`를 `f10.4` 형식으로 둔다(425). 둘째 줄부터 `NCELLS+1` 줄까지는 열 개 열을 `10f10.4`로 둔다고 설명한다(426). 각 열의 이름과 단위는 원문대로 옮긴다(427–436). 열 번째 중첩 격자 번호는 항상 존재하는 것은 아니라고 명시한다(436). 제목과 빈 줄 및 줄바꿈 마크업도 포함한다(423–437). 원문: `The file format for each of the actual GFDL files is as follows:` (423); `Line 1: Number of grid cells (f10.4) NCELLS  ` (425); `Lines 2-NCELLS+1: Have ten columns of data formatted as 10f10.4  ` (426); `1. u (m/sec)  ` (427); `2. v (m/sec)  ` (428); `3. Temperature (K)  ` (429); `4. mixing ratio(kg/kg)  ` (430); `5. storm accum precipitation (cm)  ` (431); `6. sea level pressure (hPa)  ` (432); `7. longitude (decimal deg)  ` (433); `8. latitude (decimal deg)  ` (434); `9. hurricane hour  ` (435); `10. nest number (this is not always present)` (436). |
| 438–448 | **GFDL용 fort.22 / 입력 예제와 경로 인용 조건**. 입력 예제는 주석 줄의 최대 길이를 1024자로 제시한다(440). 예제 둘째 줄의 속도 크기 배율은 `1.0`이다(441). 예제 셋째 줄의 최대 외삽 거리는 `10000.0` 미터이다(442). 예제의 시간과 램프 배율(ramp mult) 및 파일명 줄은 원문 그대로 옮긴다(443–445). 전체 경로에 슬래시가 들어 있으면 파일명을 큰따옴표로 감싸야 한다(447). 원문은 Fortran이 따옴표 없는 슬래시를 레코드 종료 문자(end-of-record character)로 취급하기 때문에 이 처리가 필수라고 설명한다(447). 예제 소개와 빈 줄을 포함한다(438–448). 원문: `To illustrate the definitions and descriptions provided, a concrete example of an ADCIRC fort.22 file for GFDL is provided as follows:` (438); `! 1st line is a comment line, max length 1024 characters  ` (440); `1.0 ! 2nd line is a velocity magnitude multiplier  ` (441); `10000.0 ! 3rd line: maximum extrapolation distance (m)  ` (442); `0.0 0.0 “/home/jason/isaac/gfdl/isaac\_gfdl\_file1″ ! time (hours), ramp mult, filename  ` (443); `6.0 0.5 “/home/jason/isaac/gfdl/isaac\_gfdl\_file2″  ` (444); `12.0 1.0 “/home/jason/isaac/gfdl/isaac\_gfdl\_file3″` (445); `When including the path to the data files, if the full path includes forward slashes (as it would if ADCIRC is executing on Unix or Linux), be sure to surround the full path file name with double quotes as shown in the example above. This is required because Fortran treats a bare forward slash in an input file as an end-of-record character.` (447). |
