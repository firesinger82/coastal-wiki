# Ramping.md — 판독 구간 기록

구간은 1행부터 65행까지 빈틈없이 이어진다.

| 구간 | 내용 |
|---|---|
| 1–16 | Ramping — 모형에 충격을 주지 않도록 조석(tides)이나 바람 같은 강제력(forcing)의 항을 일정 기간에 걸쳐 증가시키는 방법을 소개한다(5). 제목, 판본 표기와 네 절의 목차를 포함한다(1–16). |
| 17–20 | Conceptual Justification — 수면과 유속을 모두 0으로 초기화한 모형에 완전한 조석 강제력을 즉시 적용하면 가짜 파(spurious waves)가 생기기 쉽다고 설명한다(19). 조석 위상에 맞는 초기 수면과 유속을 모든 점에 지정하는 것이 이상적이지만 일반적으로 달성할 수 없다고 설명한다(19). 강제력을 점진적으로 키우는 이유를 제시한다(19). |
| 21–50 | Ramping Method — `NRAMP`는 램핑(ramping)의 활성화 여부와 램핑 항의 수를 제어한다(23). 모든 램프(ramp)는 지정한 일수에 걸친 절단된 쌍곡탄젠트(truncated hyperbolic tangent) 함수라고 설명한다(23). 각 강제력의 일수와 시간 기준을 아래 원문으로 구분한다(25–45). 큰 하천의 초기화와 평형을 위해 `FluxSettlingTime`을 사용한다(47). 복사 유량 경계조건(radiation flux boundary condition)에서 이 시간이 요구된다고 설명한다(47). 수위 오프셋(water level offset) 같은 일부 램핑 항에는 네임리스트(namelist) 제어도 있다고 설명한다(49). 원문: `[NRAMP](/index.php?title=NRAMP&action=edit&redlink=1) controls whether ramping is enabled, as well as how many ramping terms there are.  This is to permit users to apply different ramping times for different forcing terms.  All ramps in ADCIRC are applied as (truncated) [hyperbolic tangent](https://en.wikipedia.org/wiki/Hyperbolic_function) functions over a specified number of days.  The various DRAMP* variables control the number of days over which the ramping is applied for individual forcing terms, they are:  ` (23); `- [DRAMP](/index.php?title=DRAMP&action=edit&redlink=1) -  any forcing terms not covered by the other DRAMP* terms` (25); `- [DRAMPExtFlux](/index.php?title=DRAMPExtFlux&action=edit&redlink=1) - external flux boundary condition (BC)` (27); `- [DRAMPIntFlux](/index.php?title=DRAMPIntFlux&action=edit&redlink=1) - internal flux BC` (29); `- [DRAMPElev](/index.php?title=DRAMPElev&action=edit&redlink=1) - elevation specified BC` (31); `- [DRAMPTip](/index.php?title=DRAMPTip&action=edit&redlink=1) - tidal potential forcing` (33); `- [DRAMPMete](/index.php?title=DRAMPMete&action=edit&redlink=1) - meteorological forcing` (35); `- [DRAMPWRad](/index.php?title=DRAMPWRad&action=edit&redlink=1) - wave radiation stress forcing` (37); `Two other variables, [FluxSettlingTime](/index.php?title=FluxSettlingTime&action=edit&redlink=1) and [DUnRampMete](/index.php?title=DUnRampMete&action=edit&redlink=1) (also in days), affect the timing of the ramping terms.  ` (39); `- If NRAMP=1, then DRAMP is relative to [coldstart](/index.php?title=Coldstart&action=edit&redlink=1) time.` (41); `- If 1<NRAMP<8, then all DRAMP* terms are relative to coldstart time plus FluxSettlingTime` (43); `- If NRAMP=8, then all DRAMP* terms are as above, except DRAMPMete is relative to coldstart plus FluxSettlingTime plus DUnRampMete` (45); `FluxSettlingTime is used because, for large river systems such as the Mississippi River, it can take several days to initialize them and equilibrate.  It is a requirement when using the radiation flux boundary condition ([IBTYPE](/index.php?title=IBTYPE&action=edit&redlink=1)=52) because instabilities can quickly form otherwise.  DUnRampMete is useful because often a simulation is coldstarted without meteorological forcing (such as a tide-only simulation), and meteorological ramping is needed later when this forcing is added to a hotstarted simulation.  ` (47). |
| 51–60 | Typical Values — 강제력별 `DRAMP*`의 전형적인 일수를 제시한다(53). 아래 값은 문서가 제시한 전형적인 범위이며 기본값이라고 쓰지는 않는다(55–59). 원문: `- Flux: 0.5-5 days` (55); `- Tide: 5-30 days` (57); `- Meteorology:  0.5-2 days` (59). |
| 61–65 | Example Usage Case — 허리케인 Katrina에 대한 SWAN+ADCIRC의 재현 계산(hindcast)을 예로 든다(63). 최초의 짧은 램핑 설정에서는 하천 모형이 불안정해졌다고 설명한다(63). 이어서 하천·조석 강제력을 초기화하는 계산과 그 결과로 재시작(hotstart)하는 폭풍 계산을 설명한다(63). 재시작 시 이미 지난 램핑 시간에 대한 설정과 파랑 복사응력(wave radiation stress) 램핑을 0으로 남긴 이유를 설명한다(65). 예시 설정과 시간 합은 원문 그대로 옮긴다. 원문: `Consider the following illustrative example of how one might use all of these.  Let's say someone by the name of Arturo wants to run a hindcast simulation of Hurricane Katrina impacting Louisiana and Mississippi with SWAN+ADCIRC, and needs to get an accurate sense of the surge traveling up the Mississippi River.  Doing so requires specifying realistic flux boundary conditions at the upstream end of the river.  Feeling ambitious, Arturo sets NRAMP=1 and (because he has just 5 days of met. forcing) sets DRAMP=1.  His model goes unstable in the rivers.  Now feeling cautious, he first does a 30-day simulation to ramp in the river and tide forcing, with NRAMP=3, DRAMP=15 days, DRAMPExtFlux=3 days, and FluxSettlingTime=10 days.  This means the coldstart simulation runs with only river (external flux) forcing for the first 10 days, after which the tides are ramped in over 15 days, and then the model is left at full-strength forcing for another 5 days to equilibrate (10+15+5=30 days).  A hotstart file is generated at the end of the run.  Arturo uses this to hotstart his 5-day ([RNDAY](/index.php?title=RNDAY&action=edit&redlink=1)=35) storm simulation, where DUnRAMPMete=30 ensures the meteorological forcing ramping starts at the 30-day mark, and DRAMPMete=0.5 ensures a quick ramping of the meteorological forcing.  Everything works great.  He's probably been overly cautious here, and might want to play around with shortening some of the ramping times, but hey, at least it works.  ` (63); `Note that in the hotstart simulation, Arturo does not need to set any of the other values on the DRAMP line non-zero because 30-days has already passed, and so anything less than this is ignored by ADCIRC.  Furthermore, note that DRAMPWRad has been left at zero since ramping in the meteorological forcing implies that the waves, and so the wave radiation stresses, should grow slowly.` (65). |

## 판독 중 확인된 사실 (판단 아님, 후속 검토 대상)

- 39·45·63: 시간 변수 이름은 앞에서 `DUnRampMete`이고 예시에서는 `DUnRAMPMete`다.
- 43·63: `1<NRAMP<8` 조건의 설명은 모든 `DRAMP*` 항의 시간 기준을 초기 시작 시각에 `FluxSettlingTime`을 더한 것으로 적는다(43). 예시는 `NRAMP=3`, `DRAMPExtFlux=3 days`, `FluxSettlingTime=10 days`를 지정하고 최초 10일에는 하천의 외부 유량 강제력만 작용한다고 설명한다(63).
- 45·63: `DUnRampMete`를 포함한 기상 램핑 시간 기준은 `NRAMP=8` 조건에 적혀 있다(45). 예시는 초기 계산에 `NRAMP=3`을 지정하지만 재시작 폭풍 계산의 `NRAMP` 값은 적지 않는다(63).
- 23–47·63: `NRAMP`, `DRAMP*`, `FluxSettlingTime`, `DUnRampMete`, `coldstart`, `IBTYPE`, `RNDAY` 참조에는 `redlink=1`이 표시되어 있다.
