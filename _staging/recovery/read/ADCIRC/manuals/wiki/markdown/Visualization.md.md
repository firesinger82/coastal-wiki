| 1–26 | Visualization — 제목과 판본 표기를 포함한다(1–3). 격자(mesh) 설계 조정, 결과 품질 관리(QA/QC)와 계산 결과 전달에 시각화를 이용할 수 있다고 설명한다(5). 격자 높이, 절점 속성(nodal attributes), 수면 높이를 예로 든다(5). 2차원 격자의 삼각분할(triangulation)을 따라 색으로 나타내는 등치선(color contours)을 자주 사용한다고 설명한다(5). 도구별 절과 외부 링크의 목차를 포함한다(7–25). 원문: `For more general tools and utilities, see [Tools](/Tools). In the course of running ADCIRC you may wish to visualize or plot data pertaining to your model. Visualizing data can help you fine tune the mesh design, conduct QA/QC on results, and communicate key facets of the modeling to others. Examples of datasets you might plot include mesh elevation; [nodal attributes](/Nodal_attribute) such as [Manning’s n](/Manning%27s_n_at_sea_floor); or modeled results such as water surface elevation. For visualizing on a 2D flexible mesh, ADCIRC users often choose to plot them as color contours that follow the mesh triangulation. ` (5). |
| 27–56 | Plotting Considerations — 목적과 자원에 따른 도구 선택 요소를 설명한다(29). 상호작용형(interactive) 또는 정적인 그림, 자료 이동과 처리 속도를 비교한다(31–35). 입력과 출력의 자료 형식, NetCDF4의 동시 읽기와 격자 정보 포함, 학습 부담을 설명한다(37–42). 지리 좌표의 투영(projection), 표시할 파일, 사용자 작성과 즉시 실행 가능한 도구, 배경 영상과 벡터장(vector field)·도형 파일(shapefiles)·등치선 범위의 표시를 선택 요소로 제시한다(44–55). 원문: `- NetCDF vs. ASCII data – while ADCIRC mesh and nodal attributes input files must take ASCII form, outputs can be ASCII or NetCDF. Consider this since some plotting tools only work with one or the other. A few considerations:` (37); `Multiple applications can read a NetCDF4 file simultaneously, which could save considerable time if you can run your plotting tool concurrently on multiple processors within one compute node.` (38); `- NetCDF ADCIRC output files self-contain mesh node, connectivity, and boundary information.` (40); `- The learning curve to coding with netCDF files can be much steeper than ASCII.` (42). |
| 57–73 | SMS (Surface-water Modeling System) — 라이선스(license)가 필요한 GUI 기반의 상호작용형 전처리·후처리 도구라고 설명한다(59). 격자를 불규칙 삼각망(triangulated irregular network, TIN) 표면으로 표시하며 고성능 계산기(HPC)의 자료를 데스크톱으로 내려받아야 한다고 적는다(59). 특정 버전의 NetCDF 지원 상태, ASCII의 HDF5 변환, 투영과 배경 항공 영상, 벡터 자료의 형식과 도형 파일 표시 제약을 설명한다(61–72). 변환 자료의 표시 속도 비교는 원문이 일화적 보고(anecdotal reports)라고 한정한다(63). 원문: `Aquaveo’s SMS software features a suite of many GUI-based pre- and post-processing tools that allow for interactive visualization. SMS requires a license, but out of the box you can easily open and view an ADCIRC mesh and any associated data, including nodal attributes files. SMS plots mesh data as a triangulated irregular network (TIN) surface, allowing the user to change contour intervals as desired. You will need to download files from the HPC you run ADCIRC onto your desktop to plot them with SMS. A few notes about SMS: ` (59); `- ADCIRC output NetCDF support is “coming soon” as of version 12.1. SMS supports other types of NetCDF data but cannot open a *.63.nc file.` (61); `- When ADCIRC output files are opened, SMS automatically converts them from ASCII to binary HDF5 format. This format allows data to load quickly – anecdotal reports estimate this speed to be faster than the same data displayed as a TIN in ArcMap.` (63); `- supports vector overlays for fort.74-style ADCIRC data (u v format only, so you need to reformat swan_DIR.63 before displaying as vector field).` (70). |
| 74–96 | FigureGen — Fortran 프로그램과 GMT 라이브러리(library)를 이용하여 모형 자료 그림을 일괄 생성한다고 설명한다(76). 필요한 설치와 컴파일 선택, 입력 매개변수 파일로 시야 범위와 출력 시각을 지정하는 방법을 설명한다(76). 계산기에서 실행할 수 있는 점, 투영과 벡터 표시, 범위 안의 최댓값으로 등치선 상한을 정하는 기능, 해안선과 시간 막대, 파일 간 차이, 절점 속성과 해상도 설정을 설명한다(78–95). 파일 간 차이 설명의 `scalar?`와 절점 속성 예외를 원문대로 보존한다(91·93). 원문: `[FigureGen](https://ccht.ccee.ncsu.edu/figuregen-v-49/) (by Casey Dietrich of NC State) batch produces images of model data. FigureGen is a Fortran program that uses the Generic Mapping Tools (GMT) library. To use FigureGen, you must first install GMT and any of its auxiliary programs that don’t already exist on your system. These may already be installed if on a supercomputer. When you compile FigureGen, you can use flags to enable Google Earth output, NetCDF support, and parallel processing. You’ll then edit a text file of input parameters, including zoom extent and required output snaps (for time-varying ADCIRC output file), and FigureGen will generate the series of requested images. A few notes about FigureGen:` (76); `- Features options for overlaying a vector field ([fort.74](/Fort.74_file)-style data) including automatically finding the maximum vector magnitude present within the zoom extent.` (84); `Can automatically find the maximum data value present within the zoom extent to set the contour maximum.` (85); `- Can overlay a GSHHS shoreline. If your mesh includes detailed inshore waterways, this shoreline may not include sufficient resolution.` (87); `- Can plot the difference between two (scalar?) files.` (91); `- Can plot nodal attribute data (except for elemental_slope_limiter, but that is easy to add yourself)` (93); `- Can produce several types of image files, and the user can set resolution to control file size.` (95). |
| 97–120 | Kalpana — ADCIRC NetCDF 출력이나 격자 수심(bathymetry)을 도형 파일 또는 Google Earth kml로 변환하는 Python 스크립트(script)라고 설명한다(99). Matplotlib 등치선을 Fiona/Shapely 또는 Simplekml로 변환하고 값 구간을 둘러싸는 다각형(polygons)을 만든다고 설명한다(99). 사용법, 인용, 절점 속성 지원의 부재, 투영과 가상 환경(virtual environment), HPC 실행을 설명한다(101–111). 파일 크기와 생성 속도의 차이, 등치선 간격을 동적으로 바꿀 수 없는 점과 벡터장 표시를 위한 스크립트 변경을 설명한다(113–119). 원문: `[Kalpana](https://ccht.ccee.ncsu.edu/kalpana/) (by Rosemary Cyriac) produces either a shapefile or a Google Earth kml file of ADCIRC netCDF output or mesh bathymetry. Kalpana is a Python script that generates color contours using the mesh triangulation via the 2D plotting library Matplotlib, then converts the contours to either shapefile via the Fiona/Shapely libraries, or to kmz via the Simplekml library. Both the shapefile option and kml option produce polygons that enclose areas with data values that fall into one contour bin. ` (99); `- No support for plotting nodal attributes parameters yet.` (105); `- There exists a file size and speed trade-off to the two file format options – the kml option is slower to generate, but the file size is relatively small; the shapefile option generates very quickly (nearly as fast as FigureGen) but the file size is on the order of the size of the file it’s plotting. Also note that the speed of the kml generation depends on the number of lat/long bins you set up in the command line, and the number of bins depends on mesh extent and resolution.` (113); `- The shapefiles and kml files produced allow the user to zoom and pan around, but not to dynamically change contour intervals on the fly – the polygons represent an instance or a snapshot of the data.` (115); `- Neither file format supports vector fields. If you want vector fields, you should edit the Kalpana script to skip the Shapely/Fiona or Simplekml parts and use Matplotlib directly to add the vector field and save the Matplotlib plot as a png.` (119). |
| 121–134 | ArcGIS — ADCIRC 자료를 읽고 쓰는 내장 도구가 없어서 ArcPy 스크립트를 작성해야 한다고 설명한다(123). 가져온 자료를 지리 데이터베이스(geodatabase)에 넣고 격자 삼각분할로 TIN을 만드는 방법과 라이선스 비용 비교를 설명한다(123). GIS 자원, 절점 속성 지정이나 격자 높이 보간에 쓸 지리 처리 도구, 특정 버전의 netCDF4 포함, 화면 구성의 사용자 설정과 자료 다운로드 필요성을 열거한다(125–133). 원문: `Esri’s classic software contains no canned tools to read or write ADCIRC data.  The user must develop scripts to read ADCIRC files via ArcMap's integrated Python package (ArcPy). Once you’ve imported ADCIRC mesh geometry, nodal attributes, and model results data into a geodatabase, you can easily create a TIN using the mesh triangulation as hard breaklines to view your data in a similar fashion to SMS. Note that the license for ArcMap costs significantly more than an SMS license. So why the heck would you ever consider using ArcStuff for your visualization needs? ` (123); `- As of version 10.3, ArcPy includes the netCDF4 library.` (129). |
