# LISFLOOD-FP CPU·GPU SWE E 행의 배포본 이력 확인

## 1 요약

대상은 `lisflood-cpu-gpu-swe.md` §5.2에서 원 결론이 E인 32행이다. 행 수는 해당 표의 고유 행 ID로 집계했다. 판정은 정적 코드 대조이다.

아래 판정 표의 확정 결론은 E 유지 29행과 재분류 3행이다. E 유지의 강도는 강함 20행, 중간 5행, 약함 4행이다. 재분류는 C 1행과 H 2행이다. A·B·F 재분류는 각각 0행이다. E 유지 중 LG1-130·LG1-131의 2행은 8.2 결함을 8.3에서 고친 이력이다. 현재 코드에 남는 E 후보는 이 2행을 뺀 27행이다.

LG1-021은 CPU가 내부 수심 대입을 주석 처리한 배포본 변경을 근거로 C로 재분류했다. LG1-081·LG1-082는 현재 실행에서 dg2new를 호출하지 않는 근거로 H로 재분류했다. LG1-022·LG1-046·LG1-047·LG1-049는 경계·저속·건조·작은 분모의 처리 정책이라는 반대 해석을 반영하여 약함으로 낮췄다. 최대 수심 할당과 출력 정밀도 인수의 최초 발생 판은 LG1-130·LG1-133에서 해법별로 구분했다.

이 표는 원 보고서 §5의 분류 뜻을 따른다. C는 구현 간 계산 차이와 적용 제약의 설명 누락이다. H는 현재 계산 대조의 완료 조건으로 삼지 않는 항목이다. E의 강도는 실행 재현 여부가 아니라 인용한 원문 사이의 모순을 평가한다.

현재 코드 인용의 기준 경로는 `models/LISFLOOD-FP/raw/source_code/LISFLOOD-FP/`이다. `v8.0:`의 기준 경로는 `_staging/recovery/extract/LISFLOOD-FP/external/v8.0/LISFLOOD-FP-trunk/`이다. `v8.1:`의 기준 경로는 `_staging/recovery/extract/LISFLOOD-FP/external/v8.1/LISFLOOD-FP-trunk/`이다. `v8.2:`의 기준 경로는 `_staging/recovery/extract/LISFLOOD-FP/external/v8.2/LISFLOOD-FP/`이다. `v8.3:`의 기준 경로는 `_staging/recovery/extract/LISFLOOD-FP/external/v8.3/LISFLOOD-FP-8.3/`이다. 접두어 없는 `lisflood-8.2-to-8.3.patch:`는 이 8.3 배포본의 패치이다. “처음”은 제공된 네 배포본 중 가장 이른 판을 뜻한다.

각 행의 이력 검색은 네 판의 `VersionHistory.h`, 8.3 `README.md`, 8.3 패치를 대상으로 했다. 검색어는 해당 함수·필드 이름과 `FV1`, `DG2`, `CUDA`, `friction`, `limiter`, `rain`, `mass`, `fixed`, `depth`, `initial`, `drain`, `ghost`, `precision`, `point`, `boundary`, `OpenMP`이다. `v8.0:VersionHistory.h:27`은 `8.0  Jul 24 2020  FV1 and DG2 Solvers added (JS)`를 적는다. `v8.1:VersionHistory.h:27`과 `v8.2:VersionHistory.h:27`은 각각 `8.1  Nov 23 2020  Merged changes from v7.1 (d8subgrid) into v8 (PFU)`를 적는다. 현재 `VersionHistory.h:31`은 `8.3  Oct 07 2026  CUDA: max-depth grid on the GPU (large grids run), dry NoData cells skip`을 적는다. 다음 줄 `VersionHistory.h:32`는 `the mass counter, flux kernels synchronised; Metal FV1 back end (HR)`를 적는다. 각 행은 이 일반 기록과 해당 문제의 수정 기록을 구분한다.

기본 CMake 설정은 `CMakeLists.txt:10` `set(_CONFIG config.default.cmake CACHE FILEPATH "CMake config file")`이다. 기본 수치 형식은 `config.default.cmake:2` `add_compile_definitions(_NUMERIC_MODE=1)`이다. CUDA 경로는 `CMakeLists.txt:73` `if (CMAKE_CUDA_COMPILER)`와 `CMakeLists.txt:77` `add_compile_definitions(CUDA THRUST_IGNORE_CUB_VERSION_CHECK)`의 조건을 따른다. Metal 경로는 `CMakeLists.txt:232` `if (APPLE)`와 `CMakeLists.txt:234` `if (METAL_ENABLED)`의 조건을 따른다. 실제 Metal 선택 조건은 `lisflood.cpp:782` `if (Statesptr->cuda == ON && metal_is_available())`이다. 각 행의 수식 차이를 `_NUMERIC_MODE`에 따른 의도된 변경으로 간주하려면 해당 식의 전처리 분기가 있어야 한다.
