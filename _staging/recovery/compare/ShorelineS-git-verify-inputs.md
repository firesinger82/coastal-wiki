## 1 요약

이 파일은 AI가 작성한 git 이력 대조 기록이다. 백틱 안의 코드와 커밋 메시지는 원문이다. 판정과 노트 문장은 이 원문에 대한 분석이다.

대상은 `ShorelineS-inputs-vs-code.md` 5절의 고유 행 ID 54개다. 원 분류는 A 1행, E 19행, D 34행이다.

2절의 원 A 행에서 A 확정은 1행이다. 원 A 행의 재분류는 0행이다.

3절의 E 유지는 19행이다. E 유지의 강함은 16행이다. E 유지의 중간은 3행이다. E 행의 재분류는 0행이다.

4절의 D 확정은 17행이다. D에서 A로 재분류한 행은 17행이다. 2절과 4절을 합친 최종 A는 18행이다.

집계 단위는 행 ID다. 같은 코드 원인을 가진 매개변수·예제·노트 행도 각각 센다.

코드 인용의 기준 저장소는 `models/ShorelineS/raw/source_code/shorelines/`다. 기준 HEAD는 `f3ec8638 2026-08-13 Create ShorelineS_manual_v1.0.pdf`이다. `git rev-list --count HEAD`의 결과는 47이다.

FAQ 날짜 직전 커밋은 `1f74031f 2020-03-11 Add files via upload`이다. 매뉴얼 날짜 직전 커밋은 `0894269e 2024-09-25 Update transport.m`이다. 날짜 경계는 각각 2023-10-01 00:00 UTC와 2024-10-15 00:00 UTC로 고정했다.

각 E 행의 blame 결과는 현재 줄의 마지막 수정 커밋을 보여 준다. 도입 설명은 이전 이름의 같은 동작까지 추적한다. D의 A 재분류는 과거 소비 코드의 삭제 또는 입력명 교체를 기준으로 한다. 후처리 보조 함수의 삭제 행도 이 기준을 적용한다.

코드 원문은 `git show REV:functions/X.m | iconv -f latin1 -t utf8 | sed -n 'N,Mp'`와 같은 ISO-8859-1 해석으로 읽었다. 인용은 줄 바깥의 들여쓰기와 끝 공백만 제거했다. 표 안의 수직선은 Markdown 이스케이프를 적용했다.
