# LISFLOOD-FP 빌드 구성과 8.3 릴리스

## 1. 적용 판

현재 원자료는 8.3(8.2 + 공식 패치)이다([build-83:LN1-230 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LN1.md)).
Zenodo 8.2의 DOI는 `10.5281/zenodo.13121102`이다([8.3 배포 설명](../raw/source_code/LISFLOOD-FP-8.3-package/README.md), `README.md:19–24`).
공식 8.3 패키지는 8.2에 적용할 패치를 제공한다([8.3 배포 설명](../raw/source_code/LISFLOOD-FP-8.3-package/README.md), `README.md:19–24`; [LB1-408 최종 출처 판정](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LB1b.md)). [10-21 전수 검증 정정]
릴리스 표시 이름은 8.3이다(`VersionHistory.h:23`).
체크포인트의 내부 숫자 판은 8.1.0을 유지한다(`VersionHistory.h:16–22`).

## 2. 빌드 구성

현재 소스 빌드 명령은 `cmake -S . -B build`와 `cmake --build build`이다(`README.md:29–30`).
CMake는 `_CONFIG`로 지정한 설정을 읽는다(`CMakeLists.txt:10–11`).
기본 `_NUMERIC_MODE=1`은 double이다(`config.default.cmake:2`; `lisflood.h:75–97`).
`_NUMERIC_MODE=0`은 float이다(`lisflood.h:75–97`).
기본 `_ONLY_RECT=1`은 Fast SGC의 직사각형 분기를 선택한다(`config.default.cmake:3`; `lisflood2/sgm_fast.cpp:142–149`).
기본 `_CALCULATE_Q_MODE=1`은 Fast CalculateQ의 Froude 상한을 포함한다(`config.default.cmake:6`; `lisflood2/sgm_fast.cpp:74–92`). [10-21 전수 검증 정정]
기본 SGC는 행 처리와 고정 부하 분배를 사용한다([bridge-docx:LB1-265 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LB1b.md)).

NUMA 탐색 힌트 변수는 `NUMA_ROOT_DIR`이다(`cmake/Modules/FindNUMA.cmake:8–14`).
NUMA 요구 조건은 `if (UNIX AND NOT APPLE)`이다(`CMakeLists.txt:204–208`).
NetCDF 연결 조건은 `if (_NETCDF)`이다(`CMakeLists.txt:210–224`).
`dynamicrainfile`은 `_NETCDF=0`에서 종료한다(`pars.cpp:999–1002`).
`netcdf_out`의 미지원 격자는 `write_grid`에서 ASCII로 대체한다(`lisflood2/file_tool.cpp:763–791`).
v8.2 이후 CUDA 아키텍처 기본값은 `if(NOT DEFINED CMAKE_CUDA_ARCHITECTURES)` 안의 `set(CMAKE_CUDA_ARCHITECTURES 61)`로 설정한다(`CMakeLists.txt:4–6`).

실제 옛 make 파일 이름은 소문자 `makefile`이다(`makefile:1`; `INSTALL.md:3`).
INSTALL의 `Makefile.new`는 파일명 오기이다([build-83:LN1-017 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LN1.md)).
옛 makefile의 CUDA 목록은 현재 CUDA 진입점이 참조하는 모든 해법을 연결하지 않는다(`makefile:53–85,104–122`; `lisflood.cpp:419–459`).
이 결함 후보는 make의 `ifdef CUDA`가 활성인 구성에 한정하며 강도는 강함이다([build-83:LN1-101 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LN1.md)).
CMake는 주 실행 파일 외에 `generateDG2DEM`·`generateDG2start`·`DG2downscale`을 만든다(`CMakeLists.txt:190–197`).
`TESTING`은 소스에 있지만 제공된 빌드 파일은 이 매크로를 정의하지 않는다([build-83:LN1-084 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LN1.md)).

## 3. 8.2 결함과 8.3 변경

CUDA 최대 수심 배열의 크기·초기화 문제는 8.2 결함이며 8.3에서 고쳤다([cpu-gpu-swe:LG1-130 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LG1.md)).
8.3은 `maxH = GhostRaster::allocate_device(geometry);`로 전체 크기의 device 배열을 만든다(`cuda/cuda_max_field.cu:97`).
8.3은 `cudaMemset(maxH, 0, lis::GhostRaster::elements(geometry)*sizeof(NUMERIC_TYPE));`로 초기화한다(`cuda/cuda_max_field.cu:98`).
최대 수심은 출력 시 host로 복사한다(`cuda/cuda_max_field.cu:117–130`).
FV1·FV2·DG2의 반복 패스 끝 공유 배열 보호 누락은 8.2 결함이며 8.3에서 고쳤다([cpu-gpu-swe:LG1-131 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LG1.md)).
8.3은 각 방향의 패스 끝에 `__syncthreads();`를 추가했다(`cuda/fv1/cuda_fv1_solver.cu:380–381,475–476`; `cuda/dg2/cuda_dg2_solver.cu:285–286,375–376`; `cuda/fv2/cuda_fv2_solver.cu:241–242,322–323`).
8.3의 NoData 배수는 `if (Hold == C(0.0)) continue; // dry: nothing to add to the mass balance`를 추가했다(`cuda/cuda_boundary.cu:284–293`).
양의 dt에서 이 변경은 마른 셀의 0 질량 가산을 생략한다([cpu-gpu-swe:LG1-132 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LG1.md)).
젖은 셀의 배수식은 그대로다([동일 근거 LG1-132](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LG1.md)).
v8.2 루트의 `format` 파일은 macOS에서 C++ 표준 헤더 이름을 가리는 빌드 결함이었다([build-83:LN1-127 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-claude-final.md)).
8.3 패치는 이 파일을 삭제한다([동일 근거 LN1-127](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-claude-final.md)).

8.3은 Apple Metal FV1을 포함한다([build-83:LN1-231 최종 근거](../../../_staging/recovery/compare/LISFLOOD-FP-conclusion-verify-LN1.md)).
Apple 빌드의 `if(METAL_FRAMEWORK AND FOUNDATION_FRAMEWORK)` 안에서 `METAL_ENABLED`를 정의한다(`CMakeLists.txt:231–237`; `metal/CMakeLists.txt:3–6,29–34`). [10-21 전수 검증 보완]
CUDA와 Metal 실행 매크로가 모두 없으면 GPU 요청을 거부한다(`pars.cpp:1080–1086`).
