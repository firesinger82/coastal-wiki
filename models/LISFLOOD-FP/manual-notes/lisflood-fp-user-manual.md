## 1. 모델 개요와 솔버 선택 (p.10–12)

raster 기반 침수 모델. 1D 채널(kinematic/diffusive/subgrid) + 2D 범람원(storage-cell) 결합. 표준 SI 단위는 길이 m와 시간 s를 사용한다(user manual.pdf p.12). 체적유량은 m³/s이다. 고전 ACC의 단위폭 유량과 일부 범람원 Q 경계 입력은 m²/s이다. `Q=q\Delta x`로 변환한다. (user manual.pdf p.12·26; `fp_acc.cpp:41·88`; `iterateq.cpp:500–501`) [10-21 대조 정정]

### 1.1 범람원(floodplain) 솔버 — Table 1 (p.10)

| 솔버 | 차원 | 포함 SWE 항 | 무시 항 | time step | 참고 |
|---|---|---|---|---|---|
| Routing | 1D on 2D grid | 사용자 지정 속도·bed slope 방향만 | 전부 | Adaptive | Sampson et al., 2012 |
| Flow-limited | 1D on 2D grid | friction·water slope | local·convective accel | Fixed | Bates & De Roo, 2000 |
| Adaptive | 1D on 2D grid | 위와 동일 | 위와 동일 | Adaptive | Hunter et al., 2005 |
| Acceleration | 1D on 2D grid, friction 2D | friction·water slope, local accel | convective accel | Adaptive | Bates et al., 2010; De Almeida et al., 2012 |
| Roe | 2D | 전체 항 | 없음 | Adaptive | Neal et al., 2012b |

- **Routing**: 문서는 얕은 수심 또는 경사 >0.1에서 사전 계산 방향맵으로 최저 인접셀에 고정 속도 흐름을 적용한다고 적는다(user manual.pdf p.11). 8.0 이전 판(PDF 표지 6.1.1·머리글 5.9.6) 기준, 그 판 코드는 배포본이 없다. 문서는 경사 >0.1을 적는다. 현재 고전 Routing은 `if(h0<Solverptr->DepthThresh || Sfy>=Parptr->RouteSfThresh || Sfx>=Parptr->RouteSfThresh)`를 검사한다. 수심 문턱의 기본값은 0.001 m이다. (user manual.pdf p.11·16; `infevap.cpp:367–376`; `v8.0:infevap.cpp:367–376`; `VersionHistory.h:138–139`) [10-21 대조 정정]
- **Acceleration**(inertial): convective accel만 무시한다. 공간 이산화는 1차다. 시간 적분은 explicit이다. 마찰은 semi-implicit이다(user manual.pdf p.11). 문서의 `1/\Delta t`는 오기이다. 코드는 `if(MH > Solverptr->DepthThresh)`에서 `locT=cfl*Parptr->dx/(sqrt(g*MH));`를 계산한다. 이 CFL 상한은 고정 수심에서 셀 크기에 선형이다. 이 조건을 통과하지 않으면 `Solverptr->Tstep=Solverptr->InitTstep;`로 지정한다. 문서의 계산 시간 절감은 가능성 주장이다. (user manual.pdf p.11; `fp_acc.cpp:249–276`) `fp_acc.cpp:271`의 원문은 `locT=cfl*Parptr->dx/(sqrt(g*MH));`이다. [10-21 대조 정정] [10-21 전수 검증 정정]
- **Roe**: Godunov + Roe 근사 Riemann 해법으로 full SWE를 계산한다(user manual.pdf p.11). Roe의 외곽 경계와 내부 벽을 구분한다. 고전 내부 벽은 `Roe_slow` 옵션에 따라 다른 분기를 사용한다. (user manual.pdf p.11; `fp_trent.cpp:301–305`; `pars.cpp:410–428`; `VersionHistory.h:214`) 문서는 테스트 케이스가 제한적이며 덜 robust할 수 있다고 경고한다(user manual.pdf p.11). [10-21 대조 정정]

### 1.2 채널(channel) 솔버 — Table 2 (p.10–11)

| 솔버 | 차원 | 포함 | 무시 | 참고 |
|---|---|---|---|---|
| Kinematic | 1D | friction slope + bed gradient(dz/dx)만 | local·convective accel, 자유표면 gradient(dh/dx) | Bates & De Roo, 2000 |
| Diffusive | 1D | friction slope + bed·자유표면 gradient (d[z+h]/dx) | local·convective accel | Trigg et al., 2009 |
| Sub-grid channel | 1D | friction·water slope, local accel | convective accel | Neal et al., 2012a |

1D 채널은 bankfull 도달 시 인접 범람원 셀로 routing — **질량만 전달, 운동량 전달 없음** (p.12). full 1D SWE 운동량/연속식은 식(1)(2) (p.10):

PDF 식 (1)의 인쇄식: `\underbrace{\frac{\partial Q_x}{\partial t}}_{\text{local accel}} + \underbrace{\frac{\partial}{\partial x}\!\left(\frac{Q_x^2}{A}\right)}_{\text{convective accel}} + \underbrace{gA\,\frac{\partial(h+z)}{\partial x}}_{\text{water slope}} + \underbrace{\frac{gn^2 Q_x^2}{R^{4/3}A}}_{\text{friction slope}} = 0` (user manual.pdf p.10). [10-21 대조 정정]

PDF 식 (2)의 인쇄식: `\frac{\partial A}{\partial x} + \frac{\partial Q_x}{\partial x} = 0` (user manual.pdf p.10). [10-21 대조 정정]

정정 연속식: `\frac{\partial A}{\partial t} + \frac{\partial Q_x}{\partial x} = 0` (`ch_flow.cpp:807–809`). [10-21 대조 정정]

문서의 마찰항은 정방향에서만 코드의 부호 있는 마찰과 같다. 역류를 포함한 마찰 저항에는 `Q_x\lvert Q_x\rvert`가 필요하다(user manual.pdf p.10 식 (1); `ch_flow.cpp:843–847`; `sgc.cpp:824–844`). [10-21 대조 정정]

Word 변환본에는 식 본체가 인쇄되지 않았다. PDF 식은 1D 이론식이다. 이 2D 코드의 항을 Word 원문으로 복원하지 않는다. (user manual.docx p.13(변환본) 식 (1); user manual.pdf p.10 식 (1); `swe/flux.cpp:50–52`; `v8.0:swe/flux.cpp:50–52`) PDF는 시간 변화 항의 분모를 공간 좌표로 적었다. 첫 항의 단위와 두 번째 항의 단위도 다르다. Word의 보이지 않는 식을 PDF 오기의 정정으로 간주하지 않는다. (user manual.docx p.13(변환본) 식 (2); user manual.pdf p.10 식 (2); `ch_flow.cpp:408–412`; `v8.0:ch_flow.cpp:409–412`) [10-21 대조 정정]

여기서 `Q_x`=x방향 유량, `A`=흐름 단면적, `h`=수심, `z`=하상고, `n`=Manning's n, `R`=수리반경 (user manual.pdf p.10). [10-21 대조 정정] [10-21 전수 검증 정정]

### 1.3 주요 한계 (p.12–13)

- kinematic/diffusive: 채널 단면을 직사각형 단순화, wide-and-shallow 가정(wetted perimeter≈width) (p.12).
- 1D↔범람원 운동량 교환 없음, 측방 friction 무시 (p.12).
- flow-limited은 파속 과소·정확도 낮음 → 비교 실험용만. adaptive는 고해상도에 계산비용 과다 (p.12).
- Roe 제외 전 솔버: 매우 낮은 Manning's n / 높은 Froude에서 파속 과소(de Almeida & Bates 2013). acceleration은 낮은 n에서 불안정 → numerical diffusion 항 필요 (p.12–13).
- routing: `depththresh` > 10 mm 설정 시 불안정 가능 (p.13).

## 2. parameter file (.par) — 일반 규칙 (p.15)

- 8.0 이전 판(문서 표지 6.1.1·머리글 5.9.6) 기준, 그 판 코드는 배포본이 없다. PDF는 대소문자를 구분한다고 적는다. 현재 공통 파서는 키워드 대소문자를 구분하지 않는다. 적응격자 재독 파서는 대소문자를 구분한다. (`pars.cpp:56`; `lisflood.h:99–107`; user manual.pdf p.1,15; `cuda/adaptive/input/read_keyword_real.cpp:29`) 8.0 이전 판(Word의 기존 판 이력 5.9·본문 머리글 5.9.6) 기준, 그 판 코드는 배포본이 없다. 기존 문서는 par 항목이 대소문자를 구분한다고 적는다. v8.0 이후의 par 키워드 판독기는 `STRCMPi`로 대소문자를 무시한다. 파일 이름을 찾는 OS 규칙은 별도다. (user manual.docx p.1·5·19(변환본); user manual.pdf p.15; user manual +bridge.docx p.21(변환본) 쪽 이미지; `v8.0:pars.cpp:54–56`; `v8.0:lisflood.h:99–106`; `v8.1:pars.cpp:56,77,95,110,126`; `pars.cpp:54–56,124–131`; `lisflood.h:99–106`) [10-21 대조 정정]
- 인식 안 되는 항목은 에러 없이 무시. 키워드 미기재 시 코드 내장 기본값 사용.
- v8.0에서 추가한 FV1·DG2의 옵션은 읽기 순서에 영향을 받는다. 공통 파서는 줄을 읽는 순서대로 상태를 바꾼다. 해법 키워드 뒤에 해당 해법의 매개변수를 둔다. 줄의 첫 글자가 #이면 주석이다. (`pars.cpp:582–586,973–979`; user manual.pdf p.1,15; `VersionHistory.h:34`; `pars.cpp:1110–1138`) v8.0에서 추가된 FV1 선택은 cfl과 depththresh를 다시 대입한다. 현재 코드에서 두 값을 재정의하려면 fv1 뒤에 둔다. limitslopes도 DG2·FV2·MWDG2 선택 뒤에 둔다. (user manual.docx p.19(변환본); user manual.pdf p.15; `pars.cpp:582–587·974–982`; `v8.0:pars.cpp:571–583`; `VersionHistory.h:34`) DG2의 추가 수심·시간 간격 설정과 해법 검사다. DG2 선택보다 먼저 적으면 중단할 수 있다. (user manual.docx p.19–26(변환본) 표 4–6; user manual.pdf p.15–21 표 4–6; `pars.cpp:630–636·708–726`) [10-21 대조 정정]
- 솔버 선택 키워드를 **아무것도** 안 넣으면: 채널=1D kinematic, 범람원=2D adaptive (Table 6 캡션, p.16). 8.0 이전 판(문서 표지 6.1.1·머리글 5.9.6) 기준, 그 판 코드는 배포본이 없다. 옛 표의 All models는 v8.0에서 추가한 FV1·DG2와 현재 8.3의 모든 해법에 적용하지 않는다. (user manual.pdf p.15–21; `VersionHistory.h:34`; `lisflood.cpp:417–451,773–793`; `v8.0:pars.cpp:571–574`; user manual.pdf p.1) [10-21 대조 정정]

## 3. 입력 파일 형식 (p.15–32)

파일 확장자는 강제하지 않는다(user manual.pdf p.15). user manual.pdf p.15의 .par에만 주석을 쓸 수 있다는 문장은 p.32의 강우 파일 설명과 모순된다. 현재 강우·증발 로더는 첫 설명 줄을 건너뛴다. 자료 구간은 `if (line_len == 0 || line_buffer[0] == '#')`에서 건너뛴다. 개행만 있는 자료 줄을 항상 허용한다는 뜻은 아니다. (user manual.pdf p.15; `pars.cpp:1119–1121`; `input.cpp:1869–1872,1993–1995,2134,2154`; user manual.pdf p.32; `input.cpp:1848–1917`) 8.0 이전 판(문서 표지 6.1.1·머리글 5.9.6) 기준, 그 판 코드는 배포본이 없다. PDF는 대소문자를 구분한다고 적는다. 현재 공통 파서는 키워드 대소문자를 구분하지 않는다. 적응격자 재독 파서는 대소문자를 구분한다. (`pars.cpp:56`; `lisflood.h:99–107`; user manual.pdf p.1,15; `cuda/adaptive/input/read_keyword_real.cpp:29`) [10-21 대조 정정]

### 3.1 채널 파일 (.river) (p.22–24)

채널 중심선 벡터를 raster에 보간. 한 DEM 셀에 벡터점 ≤1, 도메인 경계 밖 점 ≤1 (p.22). 각 점에 width·n·bed elevation. 형식:

```
Line 1: Tribs <채널 세그먼트 수>   (생략 시 단일 reach)
Line 2: <벡터 데이터 점 수 i>
Line 3: X1 Y1 Width1 n1 BedElev1 BC Value   (첫 점에 유입 BC 필수)
Line k: Xk Yk [Widthk nk BedElevk] [Lateral inflow]   (중간점 width/n/bed는 선택)
```

- 유입 BC: `QFIX <값>`(정상 유입 m³s⁻¹) 또는 `QVAR <식별자>`(시변, .bdy 참조) (p.23).
- lateral inflow: reach 임의 점에 source 항으로 소규모 지류 (p.23).
- kinematic은 하류 bed slope가 음(내리막)이어야 — 오르막이면 경고 후 내리막 취급. diffusive는 오르막 허용 (p.23).
- **Tributary**: main stem이 segment 0. 합류점에서 `Trib <세그먼트번호>`, 각 지류 마지막 점에 `QOUT <합류 세그먼트>` (p.23–24).
- **Diffusive 채널 하류 BC**(kinematic과 달리 필수): `FREE [slope]`(normal depth, slope 생략 시 마지막 두 단면 기울기 사용/지정이 더 안정), `HFIX <고도 m>`(정상 수위), `HVAR <식별자>`(시변) (p.24).

### 3.2 다중 비연결 채널 (.rivers) (p.25)

`multiriverfile` 키워드로 읽힘. 1행=.river 개수, 이후 각 .river 파일명. 같은 main stem 지류망엔 불필요(.river 하나로 처리), 서로 다른 main stem river가 한 도메인에 있을 때만 필요.

### 3.3 경계조건 타입 파일 (.bci) (p.25)

채널과 무관한 경계조건이다. 외곽 N·E·S·W는 시작·끝 축 좌표를 받는다. P·F는 x·y 점 좌표를 받는다. 뒤 필드는 조건 종류와 수치 또는 시계열 이름이다(user manual.pdf p.25–26; `input.cpp:1582,1632,1646–1649,1661–1662,1720`; [입출력 보고서 수정안](../../../_staging/recovery/compare/lisflood-files-output-vs-code.md#4-노트-대조와-수정안), LI2-027–028). [10-21 대조 정정]

| BC 타입 | 설명 | 5열 값 (Table 12, p.25) |
|---|---|---|
| `CLOSED` | zero-flux (기본) | 없음 |
| `FREE` | uniform flow | free surface/valley slope (선택) |
| `HFIX` | 고정 수면 고도 | 고도(m) |
| `HVAR` | 시변 수면 고도 | .bdy 식별자 |
| `QFIX` | 고정 유입 | 단위폭당 mass flux(m²s⁻¹); 경계 segment는 길이, point source는 셀폭 곱해 m³s⁻¹. latlong 시 m³s⁻¹ |
| `QVAR` | 시변 유입 | .bdy 식별자 |

### 3.4 시변 경계조건 파일 (.bdy) (user manual.pdf p.26–27) [10-21 대조 정정]

QVAR/HVAR용 형식은 1행 설명, 2행 식별자, 3행 `<시점 수> <단위 days/hours/seconds>`, 이후 `Value Time` 쌍이다(user manual.pdf p.26–27). HVAR는 수면고도(m)다. QVAR는 .river에서 m³s⁻¹다. QVAR는 latlong이 꺼져 있으면 .bci에서 m²s⁻¹다. latlong이 켜져 있으면 .bci에서도 m³s⁻¹다(user manual.pdf p.26–27). 분 단위는 5.9.25에 추가되었다. v8.0과 현재 코드는 minutes와 단수 minute를 모두 지원한다. days를 부정하는 문서 오기와 구분한다. (user manual.pdf p.26–27; `VersionHistory.h:107`; `v8.0:input.cpp:1891–1893`; `input.cpp:1920–1922`) [10-21 대조 정정] [10-21 전수 검증 정정]

문서는 누락 이름을 zero-flux로 처리한다고 적는다(user manual.pdf p.27). bdy 파일을 지정하지 않은 로더 경로만 누락 시계열을 비활성화한다(`input.cpp:2080–2116`). 존재하는 bdy에서 참조한 이름을 빠뜨리면 경계 시계열이 NULL로 남는다. 해당 경계의 보간은 NULL을 역참조하는 결함 후보이다. 강도는 강함이다. (user manual.pdf p.27; `input.cpp:1953–1978,2020–2057,2080–2116`; `boundary.cpp:283,1422–1429`) [10-21 대조 정정]

시각은 엄격히 증가해야 한다. 자료 부족은 중단한다. 알 수 없는 시간 단위는 경고 후 초로 취급한다. (user manual.pdf p.26–27·31–32; `input.cpp:1889–1931`) 첫 시각 전은 첫 값이다. 마지막 시각 이후는 마지막 값이다. (user manual.pdf p.26–27; `boundary.cpp:1432–1444`) [10-21 대조 정정]

### 3.7 Weir·Bridge 파일 (.weir) (p.29–30)

방향 태그가 보와 교량을 구분한다. Weir 형식은 `X Y Direction C CrestHeight ModularLimit [Width]`다. 문서의 보 방향 태그는 N/E/S/W다. 단방향 태그는 NF/EF/SF/WF다. 문서의 보 계수 전형 범위는 0.5–1.7이다. 표준 광정 위어의 전형 계수는 1.4다. modular limit의 전형값은 0.9다(user manual.pdf p.29). 파서는 보 계수와 modular limit를 입력 열에서 읽는다. 폭만 생략할 수 있다. 폭을 생략하면 grid 크기를 쓴다. (user manual.pdf p.29–30·40; user manual +bridge.docx p.29·32(변환본); `input.cpp:161–163`) Bridge 형식은 `X Y Direction Cd SoffitElev TransitionZone Width`다. 교량 방향 태그는 nb/eb/sb/wb다. 문서의 교량 Cd 전형값은 0.8이다. 전이 구간 상한의 전형값은 1.5다. 두 값은 입력값이다. 교량은 subgrid에 적용한다(user manual.pdf p.30). latlong에서는 bridge 입력의 X·Y가 도 단위이다. DEM 헤더 필드를 bridge 행 필드로 설명하지 않는다. (user manual.pdf p.29–30; `input.cpp:161–166`) [10-21 대조 정정] [10-21 전수 검증 정정]

8.0 이전 판(머리글 5.9.6, 표지 6.1.1) 기준, 그 판 코드는 배포본이 없다. 현재 구조물 태그 W·E·N·S는 각각 입력 셀의 동·서·남·북 면에 배치된다. 코드 주석은 기준 셀로 유입하는 방향을 사용한다. (user manual.pdf p.1–2·29–30; `input.cpp:175–246,254–273,2345–2349`; `weir_flow.cpp:50–55,97`) 교량의 지원 범위는 SGC이다. 고전 CPU x 교량 분기에는 y 분기의 `Statesptr->SGC == ON` 검사가 없다. 비SGC 교량 입력에 대한 방어 누락 후보이다. 강도는 중간이다. (user manual.pdf p.30; `input.cpp:225–248`; `fp_flow.cpp:47,95`; `weir_flow.cpp:109–136,267`) [10-21 대조 정정]

지반 아래 보 마루에서 -v가 보정 여부까지 바꾸는 결함 후보이다. `Arrptr->Weir_hc[i] = getmax(z0, z1);`는 verbose 조건 안에 있다. 강도는 강함이다. (user manual.pdf p.34; `input.cpp:251–252,279–291`) [10-21 대조 정정]

### 5.3 Checkpointing (p.34–35)

checkpoint 형식 번호가 다르면 해당 파일의 상태를 읽지 않고 처음부터 시작한다. LISFLOOD 버전 번호만 다르면 읽기를 계속한다. 그 버전 경고는 `if(verbose == ON)`에서 출력한다. 격자 치수가 다르면 `exit(0);`으로 종료한다. PDF의 endian 설명은 다른 바이너리 규약에서 실패할 수 있다는 조건부 설명이다. (user manual.pdf p.35–36; `VersionHistory.h:295–298`; `chkpnt.cpp:93–109,122–143`) [10-21 대조 정정]

체크포인트 지원은 driver별로 적는다. 고전 CPU의 반복 체크포인트는 checkpoint가 켜진 상태에서 계산시간 기준을 만족하면 기록된다. main의 최종 공통 저장은 `if (SimStates.checkpoint == ON)`일 때 호출된다. CUDA 분기는 main의 최종 공통 저장 전에 반환한다. acc_nugrid에는 별도의 `write_chkpnt` 호출이 있다. lisflood2의 반복 WriteCheckpoint 블록은 주석 처리되어 있다. 공통 writer는 H·Qx·Qy·maxH·maxHtm·initHtm을 쓴다. totalHtm 저장 조건은 `if(checkv>1)`이다. 현재 LF_CheckVersion 0에서는 이 배열을 쓰지 않는다. 공통 writer는 Qxold·Qyold·SWE 운동량·DG2 계수를 쓰지 않는다. 지원하지 않는 상태가 복구된다고 쓰지 않는다. (user manual.pdf p.36; user manual +bridge.docx p.36(변환본) 쪽 이미지; `bf804e23:models/LISFLOOD-FP/source-analysis/lisflood-fp-io-boundary.md:132–134`; `iterateq.cpp:309–320`; `lisflood.cpp:419–457,809–810`; `chkpnt.cpp:211–314`; `lisflood2/sgm_fast.cpp:4600–4611`; `cuda/acc_nugrid/cuda_acc_nugrid_simulate.cu:700–714`; `VersionHistory.h:19`) [10-21 대조 정정] [10-21 전수 검증 정정]

현재 checkpoint 판 0은 총 침수 시간과 침투·증발 누적 손실을 저장하지 않는다. 재시작의 모든 진단 누계가 연속이라는 뜻으로 쓰면 안 된다. (user manual.docx p.37,40(변환본); user manual.pdf p.32,36; `VersionHistory.h:19`; `chkpnt.cpp:143,254,283–286`) [10-21 대조 정정] [10-21 전수 검증 정정]

최종 체크포인트 결함 후보의 근거 강도는 강함이다. classic CPU의 `IterateQ`는 종료 출력에서 `if (Arrptr->maxH[ptr]>1e-3) Arrptr->maxH[ptr] += Arrptr->DEM[ptr]; else Arrptr->maxH[ptr] = NULLVAL;`을 실행한다. 반환 뒤 `if (SimStates.checkpoint == ON)`이면 바뀐 maxH를 최종 checkpoint에 저장한다. 재시작은 이 배열을 최대 수심으로 읽는다. 반복 중 checkpoint는 이 종료 변환보다 먼저 기록한다. (user manual.docx p.37·40(변환본); user manual.pdf p.32·35; `iterateq.cpp:203–205·449–477`; `lisflood.cpp:773–810`; `chkpnt.cpp:140·251`; `v8.0:iterateq.cpp:469`; `v8.1:iterateq.cpp:469`; `v8.2:iterateq.cpp:469`) [10-21 대조 정정]

기본 빠른 SGC는 공통 checkpoint 배열을 해제하고 NULL로 만든다. checkpoint가 켜진 최종 writer는 NULL 배열을 사용하는 결함 후보이다. RESULT_CHECK를 정의한 빌드는 이 해제 조건에서 제외된다. 강도는 강함이다. (user manual.pdf p.35–36; `lisflood.h:59–64`; `config.default.cmake:1–8`; `lisflood2/lisflood_processing.cpp:1536–1572,2092–2122`; `utility.cpp:43–50`; `lisflood2/sgm_fast.cpp:4601–4611`; `lisflood.cpp:773–775,810`; `chkpnt.cpp:248–251`) [10-21 대조 정정]

8.0 이전 판(머리글 5.9.6, 표지 6.1.1) 기준, 그 판 코드는 배포본이 없다. 현재 dirroot가 있으면 기본 체크포인트도 결과 디렉터리에 둔다. (user manual.pdf p.15·18·35; `lisflood.cpp:332,379–380`) 일반 CPU는 mass 출력 시점에 계산 경과시간을 검사한다. 첫 검사도 저장을 일으킬 수 있다. (user manual.pdf p.35; `lisflood.cpp:123`; `iterateq.cpp:212,309–320`; `chkpnt.cpp:223`) [10-21 대조 정정]

기능 이름은 checkpointing이다. par 키워드는 checkpoint다(user manual.pdf p.32·35; `pars.cpp:563–568`). [10-21 대조 정정]

### 5.5 Weir·Bridge 계산식 (user manual.pdf p.40–42; user manual +bridge.docx p.29–32(변환본)) [10-21 대조 정정]

- 8.0 이전 판(PDF 표지 6.1.1·머리글 5.9.6) 기준, 그 판 코드는 배포본이 없다. 문서 식 (5)는 `Q=CL(2gH)^{1.5}`이다. 현재 자유월류 식은 `Q=Arrptr->Weir_Cd[weir_id]*Arrptr->Weir_w[weir_id]*pow(hu,(C(1.5)));`이다. 현재 파서는 `Cd=1.4`를 생략 기본값으로 대입하지 않는다. (user manual.pdf p.29·40; `weir_flow.cpp:83–88`; `input.cpp:161–163`; `v8.0:weir_flow.cpp:85–88`; `v8.0:input.cpp:161–163`) 실제 수두는 마루 위 수면 높이다(user manual.pdf p.40; `weir_flow.cpp:69–88`). user manual.pdf p.40·user manual +bridge.docx p.29(변환본)의 인쇄식은 `Q = CL(2gH)^{1.5}`이다. 현재 자유 월류 식은 `Q=Arrptr->Weir_Cd[weir_id]*Arrptr->Weir_w[weir_id]*pow(hu,(C(1.5)));`이다. 입력 계수에 `(2g)^{1.5}`를 흡수하는 변환은 없다. 접근속도수두 차이와 계수 차이를 따로 적는다. 8.0 이전 판(6.1.1) 기준, 그 판 코드는 배포본이 없다. (user manual.pdf p.1·29·40; user manual +bridge.docx p.29–30(변환본); `weir_flow.cpp:69–88`; `lisflood2/sgm_fast.cpp:535–566`; `input.cpp:161–163`; `VersionHistory.h:493`) [10-21 대조 정정]
- 교량 식 (6): `Q = C_d A(2gH)^{0.5}` (user manual.pdf p.41; user manual +bridge.docx p.30(변환본)). 교량 식 (6)과 그림 1은 p.41에 있다. 현행 로더에서 Cd=0.8을 쓰려면 파일에 입력해야 한다. HEC-RAS 비교는 문서가 보고한 시험이다. 현행 SGC 경로에는 별도의 기준면 결함 후보가 있다. (user manual.pdf p.40–42; `input.cpp:161–163`; `lisflood2/lisflood_processing.cpp:65`; `lisflood2/sgm_fast.cpp:606–616·645–655`) `H=WL_{us}-WL_{ds}+eg_{us}`를 대입하면 같다. `x^{0.5}=\sqrt{x}`다. 역류에는 코드가 별도로 음의 부호를 붙인다. (user manual.docx p.45(변환본) 식 (6),46; user manual.pdf p.41 식 (6); `weir_flow.cpp:139–149`; `lisflood2/sgm_fast.cpp:661–671`) 코드는 `if (hu < Soffit && hd < Soffit)`에서 개수로 유량을 사용한다. `else if(Zratio >= C(1.0) && Zratio <= Tz)`에서 두 유량을 선형 결합한다. `else if(Zratio > Tz)`에서 압력 유량을 사용한다. Tz는 고정 1.5가 아니다. (user manual.docx p.46(변환본); user manual.pdf p.41–42; `weir_flow.cpp:153–169`) [10-21 대조 정정]
