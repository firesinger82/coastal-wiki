# CADMAS-2F S티어 + HiDEM(DEM) 결합

3D2F Source code의 일반 파일은 411개이다. 그중 `.f`·`.f90` 파일은 388개이다. 파일 포섭 개수는 검수 범위에 관한 기록이다. ([최종 근거 KD1-892](../../../_staging/recovery/compare/CADMAS-SURF-conclusion-verify-KD1f.md)). [11-04 대조 정정]

## A. SURF/3D와 이름을 공유하는 vf_*의 사본 차이 [11-04 대조 정정]

같은 vf 이름의 변경을 생략하면 안 된다. 바이트 동일 파일 115개만 3D 판독으로 대신한다. 나머지 공통 파일 120개는 차이 구간 672개를 대조한다. ([최종 근거 KD1-886](../../../_staging/recovery/compare/CADMAS-SURF-conclusion-verify-KD1f.md)). [11-04 대조 정정]
3D2F는 변밀도 외에도 면 VOF, 기상·이동벽 경계, 이전 유속, 공극률 변화, 계산상태, 수송 인수, 출력 형식을 바꾼다. ([최종 근거 KD1-887](../../../_staging/recovery/compare/CADMAS-SURF-conclusion-verify-KD1f.md)). [11-04 대조 정정]

기상 EOS 집합 외에도 면 VOF·상별 벽조건·혼합 난류량·상별 초기값·수송 계산영역이 달라진다. ([최종 근거 KD1-888](../../../_staging/recovery/compare/CADMAS-SURF-conclusion-verify-KD1f.md)). [11-04 대조 정정]

## B. HiDEM(DEM) 결합 [11-04 대조 정정]

HIDEM은 2FC와 별도 MPMD 통신 집합을 쓴다. 이 2FC 사본은 직접 STOC 접속을 사용하지 않는다. 판 근거는 `vf_stoc_init.f:39–42`의 `if( my_model.eq.l_cadmas_2fc ) then` 안에 추가된 `NB_SC=0`과 `return`의 사본 diff이다. STM은 별도 연성 모델이다. ([최종 근거 KD1-889](../../../_staging/recovery/compare/CADMAS-SURF-conclusion-verify-KD1f.md)). [11-04 대조 정정]
- `mod_dem.f90`(`:1-15`): `ihidem`(연성 플래그 0=무/≠0=연성)·`nsize_dem`(DEM PE수)·`comm_2fc_dem`(통신자 프로세스수/rank)·`ihidm`(HiDEM 대표 rank)
- `vf_jphdm1.f:1-7`(`HiDEMとのインターフェイス(1):連成解析計算領域の確認`, `use mod_comm,only:comm_2fc_dem; use mod_dem`)·`vf_jphdm2.f`(인터페이스 2)
- `vf_jpcoef.f:1-8`(`HiDEM用のポテンシャル関数の連立1次方程式を作成` — HiDEM 인터페이스 전용 포텐셜 Poisson, 대각 양수화 -1.0 승, [SMAC vpcoef](cadmas-surf3d-smac-velocity-pressure-solver.md#4-압력-poisson--포텐셜-함수-pt-vf_vpcoeff)와 동형)·`vf_vpsol.f`(HiDEM Poisson solve)
- HiDEM ↔ 2FC: 압력 & 체적공극 교환(DEM 입자 영역의 유체압). `vf_cgcpr1/2.f`(이동장애물 경계값 1D/2D 복사)

> HiDEM 결합은 [STR3D FSI](str3d-contact-and-fluid-coupling.md)(FEM 연속체)와 다른 **이산요소(DEM, 개별 블록/표류물) 연성** — 표류물 충돌·구조물 붕괴 잔해. 본 repo에 HiDEM 본체는 없음(인터페이스만), comm_2fc_dem 로 외부 HiDEM 실행파일과 MPMD.

## C. sf_* 지원 카탈로그 (144 중 [cut-cell 엔진](cadmas-2f-structure-coupling-cutcell.md) 외)

`sf_c_mpi_*`는 COMM_2FC_STR를 사용하는 Fortran 통신 래퍼이다(`3D2F/sf_c_mpi_comm_rank.f:1–9`). [11-04 대조 정정]
sf_stm_*는 STM 연성의 통신·수평 격자 집산·분배이다. STOC 직접 접속용 vf_stoc_*와 구분한다. ([최종 근거 KD1-891](../../../_staging/recovery/compare/CADMAS-SURF-conclusion-verify-KD1f.md)). [11-04 대조 정정]
- 메모리(8): `sf_alloc0/1·dealloc·realloc·dcopy·icopy·fill·remv`
- restart/IO/ENS(9): `sf_rd/wt_restart·send_rst·send_surf·recv_cont·rd_obst·ens_geom·ens_out·comm_init`
- 깊이/초기(8): `sf_dpth_init/update·intpl_dpth·gdpth·cinit·pos_init·prsini`

피난은 유체장을 수신하는 갈래이다([KA1-521 수정안](../../../_staging/recovery/compare/cadmas-agent-docs-vs-code.md)). [11-04 대조 정정]

변수 사전은 VF_A2ARRAY와 3D2F include를 기준으로 한다. 3D2F 전역 배열의 실제 선언 위치는 VF_A2ARRAY 모듈이다. 3D MAIN의 직접 배열 선언과 3D2F의 `use vf_a2array` 차이가 판 근거다([KF2-047 최종 근거](../../../_staging/recovery/compare/CADMAS-SURF-conclusion-verify-KF2.md)). [11-04 대조 정정]

입출력 루틴 이름을 공유해도 지원 구문과 활성 호출은 같지 않다. 3D 입력기는 MATRIX2를 받는다. 3D2F의 해당 분기는 MATRIX만 받는다. 3D2F의 표면 유속 호출 세 줄은 C2F 주석이다. 출처는 `3D/vf_iimdl.f:64–71`, `3D2F/vf_iimdl.f:64–68`, `3D2F/vf_v1cal.f:390–392`다. 3D의 OBST FILE·POROUS FILE·RSL ELAPSE·W-LEVEL ANS SRC 구문도 3D2F에 그대로 적용할 수 없다([KF3-195 수정안](../../../_staging/recovery/compare/cadmas-2f-manual-input-vs-code.md)). [11-04 대조 정정]

HiDEM 입력 형식은 `HIDEM YES` 또는 `HIDEM NO`다. 상위 파서는 `IF (LEVEL.LE.0) THEN`에서 이 카드를 처리한다. YES는 IHIDEM=1이고 NO는 0이다(`3D2F/vf_ii1inp.f:150–155`; `3D2F/vf_iihidm.f:27–40`). [11-04 대조 정정]
