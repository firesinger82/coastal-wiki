## 1. ROMS 본문 (직접 인용)

> "ROMS is a very complex model with many options and capabilities. ROMS is composed of many Fortran files (.F), a few header files (.h), various input script files (.in), a metadata variable definition file ([varinfo.yaml](../raw/manuals/wiki/markdown/varinfo.yaml.md)), and a single [makefile](../raw/manuals/wiki/markdown/makefile.md)."
>
> "The ROMS algorithms are distributed with the following directory structure:"
> (이하 §2)
>
> "ROMS uses [C-preprocessing](../raw/manuals/wiki/markdown/C-preprocessing.md) extensively to activate and/or deactivate ..."

현재 코드의 varinfo 메타데이터는 yaml·yml과 dat 형식을 구분해서 읽는다(`ROMS/Utility/get_metadata.F:878–882`).
YAML일 때 `yaml_initialize`를 호출한다(`ROMS/Utility/get_metadata.F:887–892`).
dat일 때 formatted 파일을 연다(`ROMS/Utility/get_metadata.F:945–947`).

## 2. 디렉토리 구조 (Getting_Started.md 본문)

```
Compilers/                     make configuration files
Data/                          Input data root directory
    /ROMS/                     ROMS data root directory
         /CDL                  ROMS NetCDF metadata design
Master/                        Main standalone and coupling programs
ROMS/                          ROMS root directory
    /Adjoint/                  Adjoint model
            /Biology           Adjoint biology/ecosystem models
    /Bin                       Executable scripts
    /Drivers                   Computational drivers
    /External                  Standard input scripts
    /Functionals               Analytical expression header files
    /Include                   Test cases configuration header files
    /Modules                   Declaration modules
    /Nonlinear/                Nonlinear model
              /BBL             Bottom Boundary Layer formulation
              /Biology         Nonlinear biology/ecosystem models
              /SeaIce          SeaIce model
              /Sediment        Nonlinear sediment transport model
    /Obsolete                  Discontinued files
    /Programs                  Support programs
    /Representer/              Representer model
                /Biology       Representer biology/ecosystem models
    /Tangent/                  Tangent linear model
            /Biology           Tangent linear biology/ecosystem models
    /Utility                   Generic utility files
User/                          ROMS User interface root directory
    /External                  User standard input scripts
    /Functionals               User analytical expressions templates
    /Include                   User application header files
```

Getting Started의 디렉터리 표는 주요 배포 구조를 소개한다([tools-guides:RTG-1973](../../../_staging/recovery/compare/roms-tools-guides-vs-code.md#5-차이-결론)).
현재 코드에는 표에 없는 `Vegetation`과 `WEC` 하위 디렉터리도 있다(`makefile:453–454`).

## 3. 디렉토리 구조 의미별 분류

### 3.1 Build 인프라

| 디렉토리 | 역할 |
|---|---|
| `Compilers/` | Linux GFortran·Intel·Cray·etc. 별 make configuration |
| `Bin` | 실행 스크립트 (build_roms.sh·copyright.sh 등) |
| `Programs` | 보조 Programs |
| (root) `makefile` | 단일 makefile |

### 3.2 Coupling 인프라

| 디렉토리 | 역할 |
|---|---|
| `Master/` | standalone main과 MCT·native ESMF driver 및 CMEPS ROMS cap이 있다(`Master/master.F:16–19`, `Master/esmf_roms.F:2`, `Master/esmf_roms.F:29–30`). [드라이버 노트](../source-analysis/roms_main_driver_dispatch.md) §3. |

### 3.3 ROMS 모델 변종 (model variants)

| 디렉토리 | 모델 변종 | 활용 |
|---|---|---|
| `Nonlinear/` | **Forward (Nonlinear)** | 일반 hindcast/forecast — [비선형 물리 모듈 노트](../source-analysis/roms_nonlinear_physics_modules.md) |
| `Adjoint/` | **Adjoint model** | sensitivity analysis |
| `Tangent/` | Tangent linear model | linearized perturbation |
| `Representer/` | Representer model | 4DVar 변종 |

Representer는 I4DVAR의 primal 접선 모델과 구분한다([da-4dvar:DA1-821](../../../_staging/recovery/compare/roms-da-4dvar-vs-code.md#5-차이-결론)).
각 모델 변종의 Biology 디렉터리 존재와 실제 활성 생물 커널을 구분한다([biology:NT-018](../../../_staging/recovery/compare/roms-biology-vs-code.md#5-차이-결론)).
현재 AD/TL/RP 실행 include는 세 NPZD 모델이다(`ROMS/Adjoint/Biology/ad_biology.F:14–24`, `ROMS/Tangent/Biology/tl_biology.F:14–24`, `ROMS/Representer/Biology/rp_biology.F:14–24`).
`TANGENT` 또는 `TL_IOMS` 또는 `ADJOINT`가 정의된 `checkadj`는 `Coptions`에 `BIO_FENNEL`이 있으면 미지원 오류를 보고하고 `ic`를 증가시킨다(`ROMS/Utility/checkadj.F:139`, `ROMS/Utility/checkadj.F:162–167`).
`ic`가 양수이면 `exit_flag`를 5로 설정한다(`ROMS/Utility/checkadj.F:600–601`).

## 4. 단일 makefile 모델

ROMS 의 빌드 흐름:

1. 사용자는 응용별 `<app>.h`를 작성한다(`ROMS/Include/cppdefs.h:746–748`).
2. 빌드 스크립트 경로는 `ROMS/Bin/build_roms.sh`이다(`ROMS/Bin/build_roms.sh:73`).
3. `MAKECMDGOALS`가 `clean`도 `tarfile`도 아닌 경우 `makefile`은 `MKFILE`을 `$(COMPILERS)/$(OS)-$(strip $(FORT)).mk`로 정하고 포함한다(`makefile:374–377`).
4. 실행 파일명은 빌드 변수 `USE_DEBUG`·`USE_OpenMP`·`USE_MPI`로 선택한다(`ROMS/Bin/build_roms.sh:333–345`).

`MY_HEADER_DIR`는 응용 헤더를 담은 디렉터리이다(`ROMS/Bin/build_roms.sh:311`).
`cppdefs.h`는 `ROMS_HEADER`로 지정한 응용 헤더를 포함하는 중앙 선택기이다(`ROMS/Include/cppdefs.h:753–754`).
현재 `build_roms.sh`는 `USE_MPI`와 `USE_OpenMP`의 동시 설정을 먼저 거부한다(`ROMS/Bin/build_roms.sh:324–328`).
현재 `makefile`의 실행 파일 기본 이름은 설정에 따라 `romsG`·`romsM`·`romsO`·`romsS`이다(`makefile:327–337`).
이 기본값은 `EXEC` 경로에서 `BIN`을 별도로 지정하지 않았을 때 적용된다(`makefile:327–337`).
`65558c0d`(2019-01-26)은 `makefile`의 ocean 실행 파일 이름을 roms 이름으로 바꿨다([tools-guides:RTG-1975](../../../_staging/recovery/compare/roms-tools-guides-vs-code.md#4-노트-대조와-수정안)).

상세 자료는 [위키 개요](roms-wiki-overview.md) §2.1의 `build_roms.md`이다.

## 5. C-preprocessing 의 역할 — 운영 핵심

ROMS 의 가장 큰 특징:

> "ROMS uses C-preprocessing extensively to activate and/or deactivate ..." (Getting_Started.md 본문)

- CPP 옵션은 컴파일할 기능을 선택한다(`ROMS/Include/cppdefs.h:753–754`).
- 실행 입력은 매개변수와 파일 이름을 지정한다(`ROMS/Utility/read_phypar.F:593–594`, `ROMS/Utility/read_phypar.F:4215–4218`).
- `SOLVE3D`의 추적자 이류는 `Hadvection`·`Vadvection` 입력으로 정한다(`ROMS/Utility/read_phypar.F:418–442`).
- `LuvSrc`·`LwSrc`와 `SOLVE3D`의 `LtracerSrc`도 실행 시 입력을 읽는다(`ROMS/Utility/read_phypar.F:1078–1092`).

상세 자료는 [CPP 옵션 노트](roms-wiki-cppdefs-options.md)이다.

## 6. 변수 메타데이터 — varinfo.yaml

> "a metadata variable definition file ([varinfo.yaml](../raw/manuals/wiki/markdown/varinfo.yaml.md))" (Getting_Started.md)

ROMS의 `varinfo.yaml`은 변수 메타데이터 정의 파일이다(`Getting_Started.wiki:2`).
NetCDF 정보 변수의 정의는 `ROMS/Utility/def_info.F:11–38`에도 있다.
배포 입력의 `VARNAME`은 `varinfo.yaml`을 가리킨다(`57aecf58:ROMS/External/roms_upwelling.in:76`).
`get_metadata`는 YAML의 변수 이름·`standard_name`·`type`·`index_code`·`scale`을 읽는다(`ROMS/Utility/get_metadata.F:972`, `ROMS/Utility/get_metadata.F:977–981`).
이번 정적 대조는 [출력·메타데이터 보고서](../../../_staging/recovery/compare/roms-outputs-metadata-vs-code.md#4-노트-대조와-수정안)의 `OMD-N038`을 참조한다.
`bvstrc`·`v_stokes`·`phytFe_east`에는 결함 후보가 있다([outputs-metadata:OMD-N038](../../../_staging/recovery/compare/roms-outputs-metadata-vs-code.md#4-노트-대조와-수정안)).
