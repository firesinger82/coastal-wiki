# ADCIRC parallel — adcprep partmesh, prepall, fort.80, halo exchange

## Scope

How `adcprep --partmesh` partitions the global mesh, how `--prepall` generates per-PE PE#### directories with fort.13/14/15 fragments, what `fort.80` records, how `padcirc` constructs halos from `fort.18`, and how the per-PE outputs get merged.

## A. adcprep partmesh phase

- METIS dispatch in `PREPINPUT` at `[file=prep/adcprep.F line=397]`
- Partition selection by `PARTITION_APPROACH` at `[file=prep/adcprep.F line=549-553]`:
  - `metis()` — direct node partition
  - `metis_npart_from_epart()` — from element partition
- METIS wrappers at `[file=prep/metis.F line=355]`, `[file=prep/metis.F line=598]`
- `partmesh.txt` write: one integer per node (PE assignment) via `WRITE(990,*) PROC(I)` in `DO I=1,MNP` loop at `[file=prep/metis.F line=396-405]` and `[file=prep/metis.F line=581-586]`
- Read-back path at `[file=prep/adcprep.F line=608-621]`
- `--np` parsed into `MNPROC` at `[file=prep/adcprep.F line=213-217]`, validated nonzero at `[file=prep/adcprep.F line=264-270]`, copied to `NPROC`
- Partition count: `NPARTS = MNPROC` at `[file=prep/metis.F line=337]`, `[file=prep/metis.F line=514]`

## B. adcprep prepall phase

- PE-specific files generated by:
  - `PREP14()` at `[file=prep/adcprep.F line=713]`
  - `PREP15()` at `[file=prep/adcprep.F line=718]`
  - `PREP13()` at `[file=prep/adcprep.F line=769]`
- Per-PE filenames:
  - `PE0000/fort.14` at `[file=prep/prep.F line=1276]`
  - `PE0000/fort.15` at `[file=prep/prep.F line=1818]`
  - `PE0000/fort.13` at `[file=prep/prep.F line=1162]`
- `PE0000..PEnnnn` directory creation:
  - Loop `DO PE=0,MNPROC-1` at `[file=prep/adcprep.F line=682-708]`
  - `WRITE(PENUM(3:6), '(I4.4)') PE` (4-digit zero-padded)
- `fort.80` generated only for `PREP_ALL` via `PREP80()` at `[file=prep/adcprep.F line=943-946]`

## C. fort.80 structure

`PREP80` writer at `[file=prep/prep.F line=7432]`, header at `[file=prep/prep.F line=7444-7463]`:

- Run strings: `RUNDES`, `RUNID`, `AGRID`
- Global counts: `NELG` (elements), `NNODG` (nodes), `NPROC`
- Per-PE counts: `MNPP` (nodes), `MNEP` (elements)
- Run config: `IM`, `NWS`, station counts, etc.
- Indices: uses `NPROC` and PE index (`I-1`)
- **`NOPROCS`/`MYPROC` symbols NOT in fort.80** — uses `NPROC` and PE iteration

### Per-PE node mapping

- Local→global: `IMAP_NOD_LG` written per processor at `[file=prep/prep.F line=7465-7469]`
- Global→(owner PE, local): at `[file=prep/prep.F line=7471-7474]`

### Per-PE element mapping

- `IMAP_EL_LG` written per PE at `[file=prep/prep.F line=7479-7482]`

### Boundary fragment ownership

**NOT in fort.80**. Instead in per-PE `fort.18` (receive/send lists):
- `IRECV_TOT/ISEND_TOT`, neighbor PE IDs at `[file=prep/prep.F line=2850-2905]`

## F. Reduction / global operations

GWCE iterative residual/dot products globally reduced via `psdot/ps2dots/ps3dots`:
- Each uses `MPI_ALLREDUCE(..., MPI_SUM, ...)` at:
  - `[file=src/messenger.F90 line=1135]` (1-array)
  - `[file=src/messenger.F90 line=1178]` (2-array)
  - `[file=src/messenger.F90 line=1224]` (3-array)
- Called from ITPACK/JCG flow at `[file=src/itpackv.F line=555, 568, 678]`

`maxele/maxvel` are nodal arrays (not scalar reductions):
- Maintained as `ETAMAX`, `UMAX` per node
- Globalized via `collectFullDomainArray` at output time, not per step
- Setup at `[file=src/write_output.F line=1205-1260]`
- Gather path at `[file=src/write_output.F line=4322-4324]`

## G. Output collection

- Local PE outputs written under each PE directory (`PE####/fort.6*` style by default)
- adcprep also notes per-PE I/O layout at `[file=prep/adcprep.F line=109-110]`

### Master/global merge: 2 paths

**Runtime**: `collectFullDomainArray` to rank 0:
- `[file=src/globalio.F line=91-160]`

**Offline**: `adcpost` (separate executable):
- Reads `fort.80` and all `PE0000/fort.6*` files
- `POST_INIT` at `[file=prep/post.F line=67-116]`
- Per-file merges at `[file=prep/post.F line=284, 796, 1051]` (and POST71-74 etc.)

### NetCDF path

- Writes only on `MYPROC == 0` (`writeOutArrayNetCDF`) after gather at `[file=src/write_output.F line=4246-4250]`
- **No explicit HDF5 collective / parallel NetCDF-I/O** in inspected routines — sequential gather + master write

## Decision Guide — adcprep workflow

| Step | Command | Effect |
|------|---------|--------|
| 1 | `adcprep --np 18 --partmesh` | METIS partitions, writes `partmesh.txt` |
| 2 | `adcprep --np 18 --prepall` | Creates `PE0000`–`PE0017`, writes per-PE files + `fort.80` |
| 3 | `mpiexec -np 18 padcirc.exe` | Each rank reads its `PE####/fort.{14,15,13}` + `fort.18` halo data |
| Post | `adcpost` or built-in `POST61` etc. | Merges per-PE `PE####/fort.6X` into global `fort.6X` (or NetCDF gather path) |

## Working Rules

1. **`partmesh.txt` is per-node** — METIS output with one PE id per global node.
2. **fort.80 has node/element maps + counts** — but boundary halo metadata is in per-PE fort.18, not fort.80.
3. **Halo updates are point-to-point** (IRECV/ISEND), not collective. Number of neighbors per PE is small (typically <= 4). <!-- source-needed: neighbor 수 통계 — METIS partition 특성 문헌 또는 실측 인용 필요 -->
4. **Reductions are infrequent** — only inside JCG iterations for residual checks. Halo exchange dominates communication cost. <!-- source-needed: 성능 단언 — 프로파일/문헌 인용 필요 -->
5. **Re-running adcprep --partmesh** overwrites partmesh.txt; run --prepall after to refresh PE####/. Don't mix old partmesh + new prepall.

## Common Pitfalls

- **Adcprep --np mismatch with mpiexec --np** — fatal. PE0017 missing if you run `mpiexec -np 18` after `adcprep --np 17`.
- **Stale fort.80** from previous run — POST routines read wrong mapping; merged outputs corrupted.
- **fort.18 missing for some PE** — usually from interrupted adcprep --prepall; redo from scratch.
- **HDF5 vs sequential NetCDF** — most ADCIRC builds have sequential. Check `ldd padcirc.exe | grep netcdf`. <!-- source-needed: '대부분의 빌드' 일반화 — 공식 빌드 문서 인용 필요 -->
- **adcpost reading wrong fort.80** — when comparing runs, archive fort.80 alongside fort.6X files.
