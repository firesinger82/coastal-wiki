# Local FORTRAN Utilities Assessment

Date: 2026-04-13

Purpose:
- classify the local FORTRAN utilities under `E:\numerical_models\adcirc\tools\utilities`
- determine whether they are baseline mesh tools, helper tools, or legacy/reference artifacts

## Scope

Main folders reviewed:
- `E:\numerical_models\adcirc\tools\utilities\grid`
- `E:\numerical_models\adcirc\tools\utilities\core`

## High-Level Conclusion

These FORTRAN utilities are not the current primary mesh-generation path.

They are better classified as:
- interpolation helpers
- boundary/QC helpers
- legacy/reference utilities

They do not replace the current `wide6` `OceanMesh2D` baseline.

## Build Verification

Observed local compiler:
- `GNU Fortran 13.2.0`

Verified compilable on the current machine:
- `DEM2GRDv3.F90`
- `MeshChecker05.F90`
- `bath_interp.f`
- `interp.f`
- `bnd_extr.f`
- `max_elev_grad_chk.f`

Observed runtime verification:
- `DEM2GRDv3.exe -v` prints `VERSION 3.0`

Build caveats:
- the older fixed-form programs behave more reliably in legacy mode
- for `bnd_extr.f` and `max_elev_grad_chk.f`, object build plus explicit link was the cleanest verification path
- this is enough to classify them as usable local assets, but not yet enough to call them validated workflow tools

## grid Folder Findings

### `bath_interp.f`

Observed role:
- interpolates bathymetry from one ADCIRC grid to another
- requires interpolation factors generated by `interp.f`

Practical use:
- useful for transferring bathymetry between grids
- useful when a parent or earlier mesh already has trusted depths
- useful for nested or derived mesh workflows

Limitation:
- not a mesh generator
- interactive and old-style fixed-dimension code
- depends on `interp.f` output first

### `interp.f`

Observed role:
- computes barycentric interpolation weights from one ADCIRC mesh onto another
- intended for results or field transfer between two finite-element grids

Practical use:
- useful for remapping values between meshes
- useful upstream of `bath_interp.f`
- potentially useful for comparing or transplanting fields between `wide6` and experimental meshes

Limitation:
- not a mesh generator
- requires recompilation if mesh sizes exceed hard-coded limits
- carries manual CPP projection constants in source

### `Griddata_v1.32.F90`
### `Gridscope_ver1.22.f90`

Observed state:
- file size is only about `275` bytes each
- contents are HTTP `404 Not Found` HTML, not source code

Practical conclusion:
- currently unusable
- treat as dead references, not working utilities

### `f13builderv8.3.zip`

Observed role:
- likely fort.13 construction helper by name and package context

Practical use:
- potentially useful later for nodal-attribute construction

Current limitation:
- not reviewed deeply yet
- not relevant to choosing the base mesh path

## core Folder Findings

### `DEM2GRDv3.F90`

Observed role:
- reads an ADCIRC mesh
- reads raster DEM data
- writes a new mesh with interpolated elevations/bathymetry

Practical use:
- candidate helper for DEM-to-grid interpolation
- useful if a lightweight non-MATLAB bathymetry transfer tool is needed

Limitation:
- still not a mesh generator
- should be treated as a bathymetry helper, not as a replacement for `OceanMesh2D`
- expects ESRI-style `*.flt` plus `*.hdr` raster input, not NetCDF directly

### `MeshChecker05.F90`

Observed role:
- mesh diagnostics and levee/boundary checks
- includes checks for duplicate elements, disjoint nodes, boundary problems, unrealistic heights, overlapping BCs

Practical use:
- strong QC candidate
- especially useful as an external checker for experimental meshes

Limitation:
- diagnostic tool only
- does not generate the base mesh
- interactive behavior is oriented toward levee and boundary checks, so only part of it may be relevant for the current wide-domain branch

### `max_elev_grad_chk.f`

Observed role:
- reads `fort.14` and `maxele.63`
- computes per-element surface-gradient warnings

Practical use:
- post-run instability or steep-response diagnostic
- useful for checking whether a mesh/run combination creates unrealistic gradients

Limitation:
- postprocess diagnostic, not preprocessing baseline logic
- expects standard file names like `fort.14` and `maxele.63`

### `bnd_extr.f`

Observed role:
- extracts ADCIRC boundary strings from node and element tables
- writes `adcirc.bnd` and `gredit.bnd`

Practical use:
- useful when a mesh exists without boundary info
- useful for rough automatic boundary extraction on experimental meshes

Limitation:
- old fixed-size code
- local `wide6` evidence already shows auto-classification can fail for open boundaries
- should not be trusted alone for final boundary assignment

## Relationship To wide6

Observed local fact:
- no direct call to these FORTRAN utilities was found in `wide6/scripts`
- the trusted `wide6` chain is still centered on `OceanMesh2D` plus local Python/MATLAB helpers

Interpretation:
- these FORTRAN tools are reserve helpers
- they are not currently part of the active baseline dependency chain

## Recommended Classification

### Keep As Useful Helper Candidates

- `bath_interp.f`
- `interp.f`
- `DEM2GRDv3.F90`
- `MeshChecker05.F90`
- `max_elev_grad_chk.f`
- `bnd_extr.f`

### Keep As Later/Secondary Candidate

- `f13builderv8.3.zip`

### Treat As Broken Or Non-Usable Until Recovered

- `Griddata_v1.32.F90`
- `Gridscope_ver1.22.f90`

## Practical Policy

For now:
- do not promote these FORTRAN tools to primary mesh-builder status
- use them only as helper candidates for:
  - bathymetry transfer
  - mesh QC
  - boundary extraction
  - field remapping between meshes

The baseline remains:
- `wide6`
- `OceanMesh2D`

## Immediate Priority Ranking

Highest-value helpers to test on real data next:
1. `MeshChecker05.F90`
2. `DEM2GRDv3.F90`
3. `interp.f` plus `bath_interp.f`

Lower-priority helpers:
- `bnd_extr.f`
- `max_elev_grad_chk.f`

Reason:
- the first group can help with mesh QC and bathymetry transfer before rerunning full meshing experiments
- the second group is useful, but either riskier for final boundary trust or dependent on post-run outputs
