## 1. Configuration reference (config.json)

### 1.1 로딩 순서 (CONFIGURATION.md §Loading Order)

1. `constants_load_calc.js`의 기본값으로 `calc_constants` 시작.
2. `init_sim_parameters`는 업로드 JSON을 먼저 파싱한다(`js/constants_load_calc.js:434–443`). [11-04 대조 정정]
3. 이 함수는 try 블록에서 오류가 발생하면 `catch (error)` 안에서 `await loadConfig();`를 실행한다(`js/constants_load_calc.js:437–449`). [11-04 대조 정정]
   `loadConfig()`는 선택된 예제의 `config.json`을 읽는다(`js/constants_load_calc.js:417–449`). [11-04 대조 정정]
   병합은 현재 `calc_constants`에 적용한다(`js/constants_load_calc.js:438–448`). [11-04 대조 정정]
   새 실행에서 누락 키가 직전 실행값을 유지할 수 있다(`js/main.js:224–236`; `js/constants_load_calc.js:443`). [11-04 대조 정정]
4. **파생값 재계산**: dispatch counts, timestep, Boussinesq 계수, 역(inverse) 격자간격, 경계 reflection 인덱스, canvas/render 치수, 퇴적물 계수, colorbar 레이아웃.
5. uniform 버퍼 갱신.

> 설정 객체에는 스키마 검사가 없다(`js/constants_load_calc.js:438–443`). [11-04 대조 정정]
> 미지 키도 객체에 보존된다(`js/constants_load_calc.js:443`). [11-04 대조 정정]
> 경계 시계열 파일에는 별도의 수치·열 수·시간벡터 검사가 있다(`js/File_Loader.js:324–330,378–400,433–441`). [11-04 대조 정정] [11-04 전수 검증 보완]
> 루트 `config.json`은 `.gitignore` 처리된다(`docs/architecture/CONFIGURATION.md` §Root Config Note). [11-04 대조 정정]

> 입사파 처리 (CONFIGURATION.md §Important Config Families 끝): `incident_wave_type==0`이면 `main.js`가 UI 값을 단일 sine 성분으로 취급 — 파고→진폭 `H/2`, 방향 deg→rad, `numberOfWaves=1`, `txWaves` 재업로드. `==1`이면 `Wave_Generator.js`가 동일 H·T·방향 컨트롤로 캐시된 **TMA 방향 스펙트럼** 생성, `numberOfWaves`=생성 성분 수, `txWaves` 재업로드.

입사 경계에서 `globals.incident_wave_type == 3`이면 SolitaryWave는 `let amplitude = 0.5;`를 사용한다(`shaders/BoundaryPass.wgsl:133–151,448–460`). [11-04 대조 정정]
이 함수는 UI의 `incident_wave_H`를 사용하지 않는다(`shaders/BoundaryPass.wgsl:25,133–151`). [11-04 대조 정정]
높이 입력 연결은 코드 결함 후보다. 강도는 중간이다(`js/constants_load_calc.js:77–79`; `index.html:763–778`; `shaders/BoundaryPass.wgsl:133–151`). [11-04 대조 정정]

### 1.3 모드 플래그 (분기 결정) — SIMULATION_PIPELINE.md §Active Shader Selection

`main.js`는 config에 따라 다른 WGSL 파일을 fetch·컴파일한다:

| 플래그 | 값 | 활성 셰이더 / 경로 |
|---|---|---|
| `Accuracy_mode` (표준) | — | `Pass1.wgsl`, `Pass2.wgsl` |
| `Accuracy_mode` (고차) | — | `Pass1_HighOrder.wgsl`, `Pass2_HighOrder_HLLC.wgsl`. 고차 HLLC 선택은 본판에 한정한다(`js/main.js:1539–1551`). [11-04 대조 정정] |
| `NLSW_or_Bous` = NLSW | — | `Pass3_NLSW.wgsl`, **PCR 솔브 생략** (중간상태를 `txNewState`로 복사) |
| `NLSW_or_Bous` = Boussinesq | — | `Pass3_Bous.wgsl` + `Update_TriDiag_coef.wgsl` + `TriDiag_PCRx.wgsl` + `TriDiag_PCRy.wgsl` |
| `NLSW_or_Bous` = COULWAVE | — | `Pass3A/3B/3_COULWAVE.wgsl` + `Update_TriDiag_coef_COULWAVE.wgsl` + `TriDiag_PCRx/y_COULWAVE.wgsl` |

고차 HLLC 선택은 본판에 한정한다(`js/main.js:1539–1551`; `transect_version/js/main.js:1033–1045`). [11-04 대조 정정]
transect 판의 입력 `waves.txt`는 `numberOfWaves`열·`3*HEIGHT`행의 진폭·주기·위상 묶음이다(`transect_version/js/File_Loader.js:178–196`; `transect_version/js/Copy_Data_to_Textures.js:93–107`). [11-04 대조 정정]
같은 이름의 JSON 키라도 파랑 파일과 바인딩 계약을 두 판 사이에서 그대로 옮기지 않는다(`docs/README.md:3–5`; `transect_version/js/Copy_Data_to_Textures.js:93–107`). [11-04 대조 정정]

### 1.4 파생상수 (직접 편집 금지) — CONFIGURATION.md §Derived Values

`init_sim_parameters()`가 로딩 후 계산하며, UI 변경이 재계산을 트리거하면 매번 덮어쓸 수 있음.

| 파생값 | 산출 입력 |
|---|---|
| `dt` | 직교 시간간격은 `calc_constants.dt = calc_constants.Courant_num * Math.min(calc_constants.dx,calc_constants.dy) / Math.sqrt(calc_constants.g * calc_constants.base_depth);`로 계산한다. 구면 시간간격은 셀 중심 위도별 최소 물리 간격을 사용한다(`js/constants_load_calc.js:472–487`). [11-04 대조 정정] |
| `DispatchX`/`DispatchY` | 격자 크기 ÷ workgroup 크기 |
| `Px`/`Py` | PCR 반복 횟수 |
| `one_over_d2x`, `one_over_d3x`, `one_over_dxdy` | 역 격자간격 및 그 거듭제곱 |
| 경계 reflection/shift 인덱스 | `calc_constants.boundary_nx = calc_constants.WIDTH - 1;`이다. `calc_constants.boundary_ny = calc_constants.HEIGHT - 1;`이다. `calc_constants.reflect_x = 2 * (calc_constants.WIDTH - 3);`이다. `calc_constants.reflect_y = 2 * (calc_constants.HEIGHT - 3);`이다. `calc_constants.boundary_shift =  4;`다(`js/constants_load_calc.js:505–509`). [11-04 대조 정정] |
| render/canvas 비율, colorbar 좌표 | 격자·캔버스 치수 |
| 퇴적물 settling/erosion 계수 | 퇴적물 계수는 초기화 식과 UI 재계산 식을 구분해 기록한다(`js/constants_load_calc.js:616–630`; `js/main.js:2337–2340`). [11-04 대조 정정] |

파생 계산은 `calc_constants.TWO_THETA = calc_constants.Theta * 2.0;`이다(`js/constants_load_calc.js:489`). [11-04 대조 정정]
동일한 퇴적물 물성값에서도 `if (calc_constants.html_update > 0)` 경로가 초기화의 자연입자 식을 이전 제곱근식으로 바꾼다(`js/main.js:2294,2337–2340,2371–2375`; `js/constants_load_calc.js:622–633`). [11-04 대조 정정]
침강속도 재계산은 코드 결함 후보다. 강도는 중간이다(`js/constants_load_calc.js:622–633`; `js/main.js:2337–2340,2371–2375`; `shaders/SedTrans_Pass3.wgsl:212`). [11-04 대조 정정]

> **디버깅 팁** (CONFIGURATION.md §Derived Values 끝): 시나리오가 이상하면 해당 값이 JSON 직접 로드인지 로딩 후 파생인지 확인. 후자는 UI 변경마다 덮어쓰일 수 있음.

### 1.5 AB3·AM4 시간적분 — SIMULATION_PIPELINE.md §Time Integration [11-04 대조 정정]

현재 코드의 시간적분 근거는 Pass3의 AB3·AM4 식으로 한정한다(`shaders/Pass3_Bous.wgsl:399–410`). [11-04 대조 정정]
현 AB3·AM4 계수의 직접 비교 출처는 2017년 식이다(`Tavakkol 2017 p.3` 식 (15)–(20); `shaders/Pass3_Bous.wgsl:404–409`). [11-04 대조 정정]
현재 `dt` 산정과 `render_step` 자동 조정을 구분한다(`js/constants_load_calc.js:454–487`; `js/main.js:2247–2281,2294–2332,2624`). [11-04 대조 정정]
별도 논문 제목을 현재 WebGPU 적응 `dt` 구현의 근거로 쓰지 않는다(`js/constants_load_calc.js:454–487`; `js/main.js:2624`). [11-04 대조 정정]

| `timeScheme` / `pred_or_corrector` | 동작 |
|---|---|
| `timeScheme == 0` | 단일 스텝 explicit 업데이트 |
| `timeScheme != 0`, `pred_or_corrector == 1` | Adams-Bashforth 스타일 **predictor** — 현재·old·older 도함수 사용 |
| `pred_or_corrector == 2` | **corrector** — 새 도함수 + predictor + history 도함수 결합 |

물·퇴적물 경로 모두 gradient-history 텍스처 유지. Boussinesq/COULWAVE 모드는 추가로 `F_G_star` history 텍스처가 `Pass3`용 분산 helper 항을 보존 (SIMULATION_PIPELINE.md §Time Integration).
퇴적물 corrector 단계 플래그 전달은 CD1-1301 코드 결함 후보로 구분한다(`js/main.js:1133–1134,2806–2821`; `shaders/SedTrans_Pass3.wgsl:224–233`). [11-04 대조 정정]

### 1.6 Uniform 커플링 (편집 시 주의) — CONFIGURATION.md §Uniform Coupling

각 WGSL은 자신이 필요한 값만 담은 `Globals` struct를 선언; JS의 uniform-buffer 패킹 로직(`main.js`)이 채운다. 커플링은 **positional·byte-layout 민감** — 셰이더 `Globals`에 필드 추가 시 대응 JS 버퍼 writer도 갱신 필요. 같은 config 값(`delta`, `base_depth`, 격자 치수, 역 격자간격 등)이 hydrodynamic·sediment·boundary·render·tridiagonal 여러 셰이더 struct에 중복 등장.

## 2. 텍스처·데이터 계약 요약 (DATA_AND_TEXTURES.md)

> 심화(채널 의미·PCR ping-pong·COULWAVE grouping 레이어)는 [../source-analysis/](../source-analysis/) 인프라 노트 참조. 여기서는 요약만.

시뮬레이션은 **텍스처 중심**: 전통 모델의 CPU 행렬이 여기선 WebGPU 텍스처 (DATA_AND_TEXTURES.md 도입부). 핵심 텍스처:

| 텍스처 | 역할 (채널) |
|---|---|
| `txState` / `txNewState` | 주 수면상태 — `r`=수면고, `g`=x운동량(P/hu), `b`=y운동량(Q/hv), `a`=스칼라(foam/tracer) (§State Textures) |
| `txstateUVstar` / `current_stateUVstar` | `txstateUVstar`는 이전 중간 상태다. `current_stateUVstar`는 새 중간 상태다. PCR 최종 해는 `txNewState`에 복사한다(`shaders/Pass3_Bous.wgsl:426–429`; `js/Run_Tridiag_Solver.js:66,91`; `js/main.js:2900–2901`). [11-04 대조 정정] [11-04 전수 검증 보완] |
| `txBottom` | 지형·wet/dry — `r`=북면, `g`=동면, `b`=셀중심 bed고, `a`=near-dry 플래그 (§Bathymetry) |
| `txBottomInitial` / `txHardBottom` | 시작 bed 보존(이동바닥·누적 bed-change용) / 비침식 하한 (§Bathymetry) |

## 3. WebGPU 바인딩 패턴 계약 (WEBGPU_BINDING_PATTERN.md)

> **핵심 규칙: binding 번호가 곧 인터페이스.** 핸들러의 순서가 WGSL `@group(0) @binding(N)` 선언과 일치해야 하고, `main.js`가 넘기는 리소스가 핸들러 기대와 일치해야 함 (§도입부).

**3계층 커플링**(handler ↔ bind group ↔ shader):

1. **핸들러**(`Handler_*.js`): `create_*_BindGroupLayout(device)` + `create_*_BindGroup(...)` 정의 + JS 텍스처/버퍼 인자를 번호 바인딩에 매핑. 디스패치는 보통 안 함 — `Run_Compute_Shader.js`/`Run_Tridiag_Solver.js`/`main.js` 렌더가 담당 (§Handler Responsibilities).
2. **셰이더**(WGSL): 매칭 `Globals` struct + 매칭 텍스처/스토리지 바인딩 선언. 모든 텍스처는 config 함의 치수; 스토리지 출력은 샘플 입력과 분리(임시 텍스처 후 복사 예외); workgroup 보통 16×16 (§Shader Responsibilities).
3. **임시 텍스처 패턴**: WebGPU는 한 패스에서 같은 텍스처 read+write 불가 → `txtemp_boundary`, `txtemp_Breaking`, `txtemp_bottom`, `txtemp_PCRx`, `txtemp_WaveHeight` 등에 쓴 뒤 canonical 텍스처로 복사. `BoundaryPass`, `Pass_Breaking`, `CalcMeans`/`CalcWaveHeight`, PCR 솔버에서 특히 두드러짐 (§Why Temporary Textures).

**공유 레이아웃** (§Shared Layouts): `Handler_Pass1`(표준+고차), `Handler_Pass2`(표준/HLLC/HLLEM), `Handler_Pass3`(NLSW/Bous/COULWAVE — 셋 다 동일 broad 레이아웃), `Handler_Tridiag`(표준+COULWAVE; 표준 WGSL은 일부 바인딩 미사용), `Handler_UpdateTrid`(표준+COULWAVE). → **미사용 리소스도 호환성 계약의 일부로 취급**.

> **함정** (§Stale Comments): 여러 핸들러 주석이 compute인데 "fragment shader"라 표기; 헤더가 다른 핸들러에서 복붙된 경우 있음. **주석 말고 바인딩 선언 + 현 `main.js` 호출 경로를 신뢰.** [11-04 대조 정정]
> 현재 활성 오버레이 갱신은 초기 렌더와 같은 전체 인수 목록을 사용한다(`js/main.js:1451,2435–2437,2448–2450`). [11-04 대조 정정] [11-04 전수 검증 보완]
> 구버전 호출문은 주석으로만 남아 있다(`js/main.js:2435,2448`). [11-04 대조 정정]

**안전 변경 체크리스트** (§Safe Change Checklist) — 셰이더 변경: ① 셰이더 `@binding` 목록 → ② 매칭 `Handler_*.js` 레이아웃 → ③ `main.js`의 모든 `create_*_BindGroup()` 호출 → ④ `Create_Textures.js` 포맷 → ⑤ 디스패치 후 copy → ⑥ 채널 의미 docs. 신규 config/uniform: ① `constants_load_calc.js` 기본값 → ② 파생계산 → ③ JS uniform writer → ④ WGSL `Globals` 올바른 byte 위치 → ⑤ 영향받는 파이프라인/bind group 재생성.
